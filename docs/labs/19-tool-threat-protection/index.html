Protect tool calls with Agent 365 threat protection

Have Microsoft Defender and Microsoft Purview evaluate every tool call on an MCP server, before the tool runs, after it returns, or both, and see how a fail-closed denial reaches the caller.

Advanced 30 min Portal Updated Oct 19, 2026
Source Edit

What you'll do

  • Explain what the before-invocation and after-invocation stages evaluate and what each one can and can't prevent
  • Add an Agent 365 tool threat protection policy to an MCP server in the AI Gateway portal
  • Call a protected tool with a delegated Microsoft Entra ID token and read the result
  • Recognize the documented denial codes and why a key-only call fails closed

Before you start

  • 04Federate MCP tools behind one endpoint
  • 11Go keyless with Microsoft Entra ID and RBAC

Tracks: Portal

Your agents call tools that read web pages, tickets, and documents, and any of that content can carry a prompt injection or leak sensitive data back to the model. Content filters on the model don't see what goes into a tool or what comes out of it. In this lab you add Agent 365 tool threat protection to an MCP server, so Microsoft Defender and Microsoft Purview evaluate each tool request, each tool result, or both, and the gateway only lets allowed calls through.

#Before you begin

  • Complete Federate MCP tools behind one endpoint. This lab protects the learn MCP server from that lab. Any MCP server in your gateway works.
  • Complete Go keyless with Microsoft Entra ID and RBAC. Tool threat protection only works for callers that send a delegated Microsoft Entra ID bearer token issued for AI Gateway.
  • A Microsoft Defender or Microsoft Purview license in your tenant.
  • Permission to manage policies on the gateway, for example Contributor on its resource group, and permission to create role assignments if your user doesn't have a data-plane role yet.
  • The Azure CLI↗ 2.75 or later, signed in with az login as a user (not a service principal). The CLI snippets call the Azure Resource Manager REST API with az rest, because the az aigateway extension doesn't manage the new aigateways resource type yet.
  • For the test scripts and the Bash snippets: curl and jq (Bash) or PowerShell 7 or later.
Note

Agent 365 tool threat protection is an emerging capability of the AI Gateway tier preview, which is available in East US 2 and Sweden Central. Labels and behavior can change; see the release note↗. AI Gateway itself is free during the preview; Defender and Purview are licensed separately.

#How it works

Tool threat protection is a policy on one MCP server. It covers every tool on that server, whether the server is backed by remote MCP endpoints, OpenAPI services, or both, and every caller. The gateway first runs its usual authentication, authorization, and policies. Only requests that pass are sent for evaluation.

For each tools/call, the gateway exchanges the caller's delegated token on behalf of the user (OBO) and asks Microsoft Defender and Microsoft Purview for a verdict on malicious content, prompt injection, and sensitive-data risks. Discovery and session traffic, such as initialize, tools/list, and notifications, isn't evaluated.

The evaluation must return a valid allow. A denial, timeout, token-exchange failure, malformed verdict, or unavailable evaluator fails closed: the caller gets a normal tool result over HTTP 200 with isError: true, a denial code, and a correlation ID.

StageWhat's evaluatedWhat it preventsCost
Before tool invocationThe tool name and argumentsThe tool never runs, so there are no side effectsOne evaluation round trip
After tool invocationThe tool result, including error resultsThe result never reaches the agent. The tool already ran.One evaluation round trip
BothBoth of the aboveRequires two allow decisionsUp to two round trips per call

#Prepare a delegated caller

The policy evaluates each call on behalf of the signed-in user, so you test it with your own user token. Give your user permission to call tools on the server, then make one call before you add the policy. That proves the token and the role work, so any later failure comes from the policy.

az role assignment create `
  --assignee-object-id (az ad signed-in-user show --query id -o tsv) `

#Call a tool with your user token

The script below gets a token for https://azure-api.net/aigateway from the Azure CLI, checks that it's a delegated user token, runs the MCP handshake, and calls the server's search tool with a harmless question.

infra/call-protected-tool.shGitHub
#!/usr/bin/env bash
# Calls one tool on an AI Gateway MCP server that has Agent 365 tool threat protection, using the MCP
# Streamable HTTP handshake (initialize -> notifications/initialized -> tools/list -> tools/call).
# Prints whether the tool result came back, or the denial code and correlation ID the gateway returned.
#
# Usage:
#   export AI_GATEWAY_URL="https://<gateway>.eastus2-01.ai.gateway.azure.com"
#   ./call-protected-tool.sh token [server-name] [query]   # delegated Entra token for the signed-in az user
#   ./call-protected-tool.sh key   [server-name] [query]   # runtime key in AI_GATEWAY_API_KEY (no bearer token)
#
# token mode uses AI_GATEWAY_TOKEN when set, otherwise it runs
#   az account get-access-token --resource https://azure-api.net/aigateway
# The script calls the Learn docs search tool (or the first tool whose name contains "search") unless you set
# TOOL_NAME, and sends the query as {"query": "..."}. Use a benign query. Requires curl and jq.
set -euo pipefail

AUTH="${1:?Pass token or key as the first argument}"
SERVER="${2:-learn}"
QUERY="${3:-What is Azure API Management?}"
: "${AI_GATEWAY_URL:?Set AI_GATEWAY_URL to https://<gateway>.eastus2-01.ai.gateway.azure.com}"
command -v jq >/dev/null || { echo "This script needs jq." >&2; exit 1; }
ENDPOINT="${AI_GATEWAY_URL%/}/default/toolservers/${SERVER}/mcp"

case "$AUTH" in
  token)
    TOKEN="${AI_GATEWAY_TOKEN:-$(az account get-access-token --resource https://azure-api.net/aigateway --query accessToken -o tsv)}"
    # Delegated (user) tokens carry an scp claim. App-only tokens carry roles instead and can't be used for evaluation.
    payload="$(printf '%s' "$TOKEN" | cut -d. -f2 | tr '_-' '/+')"
    while [ $(( ${#payload} % 4 )) -ne 0 ]; do payload="${payload}="; done
    scp="$(printf '%s' "$payload" | jq -Rr '@base64d | fromjson | .scp // empty' 2>/dev/null || true)"
    if [ -n "$scp" ]; then
      echo "Delegated token for the signed-in user (scp: $scp)"
    else
      echo "Warning: the token has no scp claim, so it isn't a delegated user token." >&2
    fi
    HEADERS=(-H "Authorization: Bearer $TOKEN") ;;
  key)
    : "${AI_GATEWAY_API_KEY:?Set AI_GATEWAY_API_KEY to a runtime key from Access > Keys}"
    HEADERS=(-H "api-key: $AI_GATEWAY_API_KEY") ;;
  *)
    echo "The first argument must be token or key." >&2; exit 1 ;;
esac
HEADERS+=(-H "Content-Type: application/json" -H "Accept: application/json, text/event-stream")
STATUS="" BODY="" SESSION_ID=""

# post <json>: sends one JSON-RPC message and sets STATUS and BODY (and SESSION_ID when the server returns one).
post() {
  local raw head sid
  raw="$(curl -sS --max-time 120 -D - "$ENDPOINT" "${HEADERS[@]}" --data "$1" | tr -d '\r')"
  if [[ "$raw" == *$'\n\n'* ]]; then head="${raw%%$'\n\n'*}"; BODY="${raw#*$'\n\n'}"; else head="$raw"; BODY=""; fi
  STATUS="$(printf '%s\n' "$head" | awk 'toupper($1) ~ /^HTTP/ {code=$2} END {print code}')"
  sid="$(printf '%s\n' "$head" | awk -F': ' 'tolower($1)=="mcp-session-id" {print $2}')"
  if [ -n "$sid" ]; then SESSION_ID="$sid"; fi
}

# response <id>: prints the JSON-RPC response with that id. The body can be JSON or server-sent events.
response() {
  if printf '%s\n' "$BODY" | grep -q '^data:'; then
    printf '%s\n' "$BODY" | sed -n 's/^data:[[:space:]]*//p'
  else
    printf '%s\n' "$BODY"
  fi | jq -c --argjson id "$1" 'select(type == "object" and .id == $id)' 2>/dev/null || true
}

# require_success <step>: stops with the gateway's answer when the HTTP status isn't 2xx.
require_success() {
  case "$STATUS" in
    2??) ;;
    *) echo "$1 failed with HTTP ${STATUS:-no response}:" >&2; printf '%s\n' "$BODY" >&2; exit 1 ;;
  esac
}

echo "MCP endpoint: $ENDPOINT"

post '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-03-26","capabilities":{},"clientInfo":{"name":"aigateway-labs","version":"1.0"}}}'
require_success "initialize"
PROTOCOL="$(response 1 | jq -r '.result.protocolVersion // empty')"
if [ -z "$PROTOCOL" ]; then echo "initialize returned no result:" >&2; printf '%s\n' "$BODY" >&2; exit 1; fi
HEADERS+=(-H "MCP-Protocol-Version: $PROTOCOL")
if [ -n "$SESSION_ID" ]; then HEADERS+=(-H "Mcp-Session-Id: $SESSION_ID"); fi

post '{"jsonrpc":"2.0","method":"notifications/initialized"}'
require_success "notifications/initialized"

post '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}'
require_success "tools/list"
LIST="$(response 2)"
if [ -z "$LIST" ] || [ "$(printf '%s' "$LIST" | jq 'has("error")')" = "true" ]; then
  echo "tools/list returned an error:" >&2; printf '%s\n' "${LIST:-$BODY}" >&2; exit 1
fi
echo "tools/list: HTTP $STATUS, $(printf '%s' "$LIST" | jq '.result.tools | length') tools (discovery isn't evaluated)"

TOOL="${TOOL_NAME:-$(printf '%s' "$LIST" | jq -r '[.result.tools[].name] |
  ([.[] | select(test("docs_search"; "i"))] + [.[] | select(test("search"; "i"))])[0] // empty')}"
if [ -z "$TOOL" ]; then echo "No tool name contains 'search'. Set TOOL_NAME to the tool to call." >&2; exit 1; fi

echo "tools/call: $TOOL with query: $QUERY"
post "$(jq -cn --arg name "$TOOL" --arg query "$QUERY" \
  '{jsonrpc:"2.0",id:3,method:"tools/call",params:{name:$name,arguments:{query:$query}}}')"
require_success "tools/call"
CALL="$(response 3)"
if [ -z "$CALL" ]; then echo "tools/call returned no JSON-RPC response:" >&2; printf '%s\n' "$BODY" >&2; exit 1; fi

echo "HTTP status: $STATUS"
if [ "$(printf '%s' "$CALL" | jq 'has("error")')" = "true" ]; then
  echo "JSON-RPC error:"; printf '%s' "$CALL" | jq '.error'
elif [ "$(printf '%s' "$CALL" | jq '.result.isError == true')" = "true" ]; then
  echo "isError: true"
  printf '%s' "$CALL" | jq -r '.result._meta["com.microsoft.azure.ai.gateway/denial"] // {} |
    "Denial code: \(.code // "none")\nCorrelation ID: \(.correlationId // "none")"'
  printf '%s' "$CALL" | jq -r '[.result.content[]? | select(.type == "text") | .text] | join("\n")'
else
  echo "isError: false (the result was returned)"
  printf '%s' "$CALL" | jq -r '[.result.content[]? | select(.type == "text") | .text] | join("\n") | .[0:400]'
  echo "..."
fi

#Call it with a runtime key only

Now call the same tool with the API key and no bearer token. The key still authenticates you to the gateway, so initialize and tools/list succeed. The tools/call needs an evaluation, and without a delegated token the gateway can't run one, so it fails closed.

Bash
./infra/call-protected-tool.sh key "$MCP_SERVER"
PowerShell
./infra/call-protected-tool.ps1 -Auth key -Server $MCP_SERVER
...
tools/list: HTTP 200, <n> tools (discovery isn't evaluated)
tools/call: learn_microsoft_docs_search with query: What is Azure API Management?
HTTP status: 200
isError: true
Denial code: ToolEvaluationIdentityRequired
Correlation ID: <guid>
Tool '...' requires a validated delegated caller token.
TS_URL="$WS/toolServers/$MCP_SERVER"
az rest --url "$TS_URL?$API" --query properties -o json \
  | jq -c '{properties:{policies:([(.policies // [])[] | select(.type != "toolThreatProtection") | del(.scope)]
      + [{type:"toolThreatProtection",preInvocation:true,postInvocation:true}])}}' > policies.json
az rest --method patch --url "$TS_URL?$API" --body @policies.json --query properties.policies
rm policies.json
$TS_URL = "$WS/toolServers/$MCP_SERVER"
$p = az rest --url "$TS_URL`?$API" --query properties.policies -o json | ConvertFrom-Json
$p = @($p | Where-Object { $_ -and $_.type -ne 'toolThreatProtection' } | Select-Object * -ExcludeProperty scope) +
     @(@{ type = 'toolThreatProtection'; preInvocation = $true; postInvocation = $true })
@{ properties = @{ policies = $p } } | ConvertTo-Json -Depth 10 -Compress | Set-Content policies.json
az rest --method patch --url "$TS_URL`?$API" --body "@policies.json" --query properties.policies
Remove-Item policies.json

    #Troubleshooting

    SymptomLikely causeFix
    Every protected call returns ToolEvaluationIdentityRequiredThe call has no bearer token, or the token isn't a delegated user token. App-only tokens and runtime keys can't be used for OBO.Sign in with az login as a user, get a token for https://azure-api.net/aigateway, and send it as Authorization: Bearer. Check that the token has an scp claim.
    tools/call returns HTTP 401 or 403 with a bearer tokenThe user has no data-plane role on the MCP server, or the assignment hasn't applied yetAssign AI Gateway Tools User at the MCP server or gateway scope and wait a few minutes
    Calls return ToolEvaluationUnavailableThe token exchange or the evaluation failed, timed out, returned an invalid verdict, or the evaluator was unavailableRetry later. If it persists, confirm the Microsoft Defender or Microsoft Purview license and the Defender policy mode with your security team, and share the correlationId.
    A benign call returns ToolEvaluationDeniedDefender or Purview flagged the request or the resultReview the call with your security team using the correlationId. If the tool already ran (after-invocation stage), don't retry it automatically.
    You can't add a second tool threat protection policy to the serverEach MCP server can have only one tool threat protection policyKeep the existing policy, or delete it and add a new one with the stages you want
    Tool calls got noticeably slowerEach enabled stage adds an evaluation round tripKeep both stages where you need them, and use only Before tool invocation where results are trusted
