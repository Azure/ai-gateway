Governance & cost · Lab 07

Enforce cost budgets with per-caller overrides

Give every app, agent, and user a dollar budget per hour, day, or month, raise or lower it for specific API keys and Microsoft Entra identities, and watch the gateway answer 403 LlmCostQuotaExceeded once a caller's estimated spend runs out.

Intermediate 30 min PortalRESTBicep Updated Oct 28, 2026
Source Edit

What you'll do

  • Explain how a cost limit estimates spend and counts it per caller in fixed calendar windows
  • Add a daily cost limit to a model in the portal or with the REST API
  • Give specific API keys and Microsoft Entra identities their own budget with overrides
  • Declare a budgeted alias, its API keys, and their overrides with Bicep and azd
  • Trigger a 403 LlmCostQuotaExceeded response, find the remaining budget header, and review estimated spend in Monitoring

Before you start

  • 06Throttle tokens per caller with token limits
  • 10Issue and rotate runtime API keys

Tracks: Portal, REST, Bicep + azd

Your FinOps team has a problem that token limits can't solve: a thousand tokens on a premium reasoning model costs many times more than a thousand tokens on a mini model, so "tokens per day" says nothing about the bill. They want every app to have a daily budget in dollars, a bigger envelope for the production support bot, and a separate allowance for a data science lead who signs in with Microsoft Entra ID. In this lab you set that up as a cost limit at the gateway, so a caller who runs out of budget is stopped before the model is called.

#How it works

After each model response, the gateway estimates its cost from the tokens the provider reported and the model's public pricing, broken down by token category. A cost limit adds that estimate to the caller's counter for the current renewal period. Before it forwards the next request, the gateway checks the counter. Once spend reaches the budget, the gateway answers 403 (LlmCostQuotaExceeded in the product docs) with the message LLM cost quota is exceeded and never calls the backend. Responses also carry headers with the cost of the call and the remaining budget.

SettingPortal labelJSON fieldValues
BudgetBudget amountamountUS dollars, for example 5
WindowRenewal periodperiodhour, day, week, month, year (Hourly … Yearly)
Who gets a counterCounter dimensions (shown as Budget counted by)counterKeyAn array: ["identity"] (the API key, or the Entra tenant ID + object ID) or ["ipAddress"]
ExceptionsOverridesoverridesA different amount for an API key (apiKeyResourceId) or Entra identity (claims)
Policy identityNot shownidStable ID. Editing the amount keeps accumulated spend.

Renewal periods are fixed calendar windows, not rolling windows: a Daily budget starts fresh at the beginning of each day, not 24 hours after the first call. Attach the policy to a model to budget spend on that model, or at Gateway scope to track one budget per caller across all models.

Important

A cost limit is a guardrail, not an invoice. Spend is estimated from public pricing, and because gateway instances update counters concurrently, concurrent requests can briefly overshoot the budget before every instance sees the latest spend.

#Add a cost limit to the model

Pick one track. Each one produces the same default budget: $5 per day for each caller identity. The portal and REST tracks put it on your model. The Bicep + azd track creates a new gateway and puts it on a new alias of the model. The portal and Bicep + azd tracks also add the overrides for specific callers. The REST track points to the portal for them.

1

#Start the policy wizard

Open the AI Gateway portal↗ and select your gateway from the gateway switcher. Select Policies›Add policy. On the Type step, under Cost & Rate Limits, select Cost limit, then Next.

2

#Choose where the budget applies

On the Scope step, select Individual assets ("Apply only to selected models, aliases, or MCP servers"). Select your model, then Next.

Tip

Choose Gateway ("Apply to all compatible assets") when the budget should cover every model a caller uses, including models you import later. A gateway-scoped cost limit tracks one budget across all models instead of one per model.

3

#Set the default budget

On the Details step, under Parameters, set:

FieldValue
Budget amount5 (US dollars)
Renewal periodDaily
Counter dimensionsCaller identity

Select Next.

Note

Caller identity gives each API key, and each Entra caller, its own counter. If you select no dimension, every caller shares one counter for the policy. Caller IP address can't be combined with overrides: the portal asks you to remove all overrides or switch to caller identity before saving.

4

#Give an API key a bigger budget

On the Overrides step, under API keys, select Add. In the new row, pick your support-bot key in API key and set Budget amount to 50. Each key can have only one override.

5

#Give a Microsoft Entra identity its own budget

Under Microsoft Entra identities, select Add. In Add Microsoft Entra identities override, choose how Match requests by works:

  • Specific Microsoft Entra identity: search for a user by name or email. For a service principal, enter its object ID, not its application (client) ID.
  • Custom token claim combination: add one or more Claim name and Value pairs, for example appid and the client ID of an internal app. Every claim condition must match the validated token.

Set Budget amount to 20, then select Add.

Overrides are evaluated in the order you add them, and the first match wins. A claim combination never pools callers into a shared budget: with identity counting, each matching identity gets the override amount on its own counter.

#Read the current policies

This track calls the Azure Resource Manager REST API with az rest, because the aigateway extension doesn't set cost limits. Policies live inline in the model's properties.policies array. A PATCH replaces the whole array, so always read it first and keep the policies you didn't mean to change.

Bash
# Read your subscription ID, and build the management URL of your model, which holds its policies
SUB="$(az account show --query id -o tsv)"
URL="https://management.azure.com/subscriptions/$SUB/resourceGroups/$RG/providers/Microsoft.ApiManagement/aigateways/$GATEWAY/workspaces/default/modelProviders/$PROVIDER/models/$MODEL?api-version=2025-09-01-preview"
echo "🆔 Subscription: $SUB"

# Read the model's current policies, so that you know what the merge must keep
echo "🔐 Policies on $MODEL:"
az rest --method get --url "$URL" --query properties.policies
2

#Add or update the cost limit and keep everything else

A cost limit carries a stable id. Editing the amount of an existing policy keeps its accumulated spend, so the merge below updates an existing costLimit in place (keeping its id and any overrides) and only creates a new one, with a fresh GUID, when none exists.

# Choose the default budget: 5 US dollars for each caller, renewed every day
BUDGET=5
PERIOD=day

# Read the policies, then update the cost limit in place, keeping its id and overrides,
# or add a new one with a fresh GUID when there's none
POLICIES="$(az rest --method get --url "$URL" | jq -c \
  --argjson amount "$BUDGET" --arg period "$PERIOD" --arg id "$(uuidgen | tr 'A-Z' 'a-z')" '
  .properties.policies // [] | . as $p
  | if any($p[]; .type == "costLimit")
    then [$p[] | if .type == "costLimit"
                 then (.amount = $amount | .period = $period | .counterKey = ["identity"])
                 else . end]
    else $p + [{"type":"costLimit","id":$id,"amount":$amount,"period":$period,"counterKey":["identity"]}]
    end')"

# Send the merged array back: a PATCH replaces the whole policies array
az rest --method patch --url "$URL" --body "{\"properties\":{\"policies\":$POLICIES}}" --output none &&
  echo "🔐 Cost limit of \$$BUDGET per $PERIOD for each caller is on $MODEL"
# Choose the default budget: 5 US dollars for each caller, renewed every day
$BUDGET = 5
$PERIOD = 'day'

# Read your subscription ID, and build the management URL of your model, which holds its policies
$SUB = az account show --query id -o tsv
$URL = "https://management.azure.com/subscriptions/$SUB/resourceGroups/$RG/providers/Microsoft.ApiManagement/aigateways/$GATEWAY/workspaces/default/modelProviders/$PROVIDER/models/$MODEL`?api-version=2025-09-01-preview"
Write-Host "🆔 Subscription: $SUB"

# Read the policies, then update the cost limit in place, keeping its id and overrides,
# or add a new one with a fresh GUID when there's none
$current  = az rest --method get --url $URL | ConvertFrom-Json
$policies = @($current.properties.policies | Where-Object { $_ })
$cost     = $policies | Where-Object { $_.type -eq 'costLimit' } | Select-Object -First 1
if ($cost) {
  $cost | Add-Member -NotePropertyName amount -NotePropertyValue $BUDGET -Force
  $cost | Add-Member -NotePropertyName period -NotePropertyValue $PERIOD -Force
  $cost | Add-Member -NotePropertyName counterKey -NotePropertyValue @('identity') -Force
} else {
  $policies += [pscustomobject]@{
    type = 'costLimit'; id = [guid]::NewGuid().ToString(); amount = $BUDGET; period = $PERIOD; counterKey = @('identity')
  }
}

# Send the merged array back from a file, which keeps the JSON quotes intact: a PATCH replaces the whole array
$body = @{ properties = @{ policies = $policies } } | ConvertTo-Json -Depth 10 -Compress
$body | Set-Content -Path patch.json
az rest --method patch --url $URL --body '@patch.json' --output none
if ($?) { Write-Host "🔐 Cost limit of `$$BUDGET per $PERIOD for each caller is on $MODEL" }
Remove-Item patch.json

period accepts hour, day, week, month, or year. counterKey is an array: ["identity"], or ["ipAddress"] to count per client IP address.

What you need: only the one-time setup from Before you begin. This track doesn't use your gateway from lab 02: azd up creates a new one, so it works on its own.

1

#Choose what to declare

A Bicep deployment sends a PUT, which replaces the whole resource. Redeclaring a model you imported in the portal risks dropping settings you didn't copy. Instead, this template adds a new alias, <model-name>-budget, that targets the same backend model and carries the cost limit. Existing clients keep calling the original alias. Callers that you move to the new alias get the budget.

The template also declares what the portal track picks by hand: the app-dev and support-bot runtime keys, and two entries in the policy's overrides array. Overrides are evaluated in order, and the first match wins.

OverrideMatchesBudget
API keyapiKeyResourceId: the resource ID of the support-bot key$50 per day
Microsoft Entra identityclaims: your tenant ID (tid) and object ID (oid)$20 per day

azd fills in the object ID of the account you signed in with. The policy id is a GUID that the template derives from the gateway and the alias name, so it stays the same on every deployment, and a new amount keeps the spend accumulated so far.

// Lab 07 with azd: "azd up" creates the resource group rg-<environment name>, the quick start's gateway, Foundry
// model, default alias, and runtime API key, then the app-dev and support-bot keys and a second alias for the same
// model with a cost limit and per-caller overrides. Runtime API key values are never outputs.
targetScope = 'subscription'

@description('azd environment name. The resource group is rg-<environmentName>.')
@minLength(1)
@maxLength(60)
param environmentName string

@description('Region for every resource. Pick one where AI Gateway and the lab\'s Foundry models are available. List them with az provider show --namespace Microsoft.ApiManagement (Setup guide, Find the available regions).')
@metadata({ azd: { type: 'location' } })
param location string

@description('Default budget for each caller, in US dollars. azd reads it from COST_LIMIT_AMOUNT.')
param budgetAmount string = '5'

@description('Renewal period. azd reads it from COST_LIMIT_PERIOD.')
@allowed([ 'hour', 'day', 'week', 'month', 'year' ])
param period string = 'day'

@description('Budget for the support-bot key, in US dollars. azd reads it from COST_LIMIT_OVERRIDE_AMOUNT.')
param overrideAmount string = '50'

@description('Object ID of the Microsoft Entra identity that gets its own budget. azd sets AZURE_PRINCIPAL_ID to yours.')
param entraObjectId string = ''

@description('Budget for that Microsoft Entra identity, in US dollars. azd reads it from COST_LIMIT_ENTRA_AMOUNT.')
param entraAmount string = '20'

var suffix = take(uniqueString(subscription().id, environmentName, location), 6)
var tags = { 'azd-env-name': environmentName }

resource rg 'Microsoft.Resources/resourceGroups@2024-03-01' = {
  name: 'rg-${environmentName}'
  location: location
  tags: tags
}

// The quick start's template: a gateway, a Foundry model behind the default alias, and the app-first-call key.
module base '../../quickstart/infra/resources.bicep' = {
  name: 'aigw-base'
  scope: rg

  }
}

  }
}

infra/budget-alias.bicep adds the two keys and the alias. It only references the gateway, the provider, and the model, so you can also deploy it on its own to a gateway you already have, with az deployment group create:

infra/budget-alias.bicepGitHub
// Publishes an alias with a cost limit for an existing AI Gateway model, creates the app-dev and support-bot runtime
// API keys, and gives support-bot, and optionally one Microsoft Entra identity, a budget of its own with overrides.
// main.bicep calls it after the quick start's template, and you can also deploy it on its own to a gateway you
// already have. The alias points at the same backend model as your default alias, so only callers that send the
// new alias name are budgeted. Key values are never outputs.

@description('Name of the existing AI Gateway (Microsoft.ApiManagement/aigateways).')
param gatewayName string

@description('Name of the existing model provider in the gateway, for example foundry-models.')
param providerName string

@description('Name of the existing backend model registration under the provider.')
param modelName string

@description('Callable alias to create. Clients send this value in the request "model" field.')
param aliasName string = '${modelName}-budget'

@description('Default budget for each caller, in US dollars. A string, so that it can hold decimals such as 0.01.')
param budgetAmount string = '5'

@description('Renewal period. Budgets renew in fixed calendar windows.')
@allowed([ 'hour', 'day', 'week', 'month', 'year' ])
param period string = 'day'

@description('Runtime API key that gets the default budget. The template creates it if it doesn\'t exist.')
param defaultKeyName string = 'app-dev'

@description('Runtime API key that gets its own budget. The template creates it if it doesn\'t exist.')
param overrideKeyName string = 'support-bot'

@description('Budget for the override key, in US dollars.')
param overrideAmount string = '50'

@description('Optional object ID of a Microsoft Entra user or service principal that gets its own budget. Empty adds no Entra override.')
param entraObjectId string = ''

@description('Budget for the Microsoft Entra identity, in US dollars.')
param entraAmount string = '20'

#disable-next-line BCP081
resource gateway 'Microsoft.ApiManagement/aigateways@2025-09-01-preview' existing = {
  name: gatewayName
}

#disable-next-line BCP081
resource workspace 'Microsoft.ApiManagement/aigateways/workspaces@2025-09-01-preview' existing = {
  parent: gateway
  name: 'default'
}

#disable-next-line BCP081
resource provider 'Microsoft.ApiManagement/aigateways/workspaces/modelProviders@2025-09-01-preview' existing = {
  parent: workspace
  name: providerName
}

#disable-next-line BCP081
resource model 'Microsoft.ApiManagement/aigateways/workspaces/modelProviders/models@2025-09-01-preview' existing = {
  parent: provider
  name: modelName
}

// Each key is a separate caller identity, so each one gets its own budget counter.
#disable-next-line BCP081
resource defaultKey 'Microsoft.ApiManagement/aigateways/apiKeys@2025-09-01-preview' = {
  parent: gateway
  name: defaultKeyName
  properties: {
    displayName: defaultKeyName
  }
}

#disable-next-line BCP081
resource overrideKey 'Microsoft.ApiManagement/aigateways/apiKeys@2025-09-01-preview' = {
  parent: gateway
  name: overrideKeyName
  properties: {
    displayName: overrideKeyName
  }
}

// Overrides are evaluated in order, and the first match wins. An API key override matches the key's resource ID.
// An Entra override matches validated token claims: here the tenant ID and the object ID of one identity.
var keyOverrides = [
  {
    apiKeyResourceId: overrideKey.id
    amount: json(overrideAmount)
  }
]
var entraOverrides = empty(entraObjectId) ? [] : [
  {
    claims: {
      tid: tenant().tenantId
      oid: entraObjectId
    }
    amount: json(entraAmount)
  }
]

#disable-next-line BCP081
resource budgetAlias 'Microsoft.ApiManagement/aigateways/workspaces/aliases@2025-09-01-preview' = {
  parent: workspace
  name: aliasName
  dependsOn: [ defaultKey ]
  properties: {
    aliasName: aliasName
    backendModels: [
      { resourceId: model.id }
    ]
    policies: [
      {
        type: 'costLimit'
        // A stable ID: changing the amount on a later deployment keeps the spend accumulated so far.
        id: guid(gateway.id, aliasName, 'costLimit')
        amount: json(budgetAmount)
        period: period
        // Overrides need per-caller counters, so the template always counts by caller identity.
        counterKey: [ 'identity' ]
        overrides: concat(keyOverrides, entraOverrides)
      }
    ]
  }
}

output aliasName string = budgetAlias.name
output defaultKeyName string = defaultKey.name
output overrideKeyName string = overrideKey.name
output chatCompletionsUrl string = 'https://${gateway.properties.frontend.defaultHostname}/default/models/openai/v1/chat/completions'

#Change the budget

The parameters come from azd environment values, with the defaults in infra/main.parameters.json: COST_LIMIT_AMOUNT for the default budget, COST_LIMIT_PERIOD (hour, day, week, month, or year), COST_LIMIT_OVERRIDE_AMOUNT for support-bot, and COST_LIMIT_ENTRA_AMOUNT for your identity. Change one with azd env set and run azd provision: only the alias changes, and it keeps the policy id. Verify lowers COST_LIMIT_AMOUNT this way.

Text

Request  Status  Error code               Tokens used  Budget headers
1        200     -                        223          …; x-alias-cost-per-day-remaining=…; x-alias-cost-per-day-consumed=0.000101900
2        200     -                        221          …; x-alias-cost-per-day-remaining=…; x-alias-cost-per-day-consumed=0.000100900
…
9        200     -                        …            …; x-alias-cost-per-day-remaining=0.000000000; …
10       403     -                        -            x-alias-cost-per-day-retry-after=1837

x-alias-cost-per-day-consumed is the estimated cost of the call, and x-alias-cost-per-day-remaining is what's left of the budget. On a cost limit attached to the model, the headers start with x-cost- instead. A blocked call has no error code in its body, so the script prints -, and …-retry-after gives the seconds until the caller can try again. How many calls succeed depends on the model's price. A call or two more than you expect is the small overshoot described in How it works.

Scan the headers for the ones that report the cost and the remaining budget, and compare them with a successful response from a key that still has budget. Unlike a token limit, which frees up as the window rolls, the caller stays blocked until the next calendar renewal period starts or you raise the budget.

#Go further

  • Cap spend across all models. Add a second Cost limit with Gateway scope, for example $200 Monthly. Each caller then has one budget across every model, including models you import later. With REST, run the same merge against the gateway workspace: https://management.azure.com/subscriptions/$SUB/resourceGroups/$RG/providers/Microsoft.ApiManagement/aigateways/$GATEWAY/workspaces/default?api-version=2025-09-01-preview ("${WS}?$API" from the variable block).
  • Combine with token limits. Keep a per-minute Token rate limit to smooth bursts and a Cost limit to cap spend. Both are checked on every request, and either one can block.
  • Budget by role or app. Use Custom token claim combination overrides, for example a roles claim with an app role value, so everyone with that role gets a different per-identity amount.
  • Chargeback by team. Export tid, oid, or a custom claim to cost metrics in Attribute tokens and cost with OpenTelemetry.

#Clean up

A $0.01 budget blocks real traffic. Delete the policy, or raise it to a production value, before you continue. Raising the amount takes effect immediately, because the accumulated spend is kept and compared with the new budget.

Choose your track
1

#Remove or raise the budget

Select Policies, open the Cost limit you created, and select Delete, or select Edit and set a production Budget amount. If you created runtime keys only for this lab, revoke them in Access›Keys.

1

#Remove the cost limit

Bash
# Read the policies, and keep every one except the cost limit
POLICIES="$(az rest --method get --url "$URL" | jq -c '[(.properties.policies // [])[] | select(.type != "costLimit")]')"

# Send the array back without the cost limit: a PATCH replaces the whole policies array
az rest --method patch --url "$URL" --body "{\"properties\":{\"policies\":$POLICIES}}" --output none &&
  echo "🚮 Cost limit is removed from $MODEL"

To keep the policy instead, run the merge again with a production budget, for example BUDGET=100.

1

# Delete everything that azd up created, and purge the Foundry account
azd down --purge --force &&
  echo "🚮 Everything that azd up created is deleted"

To keep this gateway for other labs instead, skip azd down and raise the budget to a production value: azd env set COST_LIMIT_AMOUNT 100, then azd provision.
