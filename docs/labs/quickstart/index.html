Your first model call in 5 minutes

Learn the five building blocks of Azure AI Gateway, deploy a gateway with a Microsoft Foundry model in one command, and make your first model call, all in about five minutes.

Beginner 5 min CLIBicep
Notebook Source Edit

What you'll do

  • Name the five building blocks that every AI Gateway call goes through
  • Deploy a gateway, a Foundry model, an alias, and a runtime API key with one Bicep deployment
  • Call the model through the gateway with a key, and see the gateway reject a call without one

Before you start

No prerequisite labs. Start here.

Tracks: Azure CLI, Bicep / azd

Azure AI Gateway gives your apps and agents one governed endpoint for models and tools. In five minutes you deploy a gateway with a Microsoft Foundry model behind it, and you call that model the way an app does: with the gateway's URL, an alias in the model field, and a runtime API key. You don't touch the portal, and one deployment creates everything.

#Before you begin

  • An Azure subscription where you can create resources and role assignments, for example Owner, or Contributor plus Role Based Access Control Administrator. The deployment gives the gateway a role on the Foundry account.
  • The Azure CLI↗ 2.75 or later, signed in with az login. For the Bash steps you also need curl and jq. Azure Cloud Shell↗ has all three.
  • The lab files. Clone the repo and open the quick start folder:
Bash
git clone --depth 1 https://github.com/Azure/ai-gateway
cd ai-gateway/labs/quickstart

#How it works

Every call that goes through AI Gateway uses the same five building blocks. The deployment in this quick start creates one of each.

Building blockWhat it doesIn this quick start
GatewayThe Azure resource (Microsoft.ApiManagement/aigateways) that gives your apps one runtime URL for models and toolsaigw-<unique>, at https://aigw-<unique>.<region>-01.ai.gateway.azure.com
Model providerA connection to a backend. The gateway signs in to it with its own managed identity, so your apps never hold a backend keyfoundry-models, for a new Foundry account
ModelA backend deployment that the gateway can route toThe Foundry deployment gpt-6-luna
AliasThe name that apps send in the model field. The gateway routes the alias to one or more modelsgpt-6-luna
Runtime API keyIdentifies the app that calls the gateway, for limits, cost, and monitoringapp-first-call, with 10,000 tokens per minute for each caller

Your app calls the OpenAI-compatible base URL <gateway URL>/default/models/openai/v1, so any OpenAI SDK works with a different base URL and the runtime key. For the full tour, watch the 3-minute video in How Azure AI Gateway works.

#Deploy the gateway and a model

One Bicep deployment creates the gateway, a Foundry account with a gpt-6-luna deployment, the model provider, the alias, and the runtime key. It takes about three minutes. During the preview, AI Gateway runs in eastus2 and swedencentral.

1

#Deploy the template

export RG="rg-aigw-quickstart"
export LOCATION="eastus2"                  # or swedencentral

az group create --name "$RG" --location "$LOCATION" --output none
az deployment group create --resource-group "$RG" --name quickstart \
  --template-file infra/main.bicep --parameters location="$LOCATION" \
  --query properties.outputs.gatewayUrl.value --output tsv
$RG = "rg-aigw-quickstart"
$LOCATION = "eastus2"                      # or swedencentral

az group create --name $RG --location $LOCATION --output none
az deployment group create --resource-group $RG --name quickstart `
  --template-file infra/main.bicep --parameters location=$LOCATION `
  --query properties.outputs.gatewayUrl.value --output tsv
Checkpoint:

the command prints your gateway's runtime URL, for example https://aigw-abc123.eastus2-01.ai.gateway.azure.com.

2

#Review what it created

The template reuses the Bicep modules of labs 01 and 02, so it creates exactly what those labs create step by step.

infra/main.bicepGitHub
// Quick start: everything for a first model call through Azure AI Gateway, in one deployment.
// Reuses the lab templates instead of repeating them:
//   1. ../../01-provision-gateway/infra/main.bicep  creates the gateway and its connector gateway.
//   2. ../../02-first-model-call/infra/foundry.bicep creates a Foundry account with one model deployment.
//   3. ../../02-first-model-call/infra/main.bicep    grants the gateway Foundry User on the account, adds the
//      Foundry provider, registers the model, publishes an alias, and creates a runtime API key.
// The names match lab 02, so you can continue with lab 03 on the same gateway.
targetScope = 'resourceGroup'

@description('Gateway name. It becomes the first label of the runtime host name (max 24 characters).')
@minLength(1)
@maxLength(24)
param gatewayName string = 'aigw-${uniqueString(resourceGroup().id)}'

@description('Name of the Foundry (Azure AI Services) account. It is also its globally unique subdomain.')
@minLength(2)
@maxLength(64)
param foundryAccountName string = 'aigw${uniqueString(resourceGroup().id)}'

@description('Region for the gateway and the Foundry account. During public preview, Azure AI Gateway is available in East US 2 and Sweden Central.')
@allowed([
  'eastus2'
  'swedencentral'
])
param location string = 'eastus2'

@description('Model deployment to create in Foundry. Clients send this name, the alias, in the request "model" field.')
param deploymentName string = 'gpt-6-luna'

@description('Model version to deploy.')
param modelVersion string = '2026-09-22'

@description('Tags applied to the gateway and its connector gateway.')
param tags object = {}

module gateway '../../01-provision-gateway/infra/main.bicep' = {
  name: 'quickstart-gateway'
  params: {
    gatewayName: gatewayName
    location: location
    tags: tags
  }
}

module foundry '../../02-first-model-call/infra/foundry.bicep' = {
  name: 'quickstart-foundry'
  params: {
    accountName: foundryAccountName
    location: location
    deploymentName: deploymentName
    modelName: deploymentName
    modelVersion: modelVersion
  }
}

module publish '../../02-first-model-call/infra/main.bicep' = {
  name: 'quickstart-publish'
  params: {
    gatewayName: gateway.outputs.gatewayName
    foundryAccountId: foundry.outputs.accountId
    deploymentName: foundry.outputs.deploymentName
    modelVersion: modelVersion
  }
}

output gatewayName string = gateway.outputs.gatewayName
output gatewayId string = gateway.outputs.gatewayId
output gatewayUrl string = gateway.outputs.gatewayUrl
output modelEndpoint string = publish.outputs.modelEndpoint
output aliasName string = publish.outputs.aliasName
output apiKeyName string = publish.outputs.apiKeyName
output foundryAccountName string = foundry.outputs.accountName
Tip

In a hurry? ./infra/quickstart.sh (Bash) or ./infra/quickstart.ps1 (PowerShell 7) runs this section and the next one in one go, and prints the reply. Pass a resource group and a region to change the defaults.

#Make your first call

Read the deployment's outputs, get the runtime key, and call the alias. The key goes into an environment variable, so it never shows on screen.

1

#Read the URL, the alias, and the key

out() { az deployment group show --resource-group "$RG" --name quickstart --query "properties.outputs.$1.value" --output tsv; }
export AI_GATEWAY_URL="$(out gatewayUrl)"
export AI_GATEWAY_MODEL="$(out aliasName)"
export AI_GATEWAY_API_KEY="$(az rest --method post \
  --url "https://management.azure.com$(out gatewayId)/apiKeys/$(out apiKeyName)/listSecrets?api-version=2025-09-01-preview" \
  --query primaryKey --output tsv)"
$out = az deployment group show --resource-group $RG --name quickstart --query properties.outputs --output json | ConvertFrom-Json
$env:AI_GATEWAY_URL = $out.gatewayUrl.value
$env:AI_GATEWAY_MODEL = $out.aliasName.value
$env:AI_GATEWAY_API_KEY = az rest --method post `
  --url "https://management.azure.com$($out.gatewayId.value)/apiKeys/$($out.apiKeyName.value)/listSecrets?api-version=2025-09-01-preview" `
  --query primaryKey --output tsv
2

#Call the alias

Send a Chat Completions request to the gateway, with the alias in the model field and the key in the api-key header.

curl -sS "$AI_GATEWAY_URL/default/models/openai/v1/chat/completions" \
  -H "api-key: $AI_GATEWAY_API_KEY" -H "Content-Type: application/json" \
  -d "{\"model\":\"$AI_GATEWAY_MODEL\",\"messages\":[{\"role\":\"user\",\"content\":\"In one sentence, what does an AI gateway do?\"}]}" \
  | jq -r '.choices[0].message.content'
$body = @{
  model    = $env:AI_GATEWAY_MODEL
  messages = @(@{ role = "user"; content = "In one sentence, what does an AI gateway do?" })
} | ConvertTo-Json -Depth 5
$reply = Invoke-RestMethod -Method Post -Uri "$env:AI_GATEWAY_URL/default/models/openai/v1/chat/completions" `
  -Headers @{ "api-key" = $env:AI_GATEWAY_API_KEY } -ContentType "application/json" -Body $body
$reply.choices[0].message.content
Checkpoint:

the model answers in one sentence. If you get 403 or 404 in the first minute, the gateway's new role on the Foundry account is still taking effect. Wait a minute and run the call again.

The same call from the OpenAI Python SDK (pip install openai), with the three environment variables that you set above. The SDK sends the key as a bearer token, which the gateway accepts too.

Python
import os

from openai import OpenAI

client = OpenAI(
    base_url=f"{os.environ['AI_GATEWAY_URL']}/default/models/openai/v1",
    api_key=os.environ["AI_GATEWAY_API_KEY"],
)
completion = client.chat.completions.create(
    model=os.environ["AI_GATEWAY_MODEL"],
    messages=[{"role": "user", "content": "In one sentence, what does an AI gateway do?"}],
)
print(completion.choices[0].message.content)

#Call without a key

The gateway answers only callers that it can identify. Send the same request without the key:

curl -sS -o /dev/null -w "%{http_code}\n" "$AI_GATEWAY_URL/default/models/openai/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -d "{\"model\":\"$AI_GATEWAY_MODEL\",\"messages\":[{\"role\":\"user\",\"content\":\"Hello\"}]}"
(Invoke-WebRequest -Method Post -Uri "$env:AI_GATEWAY_URL/default/models/openai/v1/chat/completions" `
  -ContentType "application/json" -Body $body -SkipHttpErrorCheck).StatusCode
Checkpoint:

you got a reply with the key, and 401 without it. Your gateway is live, and the Foundry account has no key that an app could leak: only the gateway's managed identity can call it.

#See it in the portal (optional)

Open the AI Gateway portal↗ and select your gateway:

  • Models lists the gpt-6-luna deployment, and its Aliases tab shows the alias.
  • Catalog has a playground: pick the model and send a prompt.
  • Access›Keys shows app-first-call.

#Clean up

To keep exploring, keep the gateway: it uses the same names as lab 02, so lab 03 and the labs after it work on it. Use rg-aigw-quickstart as the resource group and the gateway name that the deployment printed. On the labs site, save both in Your values.

Otherwise, delete the resource group, then purge the Foundry account. Deleted Foundry accounts stay soft-deleted for 48 hours, and the template reuses the same account name when you deploy to the same resource group again.

FOUNDRY="$(out foundryAccountName)"
az group delete --name "$RG" --yes
az cognitiveservices account purge --name "$FOUNDRY" --resource-group "$RG" --location "$LOCATION"
$foundry = $out.foundryAccountName.value
az group delete --name $RG --yes
az cognitiveservices account purge --name $foundry --resource-group $RG --location $LOCATION

#Troubleshooting

SymptomCauseFix
AuthorizationFailed on Microsoft.Authorization/roleAssignmentsYou can create resources but not role assignmentsAsk for Owner, or Role Based Access Control Administrator, on the resource group.
InsufficientQuota on the model deploymentThe subscription has no gpt-6-luna capacity left in the regionDeploy to swedencentral instead, or free capacity in Foundry↗.
FlagMustBeSetForRestore or a name conflict on the Foundry accountAn earlier run's account is soft-deletedPurge it with the clean-up command, then deploy again.
403 or 404 from the gateway in the first minuteThe gateway's role on the Foundry account, or the new alias, is still taking effectWait a minute and call again. The scripts retry for you.
401The key is missing, wrong, or in the wrong headerSend it in the api-key header, or as Authorization: Bearer <key>. Read it again with the listSecrets command.
400 that mentions authenticationThe request has both an api-key and an Authorization headerSend only one of them.
The subscription is not registered to use namespaceA resource provider isn't registered yetRun az provider register --namespace Microsoft.ApiManagement, and the same for Microsoft.CognitiveServices, then deploy again.
