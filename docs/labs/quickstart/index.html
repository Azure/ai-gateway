Your first model call in 5 minutes

Learn the five building blocks of Azure AI Gateway, create a gateway with a Microsoft Foundry model in the portal, the Azure CLI, or Bicep with azd, and make your first model call, all in about five minutes.

Beginner 5 min PortalCLIBicep Updated Oct 27, 2026
Source Edit

What you'll do

  • Name the five building blocks that every AI Gateway call goes through
  • Create a gateway, publish a Foundry model behind an alias, and create a runtime API key in the portal, the Azure CLI, or Bicep with azd
  • Make your first model call through the gateway the way an app does, with an alias and a runtime API key

Before you start

No prerequisite labs. Start here.

Tracks: Portal, Azure CLI, Bicep + azd

Azure AI Gateway gives your apps and agents one governed endpoint for models and tools. In five minutes you create a gateway, put a Microsoft Foundry model behind it, and call that model the way an app does: with the gateway's URL, an alias in the model field, and a runtime API key. Click through the AI Gateway portal, paste a few Azure CLI commands into Azure Cloud Shell, or clone a Bicep template and deploy it with one azd up.

#Before you begin

You need an Azure subscription where you can create resources and role assignments, for example Owner, or Contributor plus Role Based Access Control Administrator. The gateway gets a role on your Foundry account, so that it can call the model with its own identity. Each track lists the tools that it needs at its start.

#How it works

Every call that goes through AI Gateway uses the same five building blocks. In this quick start you create one of each.

Building blockWhat it doesIn this quick start
GatewayThe Azure resource (Microsoft.ApiManagement/aigateways) that gives your apps one runtime URL for models and toolsYour gateway, at https://<gateway>.<location>-01.ai.gateway.azure.com
Model providerA connection to a backend. The gateway signs in to it with its own managed identity, so your apps never hold a backend keyYour Foundry account. The Azure CLI and Bicep tracks name the provider foundry-models
ModelA backend deployment that the gateway can route toThe Foundry deployment gpt-6-luna
AliasThe name that apps send in the model field. The gateway routes the alias to one or more models<foundry-account-name>/gpt-6-luna in the portal, gpt-6-luna in the Azure CLI and Bicep tracks
Runtime API keyIdentifies the app that calls the gateway, for limits, cost, and monitoringapp-first-call

Your app calls the OpenAI-compatible base URL <gateway URL>/default/models/openai/v1, so any OpenAI SDK works with a different base URL and the runtime key. For the full tour, watch the 3-minute video in How Azure AI Gateway works.

#Create a gateway and make your first call

Pick one track. Each one creates the same five building blocks, makes your first call through the gateway, and ends with how to clean up. During the preview, AI Gateway runs in East US 2 (eastus2) and Sweden Central (swedencentral).

Choose your track

What you need: a browser, and a model deployment in a Microsoft Foundry account, for example gpt-6-luna.

No Foundry deployment yet? Create one in Cloud Shell.

Open Azure Cloud Shell↗ in Bash and paste these commands. They create a Foundry account with a gpt-6-luna deployment in a new resource group, in a minute or two. Then create the gateway in the same resource group, so that you can clean up with one command. Model inference is billed per use.

Bash
RG="rg-aigw-quickstart"; FOUNDRY="aigw$(openssl rand -hex 3)"
az group create --name "$RG" --location eastus2 --output none
az cognitiveservices account create --resource-group "$RG" --name "$FOUNDRY" --location eastus2 \
  --kind AIServices --sku S0 --custom-domain "$FOUNDRY" --yes --output none
az cognitiveservices account deployment create --resource-group "$RG" --name "$FOUNDRY" \
  --deployment-name gpt-6-luna --model-name gpt-6-luna --model-version 2026-09-22 --model-format OpenAI \
  --sku-name GlobalStandard --sku-capacity 10 --output none
echo "Foundry account $FOUNDRY in $RG"
1

#Create the gateway

  1. Open the AI Gateway portal↗ and sign in. For your first gateway, the portal opens Create AI gateway right away. Otherwise, open the gateway switcher in the top bar and select Create new gateway.

  2. Enter a Name, or select Generate a new name. Then choose your Subscription, a Resource group, and the Region: East US 2 or Sweden Central. For the resource group, select New, or select Existing and pick the resource group of your Foundry account, so that you can clean up both with one command.

  3. Keep the Advanced defaults and select Create gateway. All gateways opens and shows the provisioning status, which moves from Activating to Succeeded in a few minutes. Then the portal selects your new gateway.

2

#Import the model from Foundry

  1. Home opens with the Set up your gateway guide. Under Add a model, select Add from Microsoft Foundry.

    You can also start from Models›Add›Models from Microsoft Foundry.

  2. Add models from Microsoft Foundry discovers the model deployments in your subscriptions and selects all of them. In Resource groups, select only the resource group of your Foundry account. Then check that Models selects only your Foundry account with gpt-6-luna.

  3. Keep Managed identity as the Authentication method, with the system-assigned managed identity, and keep Create an alias for each model selected. Then select Add models.

  4. Models opens. The Backend models tab lists gpt-6-luna, and the Aliases tab shows the alias that apps call: <foundry-account-name>/gpt-6-luna. Note the alias.

3

#Create a runtime API key

  1. Select Access, then the Keys tab, then Create API key.

  2. Enter app-first-call as the Key name, then select Create.

  3. In API key created successfully, select Copy & done to copy the key. Keep it somewhere safe: you paste it in the next steps. You can view, rotate, or delete it later in Access›Keys.

4

#Make your first call

Call the model through the gateway in the playground, with your new key, the way an app does.

  1. Select Catalog, then select your model.

  2. Under Authentication, choose app-first-call as the API key, so that the playground calls the gateway with your new key. Then send a prompt, for example In one sentence, what does an AI gateway do?.

  3. Optional: to make the same call from code, select Continue in code. It shows the endpoint URL and snippets for cURL, the OpenAI SDK, LangChain, Vercel AI, the GitHub Copilot SDK, and Microsoft Agent Framework, plus a prompt that installs the AI Gateway plugin in your coding agent.

To run the cURL snippet, open Azure Cloud Shell↗ in Bash, paste your key at this prompt so that it never shows on screen, and then paste the snippet:

Bash
read -rsp "AI Gateway API key: " AI_GATEWAY_API_KEY && export AI_GATEWAY_API_KEY && echo
Checkpoint:

the playground answered with the key app-first-call. Your gateway is live, and your app never needs a Foundry key: only the gateway's managed identity calls Foundry.

5

#Clean up

To keep exploring, skip this step: lab 03 and the labs after it work on this gateway. On the labs site, save the resource group and the gateway name in Your values. Otherwise, delete the gateway.

  1. Open the gateway switcher in the top bar and select View all gateways.

  2. On your gateway's row, select More actions (⋮), and then select Delete.

  3. To confirm, select Delete in the dialog. The row shows Deleting until Azure removes the gateway, in about five minutes.

Deleting the gateway keeps its resource group and your Foundry account. If you created them in Cloud Shell for this quick start, delete the resource group and purge the Foundry account there too: deleted Foundry accounts stay soft-deleted for 48 hours and keep counting against your quota until you purge them.

Bash
FOUNDRY="$(az cognitiveservices account list --resource-group rg-aigw-quickstart --query "[0].name" --output tsv)"
az group delete --name rg-aigw-quickstart --yes
az cognitiveservices account purge --name "$FOUNDRY" --resource-group rg-aigw-quickstart --location eastus2
Checkpoint:

after you refresh the page, All gateways no longer lists your gateway.

What you need: Azure Cloud Shell↗, in Bash or PowerShell. It's already signed in and has the Azure CLI, curl, and jq. A local Azure CLI 2.75 or later, signed in with az login, works too. The track installs the aigateway CLI extension and creates the Foundry deployment for you.

#Start creating the gateway

Register the resource providers, which is a one-time step for each subscription, and create a resource group. Then create the gateway's companion connector gateway, which the extension doesn't create, and the gateway itself. With --no-wait, Azure keeps provisioning the gateway in the background, so you can move on right away.

for ns in Microsoft.ApiManagement Microsoft.Web Microsoft.CognitiveServices; do az provider register --namespace "$ns" --wait; done
az group create --name "$RG" --location "$LOCATION" --output none

az rest --method put --output none \
  --url "https://management.azure.com/subscriptions/$SUBSCRIPTION_ID/resourceGroups/$RG/providers/Microsoft.Web/connectorGateways/$GATEWAY?api-version=2026-05-01-preview" \
  --body "$(jq -cn --arg l "$LOCATION" '{location: $l, properties: {}}')"
az aigateway create --resource-group "$RG" --name "$GATEWAY" --location "$LOCATION" --system-assigned true --no-wait
foreach ($ns in "Microsoft.ApiManagement", "Microsoft.Web", "Microsoft.CognitiveServices") { az provider register --namespace $ns --wait }
az group create --name $RG --location $LOCATION --output none

@{ location = $LOCATION; properties = @{} } | ConvertTo-Json -Compress | Set-Content body.json
az rest --method put --output none --body "@body.json" `
  --url "https://management.azure.com/subscriptions/$SUBSCRIPTION_ID/resourceGroups/$RG/providers/Microsoft.Web/connectorGateways/${GATEWAY}?api-version=2026-05-01-preview"
Remove-Item body.json
az aigateway create --resource-group $RG --name $GATEWAY --location $LOCATION --system-assigned true --no-wait

#Deploy the model in Foundry

While the gateway provisions, create a Foundry account with a gpt-6-luna deployment. Then give the gateway's managed identity the Foundry User role on the account. The gateway calls the model with this identity, so your apps never hold a Foundry key.

az cognitiveservices account create --resource-group "$RG" --name "$FOUNDRY" --location "$LOCATION" \
  --kind AIServices --sku S0 --custom-domain "$FOUNDRY" --yes --output none
az cognitiveservices account deployment create --resource-group "$RG" --name "$FOUNDRY" \
  --deployment-name "$DEPLOYMENT" --model-name gpt-6-luna --model-version 2026-09-22 --model-format OpenAI \
  --sku-name GlobalStandard --sku-capacity 10 --output none

export FOUNDRY_ID="$(az cognitiveservices account show --resource-group "$RG" --name "$FOUNDRY" --query id --output tsv)"
PRINCIPAL_ID="$(az aigateway show --resource-group "$RG" --name "$GATEWAY" --query identity.principalId --output tsv)"
az role assignment create --assignee-object-id "$PRINCIPAL_ID" --assignee-principal-type ServicePrincipal \
  --role "53ca6127-db72-4b80-b1b0-d745d6d5456d" --scope "$FOUNDRY_ID" --output none    # Foundry User
az cognitiveservices account create --resource-group $RG --name $FOUNDRY --location $LOCATION `
  --kind AIServices --sku S0 --custom-domain $FOUNDRY --yes --output none
az cognitiveservices account deployment create --resource-group $RG --name $FOUNDRY `
  --deployment-name $DEPLOYMENT --model-name gpt-6-luna --model-version 2026-09-22 --model-format OpenAI `
  --sku-name GlobalStandard --sku-capacity 10 --output none

$FOUNDRY_ID   = az cognitiveservices account show --resource-group $RG --name $FOUNDRY --query id --output tsv
$PRINCIPAL_ID = az aigateway show --resource-group $RG --name $GATEWAY --query identity.principalId --output tsv
az role assignment create --assignee-object-id $PRINCIPAL_ID --assignee-principal-type ServicePrincipal `
  --role "53ca6127-db72-4b80-b1b0-d745d6d5456d" --scope $FOUNDRY_ID --output none    # Foundry User

#Publish the model

Wait for the gateway, then publish the deployment in three steps: a provider that points at the Foundry account and signs in with the managed identity, a model for the deployment, and an alias that apps send in the model field.

az aigateway wait --resource-group "$RG" --name "$GATEWAY" --created

az aigateway model-provider create --resource-group "$RG" --gateway-name "$GATEWAY" --name "$PROVIDER" --output none \
  --kind Foundry --display-name "Foundry models" \
  --foundry "$(jq -cn --arg e "https://$FOUNDRY.cognitiveservices.azure.com/" --arg id "$FOUNDRY_ID" '{endpoint: $e,
      resourceIds: [$id], authentication: {kind: "ManagedIdentity", managedIdentity: {resource: "https://cognitiveservices.azure.com/"}}}')"
az aigateway model create --resource-group "$RG" --gateway-name "$GATEWAY" --provider-name "$PROVIDER" --name "$DEPLOYMENT" \
  --api-format OpenAIChatCompletions --supported-endpoints /openai/v1/chat/completions /openai/v1/responses \
  --deployment-config "{resourceId:$FOUNDRY_ID/deployments/$DEPLOYMENT,modelName:$DEPLOYMENT}" --output none
az aigateway model-alias create --resource-group "$RG" --gateway-name "$GATEWAY" --name "$DEPLOYMENT" --only-show-errors \
  --backend-model resource-id="$GATEWAY_ID/workspaces/default/modelProviders/$PROVIDER/models/$DEPLOYMENT" \
  --query properties.aliasName --output tsv
az aigateway wait --resource-group $RG --name $GATEWAY --created

@{ endpoint       = "https://$FOUNDRY.cognitiveservices.azure.com/"
   resourceIds    = @($FOUNDRY_ID)
   authentication = @{ kind = "ManagedIdentity"; managedIdentity = @{ resource = "https://cognitiveservices.azure.com/" } } } |
  ConvertTo-Json -Depth 10 -Compress | Set-Content foundry.json
az aigateway model-provider create --resource-group $RG --gateway-name $GATEWAY --name $PROVIDER --output none `
  --kind Foundry --display-name "Foundry models" --foundry "@foundry.json"
az aigateway model create --resource-group $RG --gateway-name $GATEWAY --provider-name $PROVIDER --name $DEPLOYMENT `
  --api-format OpenAIChatCompletions --supported-endpoints /openai/v1/chat/completions /openai/v1/responses `
  --deployment-config "{resourceId:$FOUNDRY_ID/deployments/$DEPLOYMENT,modelName:$DEPLOYMENT}" --output none
az aigateway model-alias create --resource-group $RG --gateway-name $GATEWAY --name $DEPLOYMENT --only-show-errors `
  --backend-model resource-id="$GATEWAY_ID/workspaces/default/modelProviders/$PROVIDER/models/$DEPLOYMENT" `
  --query properties.aliasName --output tsv
Remove-Item foundry.json
5

#Create a runtime API key

Create a key for your app. Then read the key, the gateway URL, and the alias into environment variables, so that the key never shows on screen.

az aigateway api-key create --resource-group "$RG" --gateway-name "$GATEWAY" --name app-first-call \
  --display-name app-first-call --output none

export AI_GATEWAY_API_KEY="$(az aigateway api-key list-secrets --resource-group "$RG" --gateway-name "$GATEWAY" \
  --name app-first-call --query primaryKey --output tsv)"
export AI_GATEWAY_URL="https://$(az aigateway show --resource-group "$RG" --name "$GATEWAY" --query properties.frontend.defaultHostname --output tsv)"
export AI_GATEWAY_MODEL="$DEPLOYMENT"
echo "$AI_GATEWAY_URL"
az aigateway api-key create --resource-group $RG --gateway-name $GATEWAY --name app-first-call `
  --display-name app-first-call --output none

$env:AI_GATEWAY_API_KEY = az aigateway api-key list-secrets --resource-group $RG --gateway-name $GATEWAY `
  --name app-first-call --query primaryKey --output tsv
$env:AI_GATEWAY_URL     = "https://" + (az aigateway show --resource-group $RG --name $GATEWAY --query properties.frontend.defaultHostname --output tsv)
$env:AI_GATEWAY_MODEL   = $DEPLOYMENT
$env:AI_GATEWAY_URL
Checkpoint:

the alias command printed gpt-6-luna, and the last command printed your gateway's runtime URL, for example https://aigw-abc123.eastus2-01.ai.gateway.azure.com.

6

#Make your first call

Send a Chat Completions request to the gateway's OpenAI-compatible base URL, the way an app does: the alias in the model field and the key in the api-key header.

curl -sS "$AI_GATEWAY_URL/default/models/openai/v1/chat/completions" \
  -H "api-key: $AI_GATEWAY_API_KEY" -H "Content-Type: application/json" \
  -d "{\"model\":\"$AI_GATEWAY_MODEL\",\"messages\":[{\"role\":\"user\",\"content\":\"In one sentence, what does an AI gateway do?\"}]}" \
  | jq -r '.choices[0].message.content // .error.message'
$body = @{
  model    = $env:AI_GATEWAY_MODEL
  messages = @(@{ role = "user"; content = "In one sentence, what does an AI gateway do?" })
} | ConvertTo-Json -Depth 5
$reply = Invoke-RestMethod -Method Post -Uri "$env:AI_GATEWAY_URL/default/models/openai/v1/chat/completions" `
  -Headers @{ "api-key" = $env:AI_GATEWAY_API_KEY } -ContentType "application/json" -Body $body
$reply.choices[0].message.content
Checkpoint:

the model answers in one sentence. Your gateway is live, and your app never needed a Foundry key: only the gateway's managed identity calls Foundry. If you get 403 or 404 in the first minute, the gateway's new role on the Foundry account is still taking effect. Wait a minute and run the call again.

To see what you created, open the AI Gateway portal↗ and select your gateway in the top bar: Models, Access›Keys, and the Catalog playground.

What you need: Azure Cloud Shell↗, in Bash or PowerShell. It's already signed in and has the Azure Developer CLI (azd), the Azure CLI, Git, curl, and jq. 1

#Clone the template

The template is a small azd project in the labs/quickstart↗ folder of the GitHub repo: an azure.yaml and a Bicep file for each scope. Clone the repo, then move into that folder. The clone also gets the other labs, which you can use next.

git clone https://github.com/Azure/ai-gateway.git
cd ai-gateway/labs/quickstart
git clone https://github.com/Azure/ai-gateway.git
Set-Location ai-gateway/labs/quickstart

infra/main.bicep creates the resource group rg-<environment name> and passes unique names to infra/resources.bicep, which creates the five building blocks in the same order as the other tracks:

infra/resources.bicepGitHub
// The five building blocks of the quick start, the same ones that the portal and Azure CLI tracks create:
// a gateway, a Foundry model deployment, a model provider that signs in with the gateway's managed identity,
// an alias that apps send in the "model" field, and a runtime API key.
targetScope = 'resourceGroup'

param location string
param tags object = {}

@description('Gateway name. It becomes the first label of the runtime host name.')
@maxLength(24)
param gatewayName string

@description('Foundry account name, also its custom subdomain. It must be globally unique.')
param foundryName string

param modelName string = 'gpt-6-luna'
param modelVersion string = '2026-09-22'

@description('Deployment capacity in thousands of tokens per minute.')
param capacity int = 10

param providerName string = 'foundry-models'
param apiKeyName string = 'app-first-call'

var foundryUserRoleId = '53ca6127-db72-4b80-b1b0-d745d6d5456d'

// 1. The gateway in the Consumption SKU, with a system-assigned managed identity, then its companion connector
//    gateway.
#disable-next-line BCP081
resource gateway 'Microsoft.ApiManagement/aigateways@2025-09-01-preview' = {
  name: gatewayName
  location: location
  tags: tags
  identity: {
    type: 'SystemAssigned'
  }
  sku: {
    name: 'Consumption'
  }
  properties: {}
}

#disable-next-line BCP081
resource connectorGateway 'Microsoft.Web/connectorGateways@2026-05-01-preview' = {
  name: gatewayName
  location: location
  tags: tags
  properties: {}
  dependsOn: [
    gateway
  ]
}

#disable-next-line BCP081
resource workspace 'Microsoft.ApiManagement/aigateways/workspaces@2025-09-01-preview' existing = {
  parent: gateway
  name: 'default'
}

// 2. A Foundry account with one model deployment. Local auth is off: only Entra identities can call it.
resource foundry 'Microsoft.CognitiveServices/accounts@2025-04-01-preview' = {
  name: foundryName
  location: location
  tags: tags
  kind: 'AIServices'
  sku: {
    name: 'S0'
  }
  properties: {
    customSubDomainName: foundryName
    disableLocalAuth: true
    publicNetworkAccess: 'Enabled'
  }
}

resource deployment 'Microsoft.CognitiveServices/accounts/deployments@2025-04-01-preview' = {
  parent: foundry
  name: modelName
  sku: {
    name: 'GlobalStandard'
    capacity: capacity
  }
  properties: {
    model: {
      format: 'OpenAI'
      name: modelName
      version: modelVersion
    }
  }
}

// The gateway calls Foundry with its own identity, so it needs the Foundry User role on the account.
resource foundryUser 'Microsoft.Authorization/roleAssignments@2022-04-01' = {
  scope: foundry
  name: guid(foundry.id, gateway.id, foundryUserRoleId)
  properties: {
    principalId: gateway.identity.principalId
    principalType: 'ServicePrincipal'
    roleDefinitionId: subscriptionResourceId('Microsoft.Authorization/roleDefinitions', foundryUserRoleId)
  }
}

// 3. A model provider that points at the Foundry account and signs in with the managed identity.
#disable-next-line BCP081
resource provider 'Microsoft.ApiManagement/aigateways/workspaces/modelProviders@2025-09-01-preview' = {
  parent: workspace
  name: providerName
  dependsOn: [
    foundryUser
  ]
  properties: {
    kind: 'Foundry'
    foundry: {
      endpoint: 'https://${foundryName}.cognitiveservices.azure.com/'
      resourceIds: [
        foundry.id
      ]
      authentication: {
        kind: 'ManagedIdentity'
        managedIdentity: {
          resource: 'https://cognitiveservices.azure.com/'
        }
      }
    }
  }
}

// 4. The deployment as a backend model, and an alias that apps send in the "model" field.
#disable-next-line BCP081
resource model 'Microsoft.ApiManagement/aigateways/workspaces/modelProviders/models@2025-09-01-preview' = {
  parent: provider
  name: modelName
  properties: {
    displayName: modelName
    apiFormat: 'OpenAIChatCompletions'
    supportedEndpoints: [
      '/openai/v1/chat/completions'
      '/openai/v1/responses'
    ]
    deployment: {
      resourceId: deployment.id
      modelName: modelName
      modelVersion: modelVersion
    }
  }
}

#disable-next-line BCP081
resource alias 'Microsoft.ApiManagement/aigateways/workspaces/aliases@2025-09-01-preview' = {
  parent: workspace
  name: modelName
  properties: {
    aliasName: modelName
    backendModels: [
      {
        resourceId: model.id
      }
    ]
  }
}

// 5. A runtime API key for your first app. Read its value with az aigateway api-key list-secrets; it's never a
//    deployment output.
#disable-next-line BCP081
resource apiKey 'Microsoft.ApiManagement/aigateways/apiKeys@2025-09-01-preview' = {
  parent: gateway
  name: apiKeyName
  properties: {}
}

output gatewayName string = gateway.name
output gatewayId string = gateway.id
output gatewayUrl string = 'https://${gateway.properties.frontend.defaultHostname}'
output aliasName string = alias.name
output foundryName string = foundry.name

// For the labs that build on this template: they call it as a module, then add their own resources.
output gatewayPrincipalId string = gateway.identity.principalId
output providerName string = provider.name

2

#Deploy with azd up

Create an azd environment named aigw-quickstart in your current subscription, so that azd doesn't prompt you. Then provision everything with one command. It takes about three minutes.

azd env new aigw-quickstart --location eastus2 --subscription "$(az account show --query id --output tsv)"
azd up
azd env new aigw-quickstart --location eastus2 --subscription (az account show --query id --output tsv)
azd up

For Sweden Central, use --location swedencentral. azd saves the template's outputs, like the gateway URL and the alias, as environment values. The API key isn't an output, so it never lands in a file or a deployment log.

3

#Read the URL, the alias, and the key

Read the outputs, and read the key from the gateway into an environment variable, so that it never shows on screen.

export AI_GATEWAY_URL="$(azd env get-value AI_GATEWAY_URL)"
export AI_GATEWAY_MODEL="$(azd env get-value AI_GATEWAY_MODEL)"
export AI_GATEWAY_API_KEY="$(az aigateway api-key list-secrets --ids "$(azd env get-value AI_GATEWAY_ID)/apiKeys/app-first-call" \
  --query primaryKey --output tsv)"
echo "$AI_GATEWAY_URL"
$env:AI_GATEWAY_URL     = azd env get-value AI_GATEWAY_URL
$env:AI_GATEWAY_MODEL   = azd env get-value AI_GATEWAY_MODEL
$GATEWAY_ID             = azd env get-value AI_GATEWAY_ID
$env:AI_GATEWAY_API_KEY = az aigateway api-key list-secrets --ids "$GATEWAY_ID/apiKeys/app-first-call" `
  --query primaryKey --output tsv
$env:AI_GATEWAY_URL
Checkpoint:

azd up ended with SUCCESS, and the last command printed your gateway's runtime URL, for example https://aigw-abc123.eastus2-01.ai.gateway.azure.com.

4

#Make your first call

Send a Chat Completions request to the gateway's OpenAI-compatible base URL, the way an app does: the alias in the model field and the key in the api-key header.

curl -sS "$AI_GATEWAY_URL/default/models/openai/v1/chat/completions" \
  -H "api-key: $AI_GATEWAY_API_KEY" -H "Content-Type: application/json" \
  -d "{\"model\":\"$AI_GATEWAY_MODEL\",\"messages\":[{\"role\":\"user\",\"content\":\"In one sentence, what does an AI gateway do?\"}]}" \
  | jq -r '.choices[0].message.content // .error.message'
$body = @{
  model    = $env:AI_GATEWAY_MODEL
  messages = @(@{ role = "user"; content = "In one sentence, what does an AI gateway do?" })
} | ConvertTo-Json -Depth 5
$reply = Invoke-RestMethod -Method Post -Uri "$env:AI_GATEWAY_URL/default/models/openai/v1/chat/completions" `
  -Headers @{ "api-key" = $env:AI_GATEWAY_API_KEY } -ContentType "application/json" -Body $body
$reply.choices[0].message.content
Checkpoint:

the model answers in one sentence. Your gateway is live, and your app never needed a Foundry key: only the gateway's managed identity calls Foundry. If you get 403 or 404 in the first minute, the gateway's new role on the Foundry account is still taking effect. Wait a minute and run the call again.

To see what you created, open the AI Gateway portal↗ and select your gateway in the top bar: Models, Access›Keys, and the Catalog playground.

5

#Clean up

To keep exploring, skip this step: lab 03 and the labs after it work on this gateway. Otherwise, in the ai-gateway/labs/quickstart folder, delete everything that azd up created. --purge also purges the Foundry account, which would otherwise stay soft-deleted for 48 hours and keep counting against your quota. It takes about ten minutes.

azd down --purge --force
azd down --purge --force
Checkpoint:

azd down ended with SUCCESS. The resource group rg-aigw-quickstart is gone, and you can delete the ai-gateway folder.

#Troubleshooting

SymptomCauseFix
A subscription is disabled in Create AI gatewayYou can't write API Management or connector gateway resources in itPick another subscription, or ask for Contributor on it.
AuthorizationFailed on Microsoft.Authorization/roleAssignmentsYou can create resources but not role assignmentsAsk for Owner, or Role Based Access Control Administrator, on the resource group.
InsufficientQuota on the model deploymentThe subscription has no gpt-6-luna capacity left in the regionStart again in swedencentral: set LOCATION in the Azure CLI track, or run azd env new with a new name and --location swedencentral in the Bicep + azd track. Or free capacity in Foundry↗.
InvalidResourceGroupLocation from azd upThe resource group rg-<environment name> already exists in another regionRun azd env new with a new environment name, or delete the old resource group.
403 or 404 from the gateway in the first minuteThe gateway's role on the Foundry account, or the new alias, is still taking effectWait a minute and call again.
403 from the backend that doesn't go awayThe gateway's managed identity has no role on the Foundry accountAssign it Foundry User on the account, as in the Azure CLI track's Deploy the model in Foundry step, and wait a few minutes.
401The key is missing, wrong, or in the wrong headerSend it in the api-key header, or as Authorization: Bearer <key>. In the portal, copy it again from Access›Keys.
400 that mentions authenticationThe request has both an api-key and an Authorization headerSend only one of them.
The subscription is not registered to use namespaceA resource provider isn't registered yetRun the az provider register loop from Start creating the gateway, then try again.
