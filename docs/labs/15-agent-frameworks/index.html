Connect agent frameworks to models and tools

Point Microsoft Agent Framework, the OpenAI Agents SDK, and LangChain with LangGraph at the gateway's OpenAI-compatible model endpoint and its MCP endpoint, so every model and tool call an agent makes passes through gateway policies and shows up in Monitoring.

Intermediate 30 min Code Updated Oct 28, 2026
Source Edit

What you'll do

  • Configure a framework's model client with the gateway's OpenAI-compatible endpoint, an alias, and a runtime key
  • Load governed tools from the gateway's MCP endpoint in each framework
  • Run the same agent in Microsoft Agent Framework, the OpenAI Agents SDK, and LangGraph
  • Prove that the gateway authenticates and records every model and tool call the agent makes

Before you start

  • 02Publish a Foundry model and make your first call
  • 04Federate MCP tools behind one endpoint

Tracks: Code

Your teams build agents with different frameworks, and each one wires its own model keys and tool servers. Nobody can say which agent called what, and a policy change means touching every codebase. In this lab you point three popular frameworks at one gateway: two URLs and one header, and every model and tool call the agent makes is governed and observable in the same place.

#Before you begin

  • Complete Publish a Foundry model and make your first call. You need the gateway URL, a callable alias, and a runtime key. Create a dedicated key for this agent under Access›Keys, for example docs-agent, so its traffic is easy to find.
  • Complete Federate MCP tools behind one endpoint. The samples use the learn MCP server from that lab. Any MCP server on your gateway works.
  • Python 3.10 or later. The samples were tested together on Python 3.13 with the versions in infra/requirements.txt↗.
  • Optional: monitoring from Monitor usage, cost, and traces, to see the agent's calls.
  • For the scripts and samples: the labs repo, cloned. Run them from the lab folder, ~/ai-gateway/labs/15-agent-frameworks.

#How it works

Agent frameworks talk to models through an OpenAI-compatible client and to tools through an MCP client. Point both at the gateway. The model client takes the runtime key as its API key, which it sends as a bearer token that the model endpoint accepts. The MCP client sends the same key in the api-key header, the only place the MCP endpoint reads it.

The framework still owns orchestration, memory, and state. The gateway authenticates each call, applies the policies on the alias, the MCP server, and the gateway, routes the alias to its provider, and records telemetry for every call that leaves the agent. Changing a model, a policy, or a tool list then needs no agent code change.

All three use the same two endpoints. The gateway serves both model APIs on the model endpoint:

  • Model: https://<gateway>.eastus2-01.ai.gateway.azure.com/default/models/openai/v1
  • MCP: https://<gateway>.eastus2-01.ai.gateway.azure.com/default/toolservers/<server-name>/mcp

#Point the model client at the gateway

Each framework takes the gateway's model endpoint as its base URL, the alias as the model name, and the runtime key as its API key.

1

#Configure the model client

# The model endpoint accepts the key as the SDK's bearer token. Adding an api-key header as well gets a 400.
client = OpenAIChatClient(
    model=model,
    base_url=f"{gateway_url}/default/models/openai/v1/",
    api_key=api_key,
)
client = AsyncOpenAI(
    base_url=f"{gateway_url}/default/models/openai/v1",
    api_key=api_key,
)
# ...
model=OpenAIChatCompletionsModel(model=model, openai_client=client),
model = ChatOpenAI(
    model=model_name,
    base_url=f"{gateway_url}/default/models/openai/v1",
    api_key=api_key,
)

Don't add an api-key default header to the model client as well: the gateway rejects a request that has both an api-key and an Authorization header with 400.

Note

The OpenAI Agents SDK sample turns off the SDK's built-in tracing, which otherwise exports traces to OpenAI. The gateway already records each model and tool call.

#Add the gateway's MCP tools

The MCP client connects to one MCP server on the gateway and sends the same key. The agent only sees the tools that the server publishes, after the gateway's tool controls.

1

#Connect to the MCP endpoint

mcp_tool = MCPStreamableHTTPTool(
    name="gateway-tools",
    url=f"{gateway_url}/default/toolservers/{server}/mcp",
    static_headers={"api-key": api_key},
    approval_mode="never_require",
    request_timeout=60,
)
async with MCPServerStreamableHttp(
    name="gateway-tools",
    params={
        "url": f"{gateway_url}/default/toolservers/{server}/mcp",
        "headers": {"api-key": api_key},
        "timeout": 60,
    },
    cache_tools_list=True,
    client_session_timeout_seconds=60,
) as mcp_server:
mcp_client = MultiServerMCPClient(
    {
        "gateway-tools": {
            "transport": "streamable_http",
            "url": f"{gateway_url}/default/toolservers/{server}/mcp",
            "headers": {"api-key": api_key},
        }
    }
)
tools = await mcp_client.get_tools()

The learn tools only read documentation, so the Agent Framework sample runs them without asking for approval. For tools that change data, set approval_mode="always_require" on the MCP tool and handle the approval requests in your app. Also narrow the tool list on the gateway, as in Control which tools agents can call, so every agent gets the same limits.

infra/agent_framework_agent.pyGitHub
"""A Microsoft Agent Framework agent whose model and MCP tool calls both go through AI Gateway.

An OpenAIChatClient (Responses API) points at the gateway's OpenAI-compatible endpoint and sends the runtime key as
its API key. Tools come from the gateway's MCP endpoint for one MCP server, with the key in the api-key header.

Usage:
    cp .env.example .env      # then fill in the values
    python agent_framework_agent.py ["your question"]
"""

import asyncio
import os
import sys

from agent_framework import Agent, MCPStreamableHTTPTool
from agent_framework.openai import OpenAIChatClient
from dotenv import load_dotenv

INSTRUCTIONS = (
    "You answer questions about Microsoft technologies. Use the Microsoft Learn tools to find current "
    "documentation and cite the URLs you used. Keep answers under 120 words."
)
QUESTION = "What is AI Gateway in Azure API Management? Answer in three bullet points."


def settings() -> tuple[str, str, str, str]:
    load_dotenv()
    missing = [name for name in ("AI_GATEWAY_URL", "AI_GATEWAY_MODEL", "AI_GATEWAY_API_KEY") if not os.environ.get(name)]
    if missing:
        sys.exit(f"Set {', '.join(missing)} in .env or your shell. See .env.example.")
    gateway_url = os.environ["AI_GATEWAY_URL"].rstrip("/")
    server = os.environ.get("AI_GATEWAY_MCP_SERVER", "learn")
    return gateway_url, os.environ["AI_GATEWAY_MODEL"], os.environ["AI_GATEWAY_API_KEY"], server


async def main() -> None:
    gateway_url, model, api_key, server = settings()
    question = " ".join(sys.argv[1:]) or QUESTION

    # The model endpoint accepts the key as the SDK's bearer token. Adding an api-key header as well gets a 400.
    client = OpenAIChatClient(
        model=model,
        base_url=f"{gateway_url}/default/models/openai/v1/",
        api_key=api_key,
    )

    mcp_tool = MCPStreamableHTTPTool(
        name="gateway-tools",
        url=f"{gateway_url}/default/toolservers/{server}/mcp",
        static_headers={"api-key": api_key},
        approval_mode="never_require",
        request_timeout=60,
    )

    async with mcp_tool:
        agent = Agent(client=client, name="docs-agent", instructions=INSTRUCTIONS, tools=mcp_tool)
        print(f"Model {model} and MCP server {server} through {gateway_url}\n")
        result = await agent.run(question)
        print(result.text)


if __name__ == "__main__":
    asyncio.run(main())
infra/openai_agents_agent.pyGitHub
"""An OpenAI Agents SDK agent whose model and MCP tool calls both go through AI Gateway.

The agent uses the Chat Completions model class with an AsyncOpenAI client pointed at the gateway's
OpenAI-compatible endpoint, and an MCP server connection to the gateway's MCP endpoint. The client sends the runtime
key as its API key, and the MCP connection sends it in the api-key header.

Usage:
    cp .env.example .env      # then fill in the values
    python openai_agents_agent.py ["your question"]
"""

import asyncio
import os
import sys

from agents import Agent, OpenAIChatCompletionsModel, Runner, set_tracing_disabled
from agents.mcp import MCPServerStreamableHttp
from dotenv import load_dotenv
from openai import AsyncOpenAI

INSTRUCTIONS = (
    "You answer questions about Microsoft technologies. Use the Microsoft Learn tools to find current "
    "documentation and cite the URLs you used. Keep answers under 120 words."
)
QUESTION = "What is AI Gateway in Azure API Management? Answer in three bullet points."


def settings() -> tuple[str, str, str, str]:
    load_dotenv()
    missing = [name for name in ("AI_GATEWAY_URL", "AI_GATEWAY_MODEL", "AI_GATEWAY_API_KEY") if not os.environ.get(name)]
    if missing:
        sys.exit(f"Set {', '.join(missing)} in .env or your shell. See .env.example.")
    gateway_url = os.environ["AI_GATEWAY_URL"].rstrip("/")
    server = os.environ.get("AI_GATEWAY_MCP_SERVER", "learn")
    return gateway_url, os.environ["AI_GATEWAY_MODEL"], os.environ["AI_GATEWAY_API_KEY"], server


async def main() -> None:
    gateway_url, model, api_key, server = settings()
    question = " ".join(sys.argv[1:]) or QUESTION

    # The SDK exports its own traces to OpenAI by default. AI Gateway already records every model and tool call.
    set_tracing_disabled(True)

    client = AsyncOpenAI(
        base_url=f"{gateway_url}/default/models/openai/v1",
        api_key=api_key,
    )

    async with MCPServerStreamableHttp(
        name="gateway-tools",
        params={
            "url": f"{gateway_url}/default/toolservers/{server}/mcp",
            "headers": {"api-key": api_key},
            "timeout": 60,
        },
        cache_tools_list=True,
        client_session_timeout_seconds=60,
    ) as mcp_server:
        agent = Agent(
            name="docs-agent",
            instructions=INSTRUCTIONS,
            model=OpenAIChatCompletionsModel(model=model, openai_client=client),
            mcp_servers=[mcp_server],
        )
        print(f"Model {model} and MCP server {server} through {gateway_url}\n")
        result = await Runner.run(agent, question)
        print(result.final_output)


if __name__ == "__main__":
    asyncio.run(main())
infra/langgraph_agent.pyGitHub
"""A LangChain agent (built on LangGraph) whose model and MCP tool calls both go through AI Gateway.

ChatOpenAI points at the gateway's OpenAI-compatible endpoint, and langchain-mcp-adapters loads tools from the
gateway's MCP endpoint over streamable HTTP. The model takes the runtime key as its API key, and the MCP client
sends it in the api-key header. LangGraph keeps orchestration and state; the gateway applies policies and records
telemetry for every call that leaves the agent.

Usage:
    cp .env.example .env      # then fill in the values
    python langgraph_agent.py ["your question"]
"""

import asyncio
import os
import sys

from dotenv import load_dotenv
from langchain.agents import create_agent
from langchain_mcp_adapters.client import MultiServerMCPClient
from langchain_openai import ChatOpenAI

INSTRUCTIONS = (
    "You answer questions about Microsoft technologies. Use the Microsoft Learn tools to find current "
    "documentation and cite the URLs you used. Keep answers under 120 words."
)
QUESTION = "What is AI Gateway in Azure API Management? Answer in three bullet points."


def settings() -> tuple[str, str, str, str]:
    load_dotenv()
    missing = [name for name in ("AI_GATEWAY_URL", "AI_GATEWAY_MODEL", "AI_GATEWAY_API_KEY") if not os.environ.get(name)]
    if missing:
        sys.exit(f"Set {', '.join(missing)} in .env or your shell. See .env.example.")
    gateway_url = os.environ["AI_GATEWAY_URL"].rstrip("/")
    server = os.environ.get("AI_GATEWAY_MCP_SERVER", "learn")
    return gateway_url, os.environ["AI_GATEWAY_MODEL"], os.environ["AI_GATEWAY_API_KEY"], server


async def main() -> None:
    gateway_url, model_name, api_key, server = settings()
    question = " ".join(sys.argv[1:]) or QUESTION

    model = ChatOpenAI(
        model=model_name,
        base_url=f"{gateway_url}/default/models/openai/v1",
        api_key=api_key,
    )

    mcp_client = MultiServerMCPClient(
        {
            "gateway-tools": {
                "transport": "streamable_http",
                "url": f"{gateway_url}/default/toolservers/{server}/mcp",
                "headers": {"api-key": api_key},
            }
        }
    )
    tools = await mcp_client.get_tools()

    agent = create_agent(model, tools, system_prompt=INSTRUCTIONS)
    print(f"Model {model_name} and MCP server {server} ({len(tools)} tools) through {gateway_url}\n")
    result = await agent.ainvoke({"messages": [{"role": "user", "content": question}]})
    print(result["messages"][-1].content)


if __name__ == "__main__":
    asyncio.run(main())

#Verify

1

#Prove the gateway is in the path

Run one sample with a wrong key. The gateway rejects the agent's first call with 401, before any model or tool runs.

AI_GATEWAY_API_KEY="not-a-key" python langgraph_agent.py
$env:AI_GATEWAY_API_KEY = "not-a-key"; python langgraph_agent.py; Remove-Item Env:AI_GATEWAY_API_KEY

Expected output: a traceback that ends with a 401 Unauthorized error for the MCP endpoint, because each sample connects to the MCP server before it calls the model. A key set in your shell takes precedence over .env.

2

#See the agent in Monitoring

If you set up monitoring in Monitor usage, cost, and traces, wait a few minutes and open Monitoring. On Overview, Model calls and Tool calls both grew. On Tools, the learn server shows up in Usage by tool server, and Tool usage by caller identity shows the agent's key. A run usually makes at least two model calls: one that asks for a tool and one that writes the answer. Open Traces to see each call with its gateway policies.

#Go further

  • Give each agent an identity. Create one runtime key per agent, as in Issue and rotate runtime API keys, so Monitoring and cost limits can tell agents apart. For production, drop keys: send a Microsoft Entra token for https://azure-api.net/aigateway from the agent's managed identity or agent identity, with the AI Gateway User role, as in Go keyless with Microsoft Entra ID and RBAC.
  • Govern the agent, not the code. Add a token limit to the alias with Throttle tokens per caller with token limits, or a request rate limit to the MCP server. The agent gets 429 responses without any code change, so handle Retry-After in long-running agents.
  • Swap models behind the alias. Retarget the alias to another model or provider, as in Publish models from any provider behind stable aliases. The agents keep working with the same AI_GATEWAY_MODEL.
  • Use .NET. The .NET hosted agent sample↗ connects Microsoft Agent Framework for .NET to a gateway. With the AI Gateway tier, pass the runtime key as the client's API key and don't add an api-key header to model calls.
  • Other SDKs. For the GitHub Copilot SDK and other frameworks, use their model and MCP configuration points with the same endpoints, and confirm the endpoint formats and authentication they support.

#Clean up

  • Delete infra/.env, because it holds a key, and infra/.venv if you don't need it.
  • If you created a key just for this lab, revoke it under Access›Keys.

Keep the gateway, the alias, and the learn MCP server. Other labs reuse them.
