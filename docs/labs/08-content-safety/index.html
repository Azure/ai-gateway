Governance & cost · Lab 08

Screen prompts and responses with content safety

Add a content safety policy that screens prompts, tool inputs, and responses for hate, self-harm, sexual, and violent content, tune each category's threshold, and see how blocked calls return 400.

Beginner 20 min PortalCLIRESTBicep Updated Oct 28, 2026
Source Edit

What you'll do

  • Explain how content safety severity thresholds decide what the gateway blocks
  • Add a content safety policy to a model in the portal, with the Azure CLI, or with the REST API
  • Override the threshold for one category without changing the others
  • Publish a screened alias with Bicep and azd, without touching existing clients
  • Test the policy with benign prompts and tell a gateway block from a Foundry content filter result

Before you start

  • 02Publish a Foundry model and make your first call

Tracks: Portal, Azure CLI, REST, Bicep + azd

Your gateway now serves a customer-facing assistant and several internal agents, on models from more than one provider. Your responsible AI review asks for one consistent rule: every prompt and every response is screened for harmful content, whichever model or tool handles it. In this lab you add a content safety policy at the gateway, tune it per category, and see what a blocked call looks like to a client.

#Before you begin

#How it works

A content safety policy screens prompts, tool inputs, and responses with Azure AI Content Safety. It rates content in four categories: Hate, Self-harm, Sexual, and Violence. You set a severity threshold for each category independently. When content reaches the threshold, the gateway blocks the call and returns 400. A blocked prompt never reaches the backend.

The threshold is the lowest severity that gets blocked, so a lower threshold blocks more:

Portal labelCLI and REST valueWhat it blocks
StrictLowThe most content: low, medium, and high severity
Balanced (default)MediumMedium and high severity
LenientHighOnly the most concerning, high-severity content
OffNoneNothing in this category

You can attach content safety to models and MCP servers. On an MCP server, it screens the tool inputs that agents send and the results that tools return. Every applicable policy is evaluated, and any one of them can block the call.

Note

Foundry deployments have their own Content filter, shown on the model's details page in Models. That filter runs inside Foundry, for that one deployment. The gateway policy runs before the backend, applies the same rules to models from any provider and to MCP tool traffic, and is managed by the platform team in one place. Keep both: a request has to pass each of them.

#Add content safety to the model

Pick one track. Each track produces the same policy: Balanced (Medium) for Hate, Self-harm, and Sexual, and Strict (Low) for Violence. The portal, CLI, and REST tracks put it on your model. The Bicep + azd track creates a new gateway and puts it on a new alias of the model. The stricter Violence threshold makes the test in Verify more likely to show a block, using only a mild, non-graphic prompt.

#Set the thresholds

On the Details step (Configure in some portal versions), under Parameters, choose how strictly each category is filtered:

FieldValue
HateBalanced
ViolenceStrict
Self-harmBalanced

Select Create. The policy appears in the Policies list with your model as its scope.

Checkpoint

Policies lists a Content safety policy for your model.

1

#Set the policy

Policies live in the model's properties.policies array. az aigateway model policy set-content-safety adds the content safety policy, or replaces the one that's there, and keeps every other policy on the model. --content-safety sets the threshold for all four categories, and --violence-severity overrides Violence.

az aigateway model policy set-content-safety -g "$RG" --gateway-name "$GATEWAY" --provider-name "$PROVIDER" -n "$MODEL" \
  --content-safety Medium --violence-severity Low
az aigateway model policy set-content-safety -g $RG --gateway-name $GATEWAY --provider-name $PROVIDER -n $MODEL `
  --content-safety Medium --violence-severity Low

The command prints the model's policies. Each threshold accepts None, Low, Medium, or High. To override another category, add --hate-severity, --self-harm-severity, or --sexual-severity.

2

#Confirm the policy

az aigateway model policy list -g "$RG" --gateway-name "$GATEWAY" --provider-name "$PROVIDER" -n "$MODEL" -o json
az aigateway model policy list -g $RG --gateway-name $GATEWAY --provider-name $PROVIDER -n $MODEL -o json
Checkpoint

The output contains "type": "contentSafety" with "violenceSeverity": "Low", "Medium" for the other three categories, and "scope": "resource", which the service adds to every model policy.

1

#Read the current policies

Policies live inline in the model's properties.policies array. A PATCH replaces the whole array, so always read it first and keep the policies you didn't mean to change.

Bash
SUB="$(az account show --query id -o tsv)"
URL="https://management.azure.com/subscriptions/$SUB/resourceGroups/$RG/providers/Microsoft.ApiManagement/aigateways/$GATEWAY/workspaces/default/modelProviders/$PROVIDER/models/$MODEL?api-version=2025-09-01-preview"

az rest --method get --url "$URL" --query properties.policies
2

#Replace the content safety policy and keep everything else

POLICIES="$(az rest --method get --url "$URL" | jq -c '
  [(.properties.policies // [])[] | select(.type != "contentSafety")]
  + [{"type":"contentSafety","hateSeverity":"Medium","violenceSeverity":"Low","sexualSeverity":"Medium","selfHarmSeverity":"Medium"}]')"

az rest --method patch --url "$URL" --body "{\"properties\":{\"policies\":$POLICIES}}"
$SUB = az account show --query id -o tsv
$URL = "https://management.azure.com/subscriptions/$SUB/resourceGroups/$RG/providers/Microsoft.ApiManagement/aigateways/$GATEWAY/workspaces/default/modelProviders/$PROVIDER/models/$MODEL`?api-version=2025-09-01-preview"

$current  = az rest --method get --url $URL | ConvertFrom-Json
$policies = @($current.properties.policies | Where-Object { $_ -and $_.type -ne 'contentSafety' })
$policies += [pscustomobject]@{
  type = 'contentSafety'; hateSeverity = 'Medium'; violenceSeverity = 'Low'; sexualSeverity = 'Medium'; selfHarmSeverity = 'Medium'
}

$body = @{ properties = @{ policies = $policies } } | ConvertTo-Json -Depth 10 -Compress
$body | Set-Content -Path patch.json
az rest --method patch --url $URL --body '@patch.json'
Remove-Item patch.json
Checkpoint

Running the GET again returns your other policies unchanged plus one contentSafety entry with "violenceSeverity": "Low" and "scope": "resource".

What you need: Cloud Shell or the azd tools with the aigateway extension, signed in. This track doesn't use your gateway from lab 02: azd up creates a new one, so it works on its own.

1

#Choose what to declare

A Bicep deployment sends a PUT, which replaces the whole resource. Redeclaring a model you imported in the portal risks dropping settings you didn't copy. Instead, this template adds a new alias, <model-name>-safe, that targets the same backend model and carries the content safety policy. Existing clients keep calling the original alias. Callers that you move to the new alias get screened.

The policy is one contentSafety object with a threshold for each category: hateSeverity, selfHarmSeverity, sexualSeverity, and violenceSeverity. Each accepts the API values from How it works: Low, Medium, High, or None.

#Review the templates

infra/main.bicep creates the resource group rg-<environment name> and calls the quick start's resources.bicep↗ for the gateway, the Foundry model, its default alias, and the app-first-call key. Then it calls infra/safe-alias.bicep with the four thresholds:

infra/main.bicepGitHub
// Lab 08 with azd: "azd up" creates the resource group rg-<environment name>, the quick start's gateway, Foundry
// model, default alias, and runtime API key, then a second alias for the same model with a content safety policy.
// The runtime API key is never an output.
targetScope = 'subscription'

@description('azd environment name. The resource group is rg-<environmentName>.')
@minLength(1)
@maxLength(60)
param environmentName string

@description('Region for every resource. Pick one where AI Gateway and the lab\'s Foundry models are available. List them with az provider show --namespace Microsoft.ApiManagement (Setup guide, Find the available regions).')
@metadata({ azd: { type: 'location' } })
param location string

@description('Threshold for Hate. azd reads it from CONTENT_SAFETY_HATE.')
@allowed([ 'Low', 'Medium', 'High', 'None' ])
param hateSeverity string = 'Medium'

@description('Threshold for Self-harm. azd reads it from CONTENT_SAFETY_SELF_HARM.')
@allowed([ 'Low', 'Medium', 'High', 'None' ])
param selfHarmSeverity string = 'Medium'

@description('Threshold for Sexual. azd reads it from CONTENT_SAFETY_SEXUAL.')
@allowed([ 'Low', 'Medium', 'High', 'None' ])
param sexualSeverity string = 'Medium'

@description('Threshold for Violence. azd reads it from CONTENT_SAFETY_VIOLENCE.')
@allowed([ 'Low', 'Medium', 'High', 'None' ])
param violenceSeverity string = 'Low'

var suffix = take(uniqueString(subscription().id, environmentName, location), 6)
var tags = { 'azd-env-name': environmentName }

resource rg 'Microsoft.Resources/resourceGroups@2024-03-01' = {
  name: 'rg-${environmentName}'
  location: location
  tags: tags
}

// The quick start's template: a gateway, a Foundry model behind the default alias, and the app-first-call key.
module base '../../quickstart/infra/resources.bicep' = {
  name: 'aigw-base'
  scope: rg
  params: {
    location: location
    tags: tags
    gatewayName: 'aigw-${suffix}'
    foundryName: 'aigw${suffix}'
  }
}

module safeAlias 'safe-alias.bicep' = {
  name: 'aigw-safe-alias'
  scope: rg
  params: {
    gatewayName: base.outputs.gatewayName
    providerName: base.outputs.providerName
    modelName: base.outputs.modelName
    hateSeverity: hateSeverity
    selfHarmSeverity: selfHarmSeverity
    sexualSeverity: sexualSeverity
    violenceSeverity: violenceSeverity
  }
}

output AZURE_RESOURCE_GROUP string = rg.name
output AI_GATEWAY_NAME string = base.outputs.gatewayName
output AI_GATEWAY_ID string = base.outputs.gatewayId
output AI_GATEWAY_URL string = base.outputs.gatewayUrl
output AI_GATEWAY_PROVIDER string = base.outputs.providerName
output AI_GATEWAY_BACKEND_MODEL string = base.outputs.modelName
output AI_GATEWAY_MODEL string = safeAlias.outputs.aliasName
output FOUNDRY_ACCOUNT_NAME string = base.outputs.foundryName

infra/safe-alias.bicep adds the alias. It only references the gateway, the provider, and the model, so you can also deploy it on its own to a gateway you already have, with az deployment group create:

infra/safe-alias.bicepGitHub
// Publishes an alias with a content safety policy for an existing AI Gateway model. main.bicep calls it after the
// quick start's template, and you can also deploy it on its own to a gateway you already have. The alias points at
// the same backend model as your default alias, but screens every prompt and response it serves, so you can test
// thresholds without changing what other callers get.

@description('Name of the existing AI Gateway (Microsoft.ApiManagement/aigateways).')
param gatewayName string

@description('Name of the existing model provider in the gateway, for example foundry-models.')
param providerName string

@description('Name of the existing backend model registration under the provider.')
param modelName string

@description('Callable alias to create. Clients send this value in the request "model" field.')
param aliasName string = '${modelName}-safe'

// The lowest severity that gets blocked: Low (Strict), Medium (Balanced), High (Lenient), or None (Off).
@description('Threshold for the Hate category.')
@allowed([ 'Low', 'Medium', 'High', 'None' ])
param hateSeverity string = 'Medium'

@description('Threshold for the Self-harm category.')
@allowed([ 'Low', 'Medium', 'High', 'None' ])
param selfHarmSeverity string = 'Medium'

@description('Threshold for the Sexual category.')
@allowed([ 'Low', 'Medium', 'High', 'None' ])
param sexualSeverity string = 'Medium'

@description('Threshold for the Violence category.')
@allowed([ 'Low', 'Medium', 'High', 'None' ])
param violenceSeverity string = 'Low'

#disable-next-line BCP081
resource gateway 'Microsoft.ApiManagement/aigateways@2025-09-01-preview' existing = {
  name: gatewayName
}

#disable-next-line BCP081
resource workspace 'Microsoft.ApiManagement/aigateways/workspaces@2025-09-01-preview' existing = {
  parent: gateway
  name: 'default'
}

#disable-next-line BCP081
resource provider 'Microsoft.ApiManagement/aigateways/workspaces/modelProviders@2025-09-01-preview' existing = {
  parent: workspace
  name: providerName
}

#disable-next-line BCP081
resource model 'Microsoft.ApiManagement/aigateways/workspaces/modelProviders/models@2025-09-01-preview' existing = {
  parent: provider
  name: modelName
}

#disable-next-line BCP081
resource safeAlias 'Microsoft.ApiManagement/aigateways/workspaces/aliases@2025-09-01-preview' = {
  parent: workspace
  name: aliasName
  properties: {
    aliasName: aliasName
    backendModels: [
      { resourceId: model.id }
    ]
    policies: [
      {
        type: 'contentSafety'
        hateSeverity: hateSeverity
        selfHarmSeverity: selfHarmSeverity
        sexualSeverity: sexualSeverity
        violenceSeverity: violenceSeverity
      }
    ]
  }
}

output aliasName string = safeAlias.name
output chatCompletionsUrl string = 'https://${gateway.properties.frontend.defaultHostname}/default/models/openai/v1/chat/completions'

#Change the thresholds

The parameters come from azd environment values, with the defaults in infra/main.parameters.json: CONTENT_SAFETY_HATE, CONTENT_SAFETY_SELF_HARM, CONTENT_SAFETY_SEXUAL, and CONTENT_SAFETY_VIOLENCE. Change one with azd env set and run azd provision: only the alias changes. Verify relaxes Violence this way.

#Verify

Test the policy with benign prompts only. You don't need harmful content to see how the gateway behaves, and you should never write it to test a filter.

1

#Run the test prompts

From the lab folder, run the script for your shell. It sends two prompts: a neutral question, and a request for a short, non-graphic scene from a historical novel. It prints the status and the start of the response or the error for each one.

./infra/test-content-safety.sh "$AI_GATEWAY_MODEL"
./infra/test-content-safety.ps1 -Model $env:AI_GATEWAY_MODEL

On GitHub, open test-content-safety.sh↗ or test-content-safety.ps1↗.

Example output:

Text
Prompt    Status  Finish reason   Response or error
neutral   200     stop            Teams put an API gateway in front of AI models to centralize access con
fiction   400     -               <the gateway's content safety error message>

The neutral prompt returns 200. The fiction prompt can go either way, and your results will vary: Content Safety rates both the prompt and the model's response, and a mild battle scene sits close to the Strict Violence threshold. If it returns 400, the gateway blocked it and the error message says why. If it returns 200, the content was rated below the threshold.

Important

If the fiction prompt passes, don't make it more graphic to force a block. The point of this test is to understand thresholds with safe input, not to probe the filter. Use Monitoring and real, representative traffic in a test environment to tune thresholds.

2

#Relax one category

Set Violence back to Balanced (Medium) with the track you used, then run the script again. For example, from the command line, set all four categories to Medium. The other three already are, so only Violence changes, and the command keeps every other policy on the model:

az aigateway model policy set-content-safety -g "$RG" --gateway-name "$GATEWAY" --provider-name "$PROVIDER" -n "$MODEL" \
  --content-safety Medium
az aigateway model policy set-content-safety -g $RG --gateway-name $GATEWAY --provider-name $PROVIDER -n $MODEL `
  --content-safety Medium

On the Bicep + azd track, set the environment value and provision again instead:

azd env set CONTENT_SAFETY_VIOLENCE Medium
azd provision
azd env set CONTENT_SAFETY_VIOLENCE Medium
azd provision

A prompt that Strict blocked is more likely to pass at Balanced. Prompts that passed before still pass.

3

#Check the Foundry content filter

Open Models, select your model, and find Content filter on its details page. That is the Foundry deployment's own filter, separate from the gateway policy. When Foundry's filter acts instead of the gateway, the error or the finish_reason comes from the backend, and it can mention content_filter.

4

#Find blocked calls in Monitoring

If you configured Application Insights in Monitor usage, cost, and traces, open Monitoring and look for 400 outcomes on your model. Review them before and after every threshold change.

Checkpoint

The neutral prompt returned 200, you saw how the borderline prompt fared at Strict and at Balanced, and you can tell a gateway block (400 from the content safety policy) from a Foundry content filter result.

#Go further

  • Screen tool traffic. Add a Content safety policy to the learn MCP server from Federate MCP tools behind one endpoint. In the wizard, pick the MCP server on the Scope step. With REST, use the same contentSafety object on .../workspaces/default/toolServers/learn.
  • Make it the default. Apply Balanced content safety to every model and MCP server, including future ones, in Set gateway-wide policy baselines.
  • Tune per category. Start every category at Balanced, tighten the ones that matter most for your audience, and turn a category Off only with a documented exception.

#Clean up
