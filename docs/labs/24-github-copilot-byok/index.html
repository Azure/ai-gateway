Use your gateway's models in GitHub Copilot

Point GitHub Copilot in VS Code, the Copilot CLI, the Copilot SDK, and the GitHub Copilot app at gpt-6-astra published by your gateway, so every coding agent request uses your key, your token limits, and your monitoring.

Intermediate 25 min PortalCLIBicepCode
Source Edit

What you'll do

  • Publish gpt-6-astra through the gateway with a per-caller token limit and a runtime key for GitHub Copilot
  • Add the gateway as a custom endpoint in VS Code and run agent mode on gpt-6-astra
  • Run the Copilot CLI against the gateway with provider environment variables
  • Start a Copilot SDK session in Python or TypeScript that sends every model call to the gateway
  • Add the gateway as a model provider in the GitHub Copilot app
  • Track Copilot usage by key in Monitoring and cut off access by suspending the key

Before you start

  • 02Publish a Foundry model and make your first call

Tracks: Portal, Azure CLI, Bicep / azd, Code

GitHub Copilot can run on a model that you bring yourself: give it an OpenAI-compatible endpoint and a key, and it sends every chat and agent request there. Make that endpoint your gateway, and Copilot's traffic gets the same controls as your apps: a key that you can suspend, a token limit for each caller, and usage in Monitoring. Copilot never sees a Foundry credential, because the gateway calls Foundry with its managed identity. In this lab you publish gpt-6-astra for Copilot, then connect four Copilot surfaces to it: VS Code, the Copilot CLI, the Copilot SDK, and the GitHub Copilot app.

#Before you begin

  • Complete Publish a Foundry model and make your first call. You need a gateway with a Foundry provider, and permission to change it, for example Contributor on the resource group.

  • Quota for gpt-6-astra (version 2026-09-03) in the Foundry account behind your gateway. This lab deploys it with 100,000 tokens per minute (TPM), because coding agents send large prompts. Model inference is billed per use.

  • For the CLI and IaC tracks: the Azure CLI↗ 2.75 or later, signed in with az login, plus jq for the Bash snippets.

  • At least one Copilot surface. You don't need all four:

    SurfaceVersion testedNeeds
    VS Code↗ with GitHub Copilot1.143Nothing else. Chat and agent mode work with your own model without a GitHub sign-in.
    GitHub Copilot CLI↗1.0.103Nothing else. A GitHub sign-in is optional with your own model.
    GitHub Copilot SDK↗1.0.26 (TypeScript), 1.0.22 (Python)Node.js 22.18 or later, or Python 3.11 or later, and a clone of this repository.
    GitHub Copilot app↗Public previewA GitHub sign-in. A Copilot plan isn't required for your own models.
Important

On Copilot Business or Copilot Enterprise, an administrator must allow custom models before VS Code and the Copilot app offer them. See Enable custom models for your enterprise↗.

#How it works

Bring your own key (BYOK) replaces the model endpoint behind Copilot. Copilot still runs its agent loop on your machine: it reads files, plans, calls tools, and asks before it edits or runs commands. Each model request goes to the gateway instead of GitHub's model service. Every surface needs the same four settings:

SettingValueWhy
Base URLhttps://<gateway-host>/default/models/openai/v1The gateway's OpenAI-compatible endpoint. VS Code wants the full URL, with /responses at the end.
Modelgpt-6-astraThe alias. Copilot sends it in the request's model field, and the gateway routes by alias. When the alias has the model's well-known name, Copilot also applies the prompts and token sizes it uses for that model.
APIResponsesCopilot recommends the Responses API for GPT-5 and later models. The gateway serves both /responses and /chat/completions for this model.
API keyThe github-copilot runtime keyCopilot sends it as Authorization: Bearer. The gateway also accepts an api-key header, but not both in one request.

Two things differ from an app that calls the gateway:

  • You add the model by hand. Clients often call GET /models to discover what an endpoint offers, but the gateway doesn't serve a model list. Each surface lets you type the model name instead.
  • Agents send big requests. Every request carries Copilot's system prompt, its tool definitions, and the conversation so far. In testing, a one-line question from the Copilot CLI used 14,000 to 38,000 input tokens. That's why this lab gives each caller 100,000 tokens per minute, and why one key per tool or per developer makes usage easy to read.

#Review the template

The template deploys gpt-6-astra in your Foundry account, then reuses lab 02's template to register it under your provider, publish the gpt-6-astra alias with the token limit, and create the github-copilot key.

infra/main.bicepGitHub
// Publishes gpt-6-astra through an existing AI Gateway so GitHub Copilot can use it as a bring-your-own-key model.
// Adds a gpt-6-astra deployment to the Foundry account the gateway already uses, then reuses the
// first-model-call lab's main.bicep to register the deployment, publish the gpt-6-astra alias with a
// per-caller token limit, and create the github-copilot runtime API key. The key value is never an output.
targetScope = 'resourceGroup'

@description('Name of the existing AI Gateway (Microsoft.ApiManagement/aigateways) in this resource group.')
param gatewayName string

@description('Resource ID of the Foundry (Azure AI Services) account that the gateway uses. It can be in another resource group.')
param foundryAccountId string

@description('Model to deploy and publish. The deployment and the alias both use this name.')
param modelName string = 'gpt-6-astra'

@description('Version of the model to deploy.')
param modelVersion string = '2026-09-03'

@description('Deployment SKU. Use DataZoneStandard if your GlobalStandard quota for the model is used up.')
@allowed([
  'GlobalStandard'
  'DataZoneStandard'
])
param skuName string = 'GlobalStandard'

@description('Deployment capacity in thousands of tokens per minute. Coding agents send large prompts, so give them room.')
@minValue(1)
param capacity int = 100

@description('Tokens per minute that each caller identity can use on the model through the gateway.')
@minValue(1000)
param tokensPerMinute int = 100000

@description('Name of the Foundry provider in the gateway. Use the name from lab 02 so the deployment registers under the same provider.')
param providerName string = 'foundry-models'

@description('Name of the runtime API key that GitHub Copilot uses.')
param apiKeyName string = 'github-copilot'

var foundrySubscriptionId = split(foundryAccountId, '/')[2]
var foundryResourceGroup = split(foundryAccountId, '/')[4]

module deployment 'deployment.bicep' = {
  name: take('deploy-${modelName}', 64)
  scope: resourceGroup(foundrySubscriptionId, foundryResourceGroup)
  params: {
    accountName: last(split(foundryAccountId, '/'))
    modelName: modelName
    modelVersion: modelVersion
    skuName: skuName
    capacity: capacity
  }
}

module publish '../../02-first-model-call/infra/main.bicep' = {
  name: take('publish-${modelName}', 64)
  params: {
    gatewayName: gatewayName
    foundryAccountId: foundryAccountId
    deploymentName: deployment.outputs.deploymentName
    modelVersion: modelVersion
    providerName: providerName
    aliasName: modelName
    apiKeyName: apiKeyName
    apiKeyDisplayName: 'GitHub Copilot'
    tokensPerMinute: tokensPerMinute
  }
}

output aliasName string = publish.outputs.aliasName
output apiKeyName string = publish.outputs.apiKeyName
output modelEndpoint string = publish.outputs.modelEndpoint

#Add gpt-6-astra to the group

VS Code opens chatLanguageModels.json with the new group. The gateway has no model list to discover, so add the model to models yourself. Print the URL to paste:

Then make the group look like this. Keep the apiKey value that VS Code wrote: it points at the secret, not the key itself.

chatLanguageModels.json
[
  {
    "name": "AI Gateway",
    "vendor": "customendpoint",
    "apiKey": "${input:chat.lm.secret.<id>}",
    "apiType": "responses",
    "models": [
      {
        "id": "gpt-6-astra",
        "name": "GPT-6 Astra (AI Gateway)",
        "url": "https://<gateway-host>/default/models/openai/v1/responses",
        "toolCalling": true,
        "vision": true,
        "maxInputTokens": 128000,
        "maxOutputTokens": 16000
      }
    ]
  }
]
FieldWhat it does
idThe alias, sent as model in each request.
nameThe label in the model picker. Copilot already offers a built-in GPT-6 Astra, so a distinct name tells them apart.
urlThe full Responses URL on your gateway.
toolCallingTells VS Code that the model can call tools, which agent mode needs.
maxInputTokens, maxOutputTokensHow much context VS Code sends and how long a reply it asks for.

Save the file.

#Connect the Copilot SDK

The GitHub Copilot SDK↗ runs the same agent as the CLI inside your own app. Pass a provider when you create a session, and the session sends its model calls to the gateway. The SDK packages bring the Copilot runtime with them, so you don't need to install the CLI. No GitHub sign-in is needed.

1

#Review the samples

The samples read AI_GATEWAY_URL, AI_GATEWAY_API_KEY, and, optionally, AI_GATEWAY_MODEL from the environment, then ask the agent which model it is and to list the files in the current folder. approveAll lets the agent run tools without asking, which suits a sample. In an app, decide which tools to allow in onPermissionRequest.

infra/copilot-sdk.tsGitHub
// Runs a GitHub Copilot SDK agent session on gpt-6-astra published by Azure AI Gateway (bring your own key).
// Set AI_GATEWAY_URL and AI_GATEWAY_API_KEY first. No GitHub sign-in is needed: every model call goes to the gateway.
import { CopilotClient, approveAll } from "@github/copilot-sdk";

const gatewayUrl = process.env.AI_GATEWAY_URL?.replace(/\/$/, "");
const apiKey = process.env.AI_GATEWAY_API_KEY;
const model = process.env.AI_GATEWAY_MODEL ?? "gpt-6-astra";
if (!gatewayUrl || !apiKey) {
  throw new Error("Set AI_GATEWAY_URL and AI_GATEWAY_API_KEY first.");
}

const client = new CopilotClient();
try {
  const session = await client.createSession({
    model,
    provider: {
      type: "openai",
      baseUrl: `${gatewayUrl}/default/models/openai/v1`,
      apiKey,
      wireApi: "responses",
    },
    onPermissionRequest: approveAll,
  });

  const prompt = process.argv.slice(2).join(" ") || "Which model are you? Then list the files in this folder.";
  const reply = await session.sendAndWait({ prompt });
  console.log(reply?.data.content);
  await session.disconnect();
} finally {
  await client.stop();
}
infra/copilot_sdk.pyGitHub
"""Runs a GitHub Copilot SDK agent session on gpt-6-astra published by Azure AI Gateway (bring your own key).

Set AI_GATEWAY_URL and AI_GATEWAY_API_KEY first. No GitHub sign-in is needed: every model call goes to the gateway.
"""

import asyncio
import os
import sys

from copilot import CopilotClient, PermissionHandler


async def main() -> None:
    gateway_url = os.environ["AI_GATEWAY_URL"].rstrip("/")
    api_key = os.environ["AI_GATEWAY_API_KEY"]
    model = os.environ.get("AI_GATEWAY_MODEL", "gpt-6-astra")

    client = CopilotClient()
    await client.start()
    try:
        session = await client.create_session(
            model=model,
            provider={
                "type": "openai",
                "base_url": f"{gateway_url}/default/models/openai/v1",
                "api_key": api_key,
                "wire_api": "responses",
            },
            on_permission_request=PermissionHandler.approve_all,
        )
        prompt = " ".join(sys.argv[1:]) or "Which model are you? Then list the files in this folder."
        reply = await session.send_and_wait(prompt, timeout=180)
        print(reply.data.content if reply else "(no reply)")
        await session.disconnect()
    finally:
        await client.stop()


if __name__ == "__main__":
    asyncio.run(main())

#Verify

Every surface you connected sends its requests with the github-copilot key. Use it to see the traffic and to switch Copilot off.

1

#See Copilot's usage by key

If you set up Monitoring in Monitor usage, cost, and traces, open Monitoring›Models in the AI Gateway portal. gpt-6-astra lists the calls and the input and output tokens from your Copilot sessions, and Model usage by caller identity shows them under the github-copilot key. The input tokens are far higher than the output tokens: that's the context that the agent sends with every request.

#Cut Copilot off by suspending the key

Suspend the key, then run the CLI again. The settings are unchanged, but the gateway now rejects the key:

az rest --method patch --url "$GW/apiKeys/$KEY_NAME?$API" \
  --body '{"properties":{"state":"suspended"}}' --query properties.state -o tsv
sleep 30
cd ~/contoso-calc && copilot -p "Say hi"
'{"properties":{"state":"suspended"}}' | Set-Content keystate.json
az rest --method patch --url "$GW/apiKeys/$KEY_NAME`?$API" --body "@keystate.json" --query properties.state -o tsv
Start-Sleep 30
Set-Location ~/contoso-calc; copilot -p "Say hi"

Expected output, after the CLI retries twice:

Text
suspended

Request failed due to a transient API error. Retrying...

VS Code, the SDK, and the app get the same 401. One key change cuts off every Copilot surface that uses the key, on every machine, without touching their settings.

#Go further

  • Sign in with Microsoft Entra ID instead of a key. If the gateway accepts Entra tokens, as in Authorize callers with Microsoft Entra ID, set COPILOT_PROVIDER_BEARER_TOKEN for the CLI, or pass a bearer token in the SDK's provider settings. Tokens expire, so refresh them for long sessions.
  • Fetch the key when it's needed. COPILOT_PROVIDER_API_KEY_COMMAND runs a command for each request and uses its output as the key, for example az keyvault secret show --vault-name <vault> -n github-copilot --query value -o tsv. The key then never sits in your shell profile, and a rotated key takes effect right away.
  • Give each developer or tool its own key. Keys are cheap, and per-key usage in Monitoring shows who uses how much. Rotate or revoke them with Manage runtime API keys.
  • Route Copilot across models. Point the gpt-6-astra alias at several backend models, as in Route by priority and weight. VS Code chains Responses API turns with previous_response_id by default; if the backends don't share state, set "statefulResponses": false on the model in chatLanguageModels.json.
  • Offer more models. Publish more aliases and add each one to models in VS Code, or to the provider in the app. For the CLI, set COPILOT_MODEL to a different alias. If an alias doesn't have a well-known model name, set COPILOT_PROVIDER_MODEL_ID to the model it serves, so the CLI picks the right prompts and token sizes.

#Clean up

Remove the gateway from each Copilot surface you configured:

  • VS Code: delete the AI Gateway group from chatLanguageModels.json, or remove it in the Language Models editor.
  • Copilot CLI: close the terminal, or run unset COPILOT_PROVIDER_BASE_URL COPILOT_PROVIDER_WIRE_API COPILOT_PROVIDER_API_KEY COPILOT_MODEL (Bash) or Remove-Item Env:COPILOT_PROVIDER_*, Env:COPILOT_MODEL (PowerShell).
  • GitHub Copilot app: remove the AI Gateway provider in Model providers.

Then delete the key. In the portal, delete github-copilot in Access›Keys. From a shell:

az rest --method delete --url "$GW/apiKeys/$KEY_NAME?$API"
rm -rf ~/contoso-calc
az rest --method delete --url "$GW/apiKeys/$KEY_NAME`?$API"
Remove-Item -Recurse -Force ~/contoso-calc

If you don't need gpt-6-astra any more, also delete the alias, the backend model, and the Foundry deployment. In the portal, delete them in Models and in Foundry. From a shell:

az rest --method delete --url "$WS/aliases/$MODEL?$API"
az rest --method delete --url "$WS/modelProviders/$PROVIDER/models/$MODEL?$API"
az cognitiveservices account deployment delete -g "$FOUNDRY_RG" -n "$FOUNDRY_ACCOUNT" --deployment-name "$MODEL"
az rest --method delete --url "$WS/aliases/$MODEL`?$API"
az rest --method delete --url "$WS/modelProviders/$PROVIDER/models/$MODEL`?$API"
az cognitiveservices account deployment delete -g $FOUNDRY_RG -n $FOUNDRY_ACCOUNT --deployment-name $MODEL

If you imported the model in the portal, also delete its <foundry-account-name>/gpt-6-astra alias. Keep the gateway and the provider: the other labs reuse them.

#Troubleshooting

SymptomCauseFix
HTTP 401 or "Authentication failed with provider"The key is wrong, suspended, or deleted, or the new key isn't active yetCheck the key's state in Access›Keys, wait a minute after you create it, and paste it again.
400 on every request from a custom clientThe request sends both Authorization and api-keySend one of them. Copilot sends Authorization: Bearer only.
404, or a "model not found" errorThe model name isn't an alias on the gateway, for example the portal import's <foundry-account-name>/gpt-6-astraPublish the gpt-6-astra alias, or set the model ID to the alias that exists.
The model doesn't appear in VS Code or the appThe gateway has no /models list to discover, or VS Code hasn't reloaded the fileAdd gpt-6-astra by hand, then run Developer: Reload Window in VS Code.
The model is missing from the picker in Agent modetoolCalling is missing or falseSet "toolCalling": true on the model.
VS Code or the app doesn't offer your own models at allYour Copilot Business or Enterprise organization hasn't allowed custom modelsAsk an administrator to enable them.
Replies are empty or cut off, or tool calls failThe surface uses Chat Completions with a reasoning modelSet the API to Responses: apiType in VS Code, COPILOT_PROVIDER_WIRE_API=responses for the CLI, wireApi in the SDK.
429 Too Many RequestsCopilot used the key's 100,000 tokens for this minuteWait for the Retry-After interval, or raise the token limit.
