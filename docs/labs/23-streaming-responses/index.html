Stream responses and count every token

Stream Chat Completions and Responses API replies through the gateway, read the server-sent events that your client receives, and prove that a token limit counts streamed tokens even when the client never asks for usage.

Intermediate 20 min CLICodePortalBicep Updated Oct 28, 2026
Notebook Source Edit

What you'll do

  • Read the server-sent events that a streamed Chat Completions response returns through the gateway
  • Get token usage at the end of a stream with include_usage, and skip chunks that have no choices
  • Stream the Responses API and read usage from the response.completed event
  • Prove that a token limit counts streamed tokens whether or not the client asks for usage

Before you start

  • 02Publish a Foundry model and make your first call

Tracks: Azure CLI, Code, Portal, Bicep + azd

Chat apps and agents stream their replies: the model sends text a few tokens at a time, so people start reading after a second or two instead of waiting for the whole answer. Streaming used to be a blind spot for governance, because a streamed Chat Completions response only reports token usage when the client asks for it. In this lab you stream through the gateway with curl, PowerShell, and the OpenAI SDKs, read every event the client receives, and then prove that a token limit still counts every streamed token.

#How it works

Add "stream": true to a Chat Completions request and the gateway answers with Content-Type: text/event-stream. The body is a series of server-sent events (SSE): each one is a data: line with a JSON chunk, followed by a blank line. The gateway passes each chunk on as the model produces it, and the response carries x-accel-buffering: no, which tells proxies such as NGINX not to hold it back.

This is what a streamed reply from a Foundry model looks like through the gateway:

ChunkchoicesWhat it carries
Prompt filter resultsEmpty []Content safety results for the prompt. id and model are empty strings.
RoleOne choicedelta.role is assistant and delta.content is an empty string.
Content deltasOne choicedelta.content holds the next few characters of the reply. usage is null.
FinishOne choicefinish_reason is stop, or length when the reply hits max_completion_tokens.
UsageEmpty []usage with prompt_tokens, completion_tokens, and total_tokens. Sent when the client sets stream_options.include_usage.
data: [DONE]Not JSONThe end of the stream. Stop reading.

Two chunks have an empty choices array, so code that reads choices[0] on every chunk crashes on the first one.

Where the gateway counts tokens. A token limit or cost limit is checked before the gateway forwards the request. When a counter is exhausted, the client gets an ordinary JSON error, such as 429 with Retry-After, and no stream starts. Once a stream starts, it runs to the end, even if it takes the counter past the limit; the next request is throttled. While the stream flows, the gateway records its token usage for token limits, cost limits, and Monitoring.

Usage without include_usage. Since the September 24, 2026 release↗, the gateway makes sure it has a usage record for every streamed Chat Completions response, even when the client doesn't set stream_options.include_usage, so the counters stay accurate. The release notes ask clients that parse the events themselves to accept a usage-only chunk before [DONE], even when they didn't ask for one. In our test run in October 2026, a client that didn't set include_usage received no usage chunk, yet the token limit counted its tokens exactly as it did for a client that asked. So write your client to work either way: skip chunks with an empty choices array, and take usage from whichever chunk carries it.

The Responses API streams typed events instead: each data: line follows an event: line, and the last event, response.completed, always carries the usage.

#Stream with the script

The script prints the reply as it streams, then counts the events, measures the time to the first token, and shows the usage chunk if the stream had one.

infra/stream-chat.shGitHub
#!/usr/bin/env bash
# Streams a Chat Completions response through AI Gateway, prints the reply as it arrives, then prints how many
# server-sent events came back, how many had an empty choices array, the time to the first token, and the usage
# chunk if the stream ended with one.
#
# Usage:
#   export AI_GATEWAY_URL="https://<gateway>.eastus2-01.ai.gateway.azure.com"
#   export AI_GATEWAY_MODEL="<model-alias>"
#   export AI_GATEWAY_API_KEY="..."      # never commit this value
#   ./stream-chat.sh [--usage] [--raw] ["Your prompt"]
#
#   --usage  sets stream_options.include_usage to true, so the stream ends with a usage chunk
#   --raw    prints every server-sent event line instead of the reply text
# Requires curl and jq 1.6 or later.
set -euo pipefail

USAGE=false
RAW=false
while [[ "${1:-}" == --* ]]; do
  case "$1" in
    --usage) USAGE=true ;;
    --raw) RAW=true ;;
    *) echo "Unknown option: $1" >&2; exit 2 ;;
  esac
  shift
done
PROMPT="${1:-Explain in three short sentences why streaming makes chat apps feel faster.}"
: "${AI_GATEWAY_URL:?Set AI_GATEWAY_URL to https://<gateway>.eastus2-01.ai.gateway.azure.com}"
: "${AI_GATEWAY_MODEL:?Set AI_GATEWAY_MODEL to the callable model alias}"
: "${AI_GATEWAY_API_KEY:?Set AI_GATEWAY_API_KEY to a runtime key from Access > Keys}"

# reasoning_effort none spends the budget on the reply instead of hidden reasoning, so the first token arrives sooner.
BODY=$(jq -n --arg m "$AI_GATEWAY_MODEL" --arg p "$PROMPT" --argjson usage "$USAGE" '
  {model: $m, stream: true, max_completion_tokens: 300, reasoning_effort: "none",
   messages: [{role: "user", content: $p}]}
  + (if $usage then {stream_options: {include_usage: true}} else {} end)')

headers=$(mktemp)
trap 'rm -f "$headers"' EXIT

# -N turns off curl's output buffering. jq reads the raw lines as they arrive and keeps running totals.
curl -sSN -D "$headers" "${AI_GATEWAY_URL%/}/default/models/openai/v1/chat/completions" \
  -H "api-key: $AI_GATEWAY_API_KEY" -H "Content-Type: application/json" -d "$BODY" \
| jq -nRrj --unbuffered --argjson raw "$RAW" '
    def secs: (. * 100 | round) / 100 | tostring + " s";
    def summary:
      "\n\n"
      + (if .events == 0 then "Response body       \(.other)\n"
         else "Events              \(.events) (\(.empty) with an empty choices array)\n"
            + "First token         \(if .ttft then (.ttft | secs) else "-" end)\n"
            + "Usage chunk         "
            + (if .usage then "prompt \(.usage.prompt_tokens), completion \(.usage.completion_tokens), total \(.usage.total_tokens)"
               else "none: run again with --usage to ask for one" end) + "\n"
         end);
    foreach (inputs, null) as $line (
      {t0: now, events: 0, empty: 0, ttft: null, usage: null, other: "", out: ""};
      .out = ""
      | if $line == null then .end = true
        elif ($line | startswith("data: ")) then
          ($line[6:]) as $data
          | if $data == "[DONE]" then .out = (if $raw then $line + "\n" else "" end)
            else ($data | fromjson) as $chunk
              | ([$chunk.choices[]?.delta.content // empty] | join("")) as $text
              | .events += 1
              | .empty += (if ($chunk.choices // []) == [] then 1 else 0 end)
              | .usage = ($chunk.usage // .usage)
              | .ttft = (if .ttft == null and $text != "" then now - .t0 else .ttft end)
              | .out = (if $raw then $line + "\n" else $text end)
            end
        else .other += $line
        end;
      if .end then summary else .out end)'

status=$(awk 'toupper($1) ~ /^HTTP/ {code=$2} END {print code}' "$headers")
type=$(awk -F': ' 'tolower($1)=="content-type" {gsub("\r","",$2); print $2}' "$headers")
served=$(awk -F': ' 'tolower($1)=="x-ms-served-model" {gsub("\r","",$2); print $2}' "$headers")
retry=$(awk -F': ' 'tolower($1)=="retry-after" {gsub("\r","",$2); print $2}' "$headers")
printf 'HTTP status         %s\n' "$status"
printf 'Content-Type        %s\n' "${type:--}"
printf 'Served by           %s\n' "${served:--}"
[[ -n "$retry" ]] && printf 'Retry-After         %s\n' "$retry"
[[ "$status" == 200 ]]
# Stream a reply, then print the event count, the time to the first token, the usage chunk, and the headers
echo "🤖 Reply from the $AI_GATEWAY_MODEL alias, as it streams:"
./infra/stream-chat.sh
# Stream a reply, then print the event count, the time to the first token, the usage chunk, and the headers
Write-Host "🤖 Reply from the $env:AI_GATEWAY_MODEL alias, as it streams:"
./infra/stream-chat.ps1

#Stream the Responses API

The Responses API names every event. List the event types in order, then read the usage from response.completed:

# Stream a Responses API reply into a file, so that you can count its events
curl -sSN "${AI_GATEWAY_URL%/}/default/models/openai/v1/responses" \
  -H "api-key: $AI_GATEWAY_API_KEY" -H "Content-Type: application/json" \
  -d "{\"model\":\"$AI_GATEWAY_MODEL\",\"stream\":true,\"input\":\"Say hello in five words.\"}" > events.txt &&
  echo "🤖 Stream received from the $AI_GATEWAY_MODEL alias"

# Count each run of the same event type, in order
echo "📊 Event types, in order:"
grep '^event:' events.txt | uniq -c

# Read the usage from the response.completed event, then delete the file
echo "📊 Usage from response.completed:"
sed -n 's/^data: {/{/p' events.txt | jq -c 'select(.type == "response.completed") | .response.usage'
rm events.txt
# Build a streamed Responses API request
$body = @{ model = $env:AI_GATEWAY_MODEL; stream = $true; input = "Say hello in five words." } | ConvertTo-Json

# Send it: Invoke-WebRequest waits for the whole stream, which is fine here because you only count its events
$r = Invoke-WebRequest -Method Post -Uri "$($env:AI_GATEWAY_URL.TrimEnd('/'))/default/models/openai/v1/responses" `
  -Headers @{ "api-key" = $env:AI_GATEWAY_API_KEY } -ContentType "application/json" -Body $body
if ($?) { Write-Host "🤖 Stream received from the $env:AI_GATEWAY_MODEL alias" }

# Count each run of the same event type, in order, the way uniq -c does
Write-Host "📊 Event types, in order:"
$lines = $r.Content -split "`n"
$prev = $null; $n = 0
foreach ($e in $lines -match '^event:') { if ($e -eq $prev) { $n++ } else { if ($prev) { '{0,4} {1}' -f $n, $prev }; $prev = $e; $n = 1 } }
'{0,4} {1}' -f $n, $prev

# Read the usage from the response.completed event
Write-Host "📊 Usage from response.completed:"
($lines -match '^data: \{' | ForEach-Object { $_.Substring(6) | ConvertFrom-Json } |
  Where-Object type -eq 'response.completed').response.usage | ConvertTo-Json -Compress

#Stream from code

Pass stream=True and iterate over the chunks. Skip chunks without choices, and keep the usage from the chunk that has it.

stream = client.chat.completions.create(
    model=model,
    messages=[{"role": "user", "content": "Explain in two sentences why streaming makes chat apps feel faster."}],
    stream=True,
    stream_options={"include_usage": True},
)
usage = None
for chunk in stream:
    if chunk.usage:
        usage = chunk.usage
    if not chunk.choices:  # the prompt filter chunk and the usage chunk
        continue
    print(chunk.choices[0].delta.content or "", end="", flush=True)
print(f"\nTokens used: {usage.total_tokens if usage else 'no usage chunk'}")
const stream = await client.chat.completions.create({
  model,
  messages: [{ role: "user", content: "Explain in two sentences why streaming makes chat apps feel faster." }],
  stream: true,
  stream_options: { include_usage: true },
});
let usage: OpenAI.CompletionUsage | undefined;
for await (const chunk of stream) {
  if (chunk.usage) usage = chunk.usage;
  // choices[0] is undefined on the prompt filter chunk and the usage chunk.
  process.stdout.write(chunk.choices[0]?.delta?.content ?? "");
}
console.log(`\nTokens used: ${usage?.total_tokens ?? "no usage chunk"}`);

  --description "Streaming lab: 1,000 tokens per minute for each caller" \
  --backend-model resource-id="$GATEWAY_ID/workspaces/default/modelProviders/$PROVIDER/models/$MODEL" \
  --policies '[{"type": "tokenLimit", "count": 1000, "period": "minute", "counterKey": ["identity"]}]' \
  --only-show-errors --query "{alias:name, policies:properties.policies}" -o json
# Write the token limit of 1,000 tokens per minute for each caller identity to a file, so that PowerShell
# passes the JSON to az unchanged
ConvertTo-Json -Depth 10 -Compress -InputObject @(
  @{ type = "tokenLimit"; count = 1000; period = "minute"; counterKey = @("identity") }
) | Set-Content policies.json

# Create or update the streaming alias for the same backend model, with that limit, and show it and its policies
Write-Host "🔖 Alias $STREAM_ALIAS and its policies:"
az aigateway model-alias set -g $RG --gateway-name $GATEWAY -n $STREAM_ALIAS `

  --backend-model resource-id="$GATEWAY_ID/workspaces/default/modelProviders/$PROVIDER/models/$MODEL" `
  --policies "@policies.json" `

#Verify

Send bursts of streamed requests that each use about 220 tokens: first without asking for usage, then with it. If the gateway only counted the tokens that clients report, the first burst would never be throttled.

1

#Stream a burst without asking for usage

For each request, the script prints the status, Retry-After, the number of events, and the usage chunk, if any.

# Send 8 streamed requests to the streaming alias, without asking for usage
echo "🚦 Expect 429 Too Many Requests after about 1,000 tokens, with no usage chunks:"
./infra/stream-burst.sh "$STREAM_ALIAS" 8
# Send 8 streamed requests to the streaming alias, without asking for usage
Write-Host "🚦 Expect 429 Too Many Requests after about 1,000 tokens, with no usage chunks:"
./infra/stream-burst.ps1 -Model $STREAM_ALIAS -Requests 8

On GitHub, open stream-burst.sh↗ or stream-burst.ps1↗.

Expected output (your counts differ):

Text
🚦 Expect 429 Too Many Requests after about 1,000 tokens, with no usage chunks:
Request  Status  Retry-After  Events  Usage chunk
1        200     -            209     none
2        200     -            187     none
3        200     -            207     none
4        200     -            200     none
5        200     -            196     none
6        200     -            191     none
7        429     2            -       Token limit is exceeded. Try again in 2 seconds.
8        429     1            -       Token limit is exceeded. Try again in 1 seconds.

No stream carried a usage chunk, yet the gateway throttled request 7, after about 1,300 tokens. If it had counted only the prompts, about 25 tokens each, the alias would have allowed roughly 40 requests.

Note

A new alias or policy can take up to a minute to apply, and the counters catch up within a few seconds, so a fast burst can go a few hundred tokens past the limit. If every request returns 200, wait a minute and run it again.

The throttled answer is plain JSON, not an event stream, because the gateway refused the request before it reached the model. Check the status code before you start reading events, and honor Retry-After.

#Go further

  • Cap spend for streams. A cost limit is estimated from the same usage record, so streamed calls count against budgets too. Try it in Enforce cost budgets.
  • Shorten the time to the first token. Reasoning models think before they write. For chat that needs a quick first word, set reasoning_effort to low or none where the model supports it, as the scripts in this lab do.
  • Stream from an agent. Agent frameworks stream through the same endpoint. See Connect agent frameworks to models and tools.
  • Check your proxies. Anything between the client and the gateway, such as a reverse proxy or an API layer of your own, must pass text/event-stream responses through without buffering.
