Lock down the gateway with private networking

Join your AI Gateway to a virtual network, reach it through a private endpoint, call a private Foundry backend, and only then turn off public network access, with DNS checks at every step.

Advanced 45 min PortalCLIBicep Updated Oct 14, 2026
Source Edit

What you'll do

  • Explain why inbound private endpoints and outbound VNet integration are configured separately
  • Prepare a delegated integration subnet with an NSG that passes the gateway's prerequisite checks
  • Add an inbound private endpoint with the privatelink.azure-api.net zone and make a Foundry backend private
  • Prove name resolution and both traffic paths from a VM inside the virtual network
  • Disable public network access last, and roll it all back cleanly

Before you start

  • 01Provision your AI Gateway
  • 12Call backends with managed identities

Tracks: Portal, Azure CLI, Bicep / azd

Your security team signs off on the AI platform only if model and tool traffic never crosses the public internet: apps reach the gateway on a private IP, the gateway reaches Foundry on a private IP, and the public endpoint is switched off. In this lab you build that topology step by step, verify each hop from a VM inside the virtual network, and disable public access only after everything resolves and responds privately.

#Before you begin

  • Complete Provision your AI Gateway and Call backends with managed identities. You need a gateway with an imported Foundry model that the gateway calls with its managed identity, a callable alias, and a runtime API key from Access›Keys.
  • The Azure CLI↗ 2.75 or later, signed in with az login, and the aigateway extension (install it↗). Every track uses the CLI for the test VM and the verification steps.
  • Permission to create network resources and to change the gateway and the Foundry resource, for example Contributor on their resource groups. Approving a private endpoint on the gateway also requires write access to the gateway.
  • AI Gateway is in preview in East US 2 and Sweden Central. The virtual network for VNet integration must be in the gateway's region.
Important

This lab creates billable resources: private endpoints, private DNS zones, and a small Linux VM with a disk. AI Gateway itself is free during the preview. Follow Clean up when you finish.

#How it works

Private networking has two directions, and you configure them separately. Inbound, a private endpoint gives the gateway a private IP in your virtual network, and the privatelink.azure-api.net private DNS zone makes the gateway's usual host name resolve to that IP for clients in linked networks. Outbound, VNet integration joins the gateway to a delegated subnet, so it can call models, MCP servers, and APIs on private IPs. An inbound private endpoint doesn't grant outbound reach, and VNet integration doesn't make the gateway private.

The order matters. Turn on VNet integration first, add the inbound private endpoint, make your backends private, test both paths, and disable public network access last. Most connectivity problems are DNS: clients must resolve the gateway to its private endpoint IP, and the gateway must resolve each backend to its private IP.

#Choose what to declare

The template declares everything around the gateway: the NSG, the virtual network and subnets, the inbound private endpoint with its privatelink.azure-api.net zone, and an optional private endpoint to Foundry. It references the gateway as existing and never redeclares it. A Bicep deployment sends a PUT, and redeclaring the gateway service risks resetting settings you didn't copy into the template. Turning on VNet integration and disabling public access are PATCH operations, so you run them with az aigateway network update, exactly like the CLI track.

The private endpoints are behind parameters (includeGatewayPrivateEndpoint and foundryAccountId), so you can follow the recommended order: deploy the network now, enable VNet integration next, and redeploy with the private endpoints after that.

#Review the template

infra/main.bicepGitHub
// Private networking for an existing AI Gateway.
// Creates the network pieces the gateway needs, without redeclaring the gateway itself:
//   - an NSG that allows outbound TCP 443 to the Storage and AzureKeyVault service tags
//   - a virtual network with an integration subnet (delegated to Microsoft.Web/serverFarms),
//     a private-endpoint subnet, and a small jumpbox subnet for testing
//   - optionally, an inbound private endpoint to the gateway (group ID "Gateway") registered in the
//     privatelink.azure-api.net private DNS zone
//   - optionally, a private endpoint to a Foundry resource (group ID "account") with its private DNS zones
// Outbound VNet integration and public network access are PATCH operations on the gateway. Run them with
// `az aigateway network update`, because a Bicep PUT on the gateway service would redeclare the whole resource.

@description('Name of the existing AI Gateway (API Management service with the AIGateway SKU).')
param gatewayName string

@description('Resource group of the existing AI Gateway. Defaults to the deployment resource group.')
param gatewayResourceGroup string = resourceGroup().name

@description('Region for the network resources. Use the gateway region: VNet integration requires the virtual network in the same region as the gateway.')
param location string = resourceGroup().location

@description('Name of the virtual network.')
param vnetName string = 'vnet-aigw'

@description('Address space of the virtual network.')
param vnetAddressPrefix string = '10.20.0.0/16'

@description('Name of the subnet dedicated to gateway VNet integration.')
param integrationSubnetName string = 'snet-aigw-integration'

@description('Prefix of the integration subnet. /27 is the minimum; /24 leaves room to scale.')
param integrationSubnetPrefix string = '10.20.0.0/24'

@description('Name of the subnet that holds private endpoints.')
param privateEndpointSubnetName string = 'snet-private-endpoints'

@description('Prefix of the private-endpoint subnet.')
param privateEndpointSubnetPrefix string = '10.20.1.0/24'

@description('Name of the subnet for the test VM (jumpbox).')
param jumpboxSubnetName string = 'snet-jumpbox'

@description('Prefix of the jumpbox subnet.')
param jumpboxSubnetPrefix string = '10.20.2.0/27'

@description('Name of the network security group attached to the integration subnet.')
param nsgName string = 'nsg-aigw-integration'

@description('Create the inbound private endpoint to the gateway. Deploy with false first, enable VNet integration, then redeploy with true.')
param includeGatewayPrivateEndpoint bool = false

@description('Name of the inbound private endpoint to the gateway.')
param gatewayPrivateEndpointName string = 'pe-${gatewayName}'

@description('Optional resource ID of a Foundry (AIServices) account to reach privately. Leave empty to skip.')
param foundryAccountId string = ''

@description('Name of the private endpoint to the Foundry account.')
param foundryPrivateEndpointName string = 'pe-foundry-${gatewayName}'

var includeFoundryPrivateEndpoint = !empty(foundryAccountId)

// Standard private DNS zones for Foundry (AIServices) accounts.
var foundryDnsZoneNames = [
  'privatelink.cognitiveservices.azure.com'
  'privatelink.openai.azure.com'
  'privatelink.services.ai.azure.com'
]

resource gateway 'Microsoft.ApiManagement/service@2025-09-01-preview' existing = {
  name: gatewayName
  scope: resourceGroup(gatewayResourceGroup)
}

resource nsg 'Microsoft.Network/networkSecurityGroups@2024-05-01' = {
  name: nsgName
  location: location
  properties: {
    securityRules: [
      {
        name: 'AllowStorageOutbound'
        properties: {
          priority: 100
          direction: 'Outbound'
          access: 'Allow'
          protocol: 'Tcp'
          sourceAddressPrefix: 'VirtualNetwork'
          sourcePortRange: '*'
          destinationAddressPrefix: 'Storage'
          destinationPortRange: '443'
        }
      }
      {
        name: 'AllowKeyVaultOutbound'
        properties: {
          priority: 110
          direction: 'Outbound'
          access: 'Allow'
          protocol: 'Tcp'
          sourceAddressPrefix: 'VirtualNetwork'
          sourcePortRange: '*'
          destinationAddressPrefix: 'AzureKeyVault'
          destinationPortRange: '443'
        }
      }
    ]
  }
}

// Subnets are declared inline so that redeploying the template never tries to delete them.
resource vnet 'Microsoft.Network/virtualNetworks@2024-05-01' = {
  name: vnetName
  location: location
  properties: {
    addressSpace: {
      addressPrefixes: [ vnetAddressPrefix ]
    }
    subnets: [
      {
        name: integrationSubnetName
        properties: {
          addressPrefix: integrationSubnetPrefix
          networkSecurityGroup: {
            id: nsg.id
          }
          delegations: [
            {
              name: 'Microsoft.Web.serverFarms'
              properties: {
                serviceName: 'Microsoft.Web/serverFarms'
              }
            }
          ]
        }
      }
      {
        name: privateEndpointSubnetName
        properties: {
          addressPrefix: privateEndpointSubnetPrefix
          privateEndpointNetworkPolicies: 'Disabled'
        }
      }
      {
        name: jumpboxSubnetName
        properties: {
          addressPrefix: jumpboxSubnetPrefix
        }
      }
    ]
  }
}

resource integrationSubnet 'Microsoft.Network/virtualNetworks/subnets@2024-05-01' existing = {
  parent: vnet
  name: integrationSubnetName
}

resource privateEndpointSubnet 'Microsoft.Network/virtualNetworks/subnets@2024-05-01' existing = {
  parent: vnet
  name: privateEndpointSubnetName
}

// Inbound: clients in the virtual network reach the gateway on a private IP.
resource gatewayDnsZone 'Microsoft.Network/privateDnsZones@2020-06-01' = if (includeGatewayPrivateEndpoint) {
  name: 'privatelink.azure-api.net'
  location: 'global'
}

resource gatewayDnsZoneLink 'Microsoft.Network/privateDnsZones/virtualNetworkLinks@2020-06-01' = if (includeGatewayPrivateEndpoint) {
  parent: gatewayDnsZone
  name: '${vnetName}-link'
  location: 'global'
  properties: {
    registrationEnabled: false
    virtualNetwork: {
      id: vnet.id
    }
  }
}

resource gatewayPrivateEndpoint 'Microsoft.Network/privateEndpoints@2024-05-01' = if (includeGatewayPrivateEndpoint) {
  name: gatewayPrivateEndpointName
  location: location
  properties: {
    subnet: {
      id: privateEndpointSubnet.id
    }
    privateLinkServiceConnections: [
      {
        name: 'gateway'
        properties: {
          privateLinkServiceId: gateway.id
          groupIds: [ 'Gateway' ]
        }
      }
    ]
  }
}

resource gatewayPrivateDnsZoneGroup 'Microsoft.Network/privateEndpoints/privateDnsZoneGroups@2024-05-01' = if (includeGatewayPrivateEndpoint) {
  parent: gatewayPrivateEndpoint
  name: 'default'
  properties: {
    privateDnsZoneConfigs: [
      {
        name: 'apim-gateway'
        properties: {
          privateDnsZoneId: gatewayDnsZone.id
        }
      }
    ]
  }
}

// Outbound: the integrated gateway resolves the Foundry account to a private IP and calls it privately.
resource foundryDnsZones 'Microsoft.Network/privateDnsZones@2020-06-01' = [for zoneName in foundryDnsZoneNames: if (includeFoundryPrivateEndpoint) {
  name: zoneName
  location: 'global'
}]

resource foundryDnsZoneLinks 'Microsoft.Network/privateDnsZones/virtualNetworkLinks@2020-06-01' = [for (zoneName, i) in foundryDnsZoneNames: if (includeFoundryPrivateEndpoint) {
  parent: foundryDnsZones[i]
  name: '${vnetName}-link'
  location: 'global'
  properties: {
    registrationEnabled: false
    virtualNetwork: {
      id: vnet.id
    }
  }
}]

resource foundryPrivateEndpoint 'Microsoft.Network/privateEndpoints@2024-05-01' = if (includeFoundryPrivateEndpoint) {
  name: foundryPrivateEndpointName
  location: location
  properties: {
    subnet: {
      id: privateEndpointSubnet.id
    }
    privateLinkServiceConnections: [
      {
        name: 'foundry'
        properties: {
          privateLinkServiceId: foundryAccountId
          groupIds: [ 'account' ]
        }
      }
    ]
  }
}

resource foundryPrivateDnsZoneGroup 'Microsoft.Network/privateEndpoints/privateDnsZoneGroups@2024-05-01' = if (includeFoundryPrivateEndpoint) {
  parent: foundryPrivateEndpoint
  name: 'default'
  properties: {
    privateDnsZoneConfigs: [for (zoneName, i) in foundryDnsZoneNames: {
      name: replace(zoneName, '.', '-')
      properties: {
        privateDnsZoneId: foundryDnsZones[i].id
      }
    }]
  }
}

output vnetId string = vnet.id
output integrationSubnetId string = integrationSubnet.id
output privateEndpointSubnetId string = privateEndpointSubnet.id
output gatewayPrivateEndpointName string = includeGatewayPrivateEndpoint ? gatewayPrivateEndpoint.name : ''
output foundryPrivateEndpointName string = includeFoundryPrivateEndpoint ? foundryPrivateEndpoint.name : ''

#Reach the model backend privately

The gateway now sits in your virtual network, but it still calls Foundry on its public endpoint. Give the Foundry resource a private endpoint in the same virtual network and link its private DNS zones, so the integrated gateway resolves Foundry to a private IP. Then turn off Foundry's public access. The gateway keeps authenticating with its managed identity from Call backends with managed identities; only the network path changes.

Warning

Disabling public access on the Foundry resource also blocks anything else that calls it over the internet, including tools on your workstation. Use a dedicated Foundry resource for this lab if others depend on it.

#Link the Foundry private DNS zones

Create each zone, link it to the virtual network, and add it to the endpoint's DNS zone group:

Bash
first=true
for zone in privatelink.cognitiveservices.azure.com privatelink.openai.azure.com privatelink.services.ai.azure.com; do
  az network private-dns zone create -g "$RG" -n "$zone"
  az network private-dns link vnet create -g "$RG" -z "$zone" -n "$VNET-link" -v "$VNET" -e false
  if $first; then
    az network private-endpoint dns-zone-group create -g "$RG" --endpoint-name "pe-foundry-$GATEWAY" \
      -n default --private-dns-zone "$zone" --zone-name "${zone//./-}"
    first=false
  else
    az network private-endpoint dns-zone-group add -g "$RG" --endpoint-name "pe-foundry-$GATEWAY" \
      -n default --private-dns-zone "$zone" --zone-name "${zone//./-}"
  fi
done

#Test the private path from inside the network

Before you switch anything off, prove that a client inside the virtual network resolves the gateway to its private IP and gets an HTTP answer. A small Linux VM without a public IP is enough. You run commands on it with az vm run-command invoke, so you don't need SSH, a bastion, or a gateway key on the VM.

#Create the test VM

az vm create -g "$RG" -n "$JUMPBOX" -l "$LOCATION" \
  --image Ubuntu2204 --size Standard_B2s \
  --vnet-name "$VNET" --subnet "$JUMPBOX_SUBNET" \
  --public-ip-address "" --nsg "" \
  --os-disk-delete-option Delete --nic-delete-option Delete \
  --admin-username azureuser --generate-ssh-keys
az vm create -g $RG -n $JUMPBOX -l $LOCATION `
  --image Ubuntu2204 --size Standard_B2s `
  --vnet-name $VNET --subnet $JUMPBOX_SUBNET `
  --public-ip-address '""' --nsg '""' `
  --os-disk-delete-option Delete --nic-delete-option Delete `
  --admin-username azureuser --generate-ssh-keys

--public-ip-address "" and --nsg "" create the VM without a public IP or its own NSG, and the delete options remove its disk and network interface when you delete the VM. If Standard_B2s isn't available in your region, pick another small size.

#Run the DNS and HTTPS checks

From the lab folder, run the script for your shell. It sends jumpbox-check.sh↗ to the VM, which runs nslookup on the gateway host and sends one HTTPS request without credentials.

./infra/test-private-path.sh "$RG" "$JUMPBOX"
./infra/test-private-path.ps1 -ResourceGroup $RG -VmName $JUMPBOX

On GitHub, open test-private-path.sh↗ or test-private-path.ps1↗.

Expected output (trimmed; your IP differs):

Text
[stdout]
== DNS: <gateway>.azure-api.net
Non-authoritative answer:
<gateway>.azure-api.net	canonical name = <gateway>.privatelink.azure-api.net.
Name:	<gateway>.privatelink.azure-api.net
Address: 10.20.1.4
== HTTPS: POST https://<gateway>.azure-api.net/default/models/openai/v1/chat/completions (no credentials)
HTTP 401 from 10.20.1.4

The name resolves through privatelink.azure-api.net to an IP in snet-private-endpoints, and the gateway answers from that IP. The request carries no key, so the gateway rejects it; any HTTP status code proves the network path. HTTP 000 means DNS or routing failed.

Checkpoint

Inside the virtual network, the gateway resolves to a 10.20.1.x address and answers over HTTPS. From your workstation, the model call through the gateway still returns 200.

#Go further

  • Hub-and-spoke networks. Put the private endpoint in a hub, peer your spokes, and link privatelink.azure-api.net to every spoke that hosts clients. For on-premises clients, forward the zone from your DNS servers to Azure. See Azure private endpoint DNS configuration↗.
  • Private MCP servers and APIs. Any backend with a private endpoint or a private IP that the integrated virtual network can reach works the same way. Remember the second half of the DNS rule: the gateway must resolve each backend to its private IP.
  • Endpoints in another region. The inbound private endpoint can be in a different region from the gateway, as long as it's in the same region as its own virtual network.
  • Data residency. Residency follows the whole request path, so account for where your backends, tools, logs, and clients live, not only the gateway region.

#Troubleshooting

SymptomLikely causeFix
nslookup on the VM returns a public IP, or no privatelink.azure-api.net aliasThe zone isn't linked to the VM's virtual network, or the endpoint has no DNS zone groupLink privatelink.azure-api.net to the virtual network and add the zone group (apim-gateway configuration) to the endpoint.
The portal shows VNet integration prerequisites may not be metThe subnet is in another region, smaller than /27, shared with other resources, not delegated, or the NSG lacks the 443 rulesFix each listed item. The NSG needs outbound TCP 443 allow rules to Storage and AzureKeyVault.
Model calls fail after you disable Foundry public accessThe gateway resolves Foundry to its public IP, or VNet integration isn't onConfirm virtualNetworkType is External, and that the Foundry private DNS zones are linked to the integrated virtual network. An inbound private endpoint alone doesn't give the gateway outbound reach.
The private endpoint connection stays PendingYou created the endpoint without write access to the gatewayApprove it in Networking›Private endpoints or with az aigateway network private-endpoint-connection approve.
Clients outside the virtual network stop workingPublic network access is disabledExpected. Route those clients through a peered or linked network, or re-enable public access while you migrate them.
Networking changes are rejected while another change runsThe networking configuration is locked during an updateWait for az aigateway network wait --updated to return, then retry.
