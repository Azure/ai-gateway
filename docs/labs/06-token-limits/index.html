Governance & cost · Lab 06

Throttle tokens per caller with token limits

Cap how many tokens each app, agent, or user can consume per minute, hour, or day, and watch the gateway answer with 429 and Retry-After before your backend capacity runs out.

Beginner 25 min PortalCLIRESTBicep Updated Oct 22, 2026
Notebook Source Edit

What you'll do

  • Explain how a token limit counts tokens per caller and per time window
  • Add a token rate limit to a model in the portal, with the Azure CLI, or with the REST API
  • Publish a separately limited alias with Bicep, without touching existing clients
  • Trigger a 429 response, read Retry-After, and find the throttled calls in Monitoring

Before you start

  • 02Publish a Foundry model and make your first call

Tracks: Portal, Azure CLI, REST, Bicep / azd

Your gateway now serves several apps from one model deployment. One batch job sends long prompts in a tight loop and eats the deployment's tokens-per-minute (TPM) capacity, so every other app starts to fail. In this lab you give each caller its own token allowance at the gateway, so a noisy neighbor gets a 429 with Retry-After and everyone else keeps working.

#Before you begin

  • Complete Publish a Foundry model and make your first call. You need a gateway, an imported model, a callable alias, and a runtime API key from Access›Keys.
  • For the CLI, REST, and IaC tracks: the Azure CLI↗ 2.75 or later, signed in with az login, plus jq for the Bash snippets. The CLI track calls the Azure Resource Manager REST API with az rest, because the az aigateway extension doesn't manage the new aigateways resource type yet.
  • Permission to change the gateway, for example Contributor on the resource group.

Set these variables once. Every track and the Verify section reuse them.

#How it works

A token limit is a policy that the gateway evaluates before it forwards a request. It keeps a counter of the tokens that each caller consumed in the current window. While the counter is under the limit, the request goes through and the tokens in the response are added to the counter. When the counter reaches the limit, the gateway answers 429 Too Many Requests with a Retry-After header and never calls the backend.

SettingPortal labelJSON fieldValues
AllowanceAllowed tokenscountPositive integer
WindowTime periodperiodminute (TPM), hour, day (quota)
Who gets a counterCounter dimensionscounterKeyAn array: ["identity"] (each API key, or each Entra tenant + object ID), ["ipAddress"], or both

You can attach a token limit to a model (applies to every alias that targets it), to an alias (only callers that use that name), or to the gateway (a default for every compatible model, including models you add later). Every applicable policy is checked, and any one of them can block the request.

Note

The backend deployment has its own capacity, shown as Token rate limit (TPM) on the model's details page. The gateway limit is how you share that capacity fairly. Set per-caller limits so that the sum of your busiest callers stays below the deployment's TPM.

#Add a token limit to the model

Pick one track. Each track produces the same policy on your model: 1,000 tokens per minute for each caller identity. The limit is deliberately low so you can trigger it in a few requests. The IaC track takes a different route, explained in its first step.

Choose your track
1

#Start the policy wizard

Open the AI Gateway portal↗ and select your gateway from the gateway switcher. Select Policies›Add policy. On the Type step, under Cost & Rate Limits, select Token rate limit, then Next.

2

#Choose where the limit applies

On the Scope step, select Individual assets ("Apply only to selected models, aliases, or MCP servers"). Select your model, then Next.

Tip

Gateway scope applies the limit to every compatible asset, including models you add later. It's a good default for production. You'll try it in Go further.

3

#Configure the allowance

On the Details step (Configure in some portal versions), under Parameters, set:

FieldValue
Time periodPer minute
Allowed tokens1000
Counter dimensionsCaller identity

Select Create. The policy appears in the Policies list with your model as its scope.

Checkpoint

Policies lists a Token rate limit for your model with 1,000 tokens per minute and the Caller identity counter.

1

#Set the token limit

Policies live in the model's properties.policies array, and a PATCH replaces the whole array. So read the array, swap in the token limit, keep every other policy, and write it back.

az rest --url "$MODEL_URL?$API" \
  | jq -c '{properties:{policies:([(.properties.policies // [])[] | select(.type != "tokenLimit")]
      + [{type:"tokenLimit",count:1000,period:"minute",counterKey:["identity"]}])}}' > policies.json
az rest --method patch --url "$MODEL_URL?$API" --body @policies.json --query properties.policies
rm policies.json
$p = (az rest --url "$MODEL_URL`?$API" | ConvertFrom-Json).properties.policies
$p = @($p | Where-Object { $_ -and $_.type -ne 'tokenLimit' }) +
     @(@{ type = 'tokenLimit'; count = 1000; period = 'minute'; counterKey = @('identity') })
@{ properties = @{ policies = $p } } | ConvertTo-Json -Depth 10 -Compress | Set-Content policies.json
az rest --method patch --url "$MODEL_URL`?$API" --body "@policies.json" --query properties.policies
Remove-Item policies.json

period accepts minute, hour, or day. counterKey is an array with identity, ipAddress, or both.

2

#Confirm the policy

az rest --url "$MODEL_URL?$API" --query properties.policies -o json
az rest --url "$MODEL_URL`?$API" --query properties.policies -o json
Checkpoint

The output contains "type": "tokenLimit" with "count": 1000, "period": "minute", "counterKey": ["identity"], and "scope": "resource", which the service adds to every model policy.

#Read the current policies

#Replace the token limit and keep everything else

  + [{"type":"tokenLimit","count":1000,"period":"minute","counterKey":["identity"]}]')"

Remove-Item patch.json
Checkpoint

Running the GET again returns your other policies unchanged plus one tokenLimit entry with "counterKey": ["identity"] and "scope": "resource".

1

#Choose what to declare

A Bicep deployment sends a PUT, which replaces the whole resource. Redeclaring a model you imported in the portal risks dropping settings you didn't copy. Instead, this template adds a new alias, <model-name>-limited, that targets the same backend model and carries its own token limit. Existing clients keep calling the original alias. Callers that you move to the new alias get the allowance.

This is also a common production pattern: one backend model, several aliases, and a different limit for each audience (for example gpt-chat for interactive apps and gpt-batch for offline jobs).

2

#Review the template

infra/main.bicepGitHub
// Publishes a rate-limited alias for an existing AI Gateway model.
// The alias points at the same backend model as your default alias, but carries its own token limit,
// so you can give a "batch" or "trial" audience a smaller allowance without touching the model.

@description('Name of the existing AI Gateway (Microsoft.ApiManagement/aigateways).')
param gatewayName string

@description('Name of the existing model provider in the gateway, for example foundry-models.')
param providerName string

@description('Name of the existing backend model registration under the provider.')
param modelName string

@description('Callable alias to create. Clients send this value in the request "model" field.')
param aliasName string = '${modelName}-limited'

@description('Tokens allowed per period for each caller.')
@minValue(1)
param allowedTokens int = 1000

@description('Token limit window.')
@allowed([ 'minute', 'hour', 'day' ])
param period string = 'minute'

@description('Who gets a token counter: identity (each API key or Entra principal), ipAddress (each client IP address), or both.')
@allowed([ 'identity', 'ipAddress' ])
param counterKey array = [ 'identity' ]

resource gateway 'Microsoft.ApiManagement/aigateways@2025-09-01-preview' existing = {
  name: gatewayName
}

resource workspace 'Microsoft.ApiManagement/aigateways/workspaces@2025-09-01-preview' existing = {
  parent: gateway
  name: 'default'
}

resource provider 'Microsoft.ApiManagement/aigateways/workspaces/modelProviders@2025-09-01-preview' existing = {
  parent: workspace
  name: providerName
}

resource model 'Microsoft.ApiManagement/aigateways/workspaces/modelProviders/models@2025-09-01-preview' existing = {
  parent: provider
  name: modelName
}

resource limitedAlias 'Microsoft.ApiManagement/aigateways/workspaces/aliases@2025-09-01-preview' = {
  parent: workspace
  name: aliasName
  properties: {
    backendModels: [
      { resourceId: model.id }
    ]
    policies: [
      {
        type: 'tokenLimit'
        count: allowedTokens
        period: period
        counterKey: counterKey
      }
    ]
  }
}

output aliasName string = limitedAlias.name
output chatCompletionsUrl string = 'https://${gateway.properties.frontend.defaultHostname}/default/models/openai/v1/chat/completions'

On GitHub, open infra/main.bicep↗.

3

#Deploy it

az deployment group create -g "$RG" \
  --template-file infra/main.bicep \
  --parameters gatewayName="$GATEWAY" providerName="$PROVIDER" modelName="$MODEL" \
               allowedTokens=1000 period=minute counterKey="['identity']" \
  --query properties.outputs

export AI_GATEWAY_MODEL="$MODEL-limited"
az deployment group create -g $RG `
  --template-file infra/main.bicep `
  --parameters gatewayName=$GATEWAY providerName=$PROVIDER modelName=$MODEL `
               allowedTokens=1000 period=minute counterKey="['identity']" `
  --query properties.outputs

$env:AI_GATEWAY_MODEL = "$MODEL-limited"

counterKey is an array parameter. Pass "['ipAddress']" to count per client IP address, or "['identity','ipAddress']" for both. The single quotes inside the value survive both Bash and PowerShell.

Checkpoint

In the portal, Models shows the <model-name>-limited alias, and Policies lists a Token rate limit scoped to it.

#Verify

Send a burst of requests that each use about 225 tokens. With a 1,000-token budget, the first few succeed, and then the gateway starts answering 429.

1

#Run the burst

From the lab folder, run the script for your shell. For each request it prints the status, Retry-After, the tokens used, and the backend deployment's own x-ratelimit-remaining-tokens header.

./infra/trigger-token-limit.sh "$AI_GATEWAY_MODEL" 8
./infra/trigger-token-limit.ps1 -Model $env:AI_GATEWAY_MODEL -Requests 8

On GitHub, open trigger-token-limit.sh↗ or trigger-token-limit.ps1↗.

Expected output (your token counts will differ):

Text
Request  Status  Retry-After  Tokens used  Backend tokens left
1        200     -            231          9977
2        200     -            214          9977
3        200     -            220          9977
4        200     -            221          9977
5        200     -            223          9977
6        200     -            229          9977
7        429     1            -            -
8        200     -            222          9977

The gateway stops this caller once it passes 1,000 tokens, while the backend deployment still has most of its capacity left: that's the point of a per-caller limit. Retry-After says how many seconds to wait, and a request sent after that wait can succeed again, as request 8 shows. The gateway doesn't add its own remaining-tokens header, so watch the status and Retry-After.

Note

The gateway counts a request's tokens after the response, and its counters catch up within a few seconds, so a fast burst can go a few hundred tokens past the budget before the first 429. A new or changed policy can also take up to a minute to apply. If every request returns 200, wait a minute and run the burst again.

2

#Inspect one throttled response

Look at the full headers and body of a single throttled call:

Bash
curl -i "${AI_GATEWAY_URL%/}/default/models/openai/v1/chat/completions" \
  -H "api-key: $AI_GATEWAY_API_KEY" -H "Content-Type: application/json" \
  -d "{\"model\":\"$AI_GATEWAY_MODEL\",\"messages\":[{\"role\":\"user\",\"content\":\"ping\"}]}"

The status line is HTTP/1.1 429, and Retry-After tells the client how many seconds to wait. Well-behaved SDKs, including the OpenAI SDKs, honor Retry-After automatically when they retry.

3

#Prove the counter is per caller

Create a second runtime key in Access›Keys, set it as AI_GATEWAY_API_KEY in a new terminal, and run the burst again while the first key is still throttled. The second key starts with a full allowance, because Caller identity gives every key its own counter.

4

#Find the throttled calls in Monitoring

If you configured Application Insights in Monitor usage, cost, and traces, open Monitoring. The dashboard shows 429 outcomes and policy impact next to token consumption, and the Traces tab shows the policy span that blocked each request.

Checkpoint

You saw 200 responses until the allowance ran out, then 429 with Retry-After. A second key wasn't affected, and the backend received no calls while the limit was active.

#Go further

  • Set a gateway-wide default. Add a second Token rate limit with Gateway scope and a generous allowance, such as 100000 per minute. New models get a guardrail the moment you import them, and you keep the stricter model or alias limits on top.
  • Add a daily quota. Combine a per-minute limit (smooths bursts) with a Per day limit (caps total use). Both are checked on every request.
  • Limit by IP address. For a public demo with one shared key, use Caller IP address so each visitor gets their own counter.
  • Budget in dollars instead of tokens. Token counts don't reflect model prices. To cap spend, continue with Enforce cost budgets.

#Clean up

The policy doesn't cost anything, but a 1,000-token limit will throttle real traffic. Remove it, or raise it to a production value, before you continue.

#Troubleshooting

SymptomLikely causeFix
Every request returns 200, never 429The limit is on a different model or alias than the one you call, or the window reset between requestsCheck that the request model matches an alias of the limited model. Run the burst without pauses.
429 on the very first requestAnother token limit with a lower allowance applies, for example a Gateway scope policy, or the counter is shared because Counter dimensions is emptyReview Policies for every limit that covers the model. Pick Caller identity for per-caller counters.
403 with LlmCostQuotaExceededA Cost limit blocked the call, not the token limitSee Enforce cost budgets.
429 without a gateway token limitThe backend deployment ran out of TPMRaise the deployment's capacity in Foundry, or lower per-caller gateway limits so their sum fits.
