Govern MCP servers with Agent 365

Connect Microsoft Agent 365 to your gateways, find their MCP servers in one inventory, block a single tool or a whole server from the Microsoft 365 admin center, and see exactly what agents get back.

Intermediate 20 min Portal Updated Oct 19, 2026
Source Edit

What you'll do

  • Explain how Agent 365 governance and gateway enforcement split the work
  • Publish a static list of allowed tools so Agent 365 can govern individual tools
  • Grant tenant consent and find your gateway's MCP servers in the Agent 365 inventory
  • Block and unblock a tool and a whole MCP server, and recognize what agents receive

Before you start

  • 04Federate MCP tools behind one endpoint
  • 05Control which tools agents can call

Tracks: Portal

Your platform team runs the gateway, but the people who decide which tools agents may use sit in IT and security, and they work in the Microsoft 365 admin center, not in Azure. When a tool is found to be risky, they need to switch it off across every gateway in minutes, without filing a ticket. In this lab you connect Microsoft Agent 365 to your gateways, block one tool and then a whole MCP server from the admin center, and watch the gateway enforce each decision on live traffic.

#Before you begin

  • Complete Federate MCP tools behind one endpoint and Control which tools agents can call. This lab governs the learn MCP server, and you edit its Tool availability the same way you did in lab 05.
  • A Microsoft Agent 365 tenant, and a tenant administrator who can grant tenant-level consent in the Microsoft 365 admin center↗. After consent, Agent 365 administrators don't need Azure permissions of their own.
  • Permission to edit the MCP server in the AI Gateway portal, for example Contributor on the gateway's resource group, and a runtime API key from Access›Keys.
  • For the test script: curl and jq (Bash) or PowerShell 7 or later. Get the gateway URL from the portal or with the Azure CLI↗ 2.75 or later, signed in with az login. The CLI reads the new aigateways resource type with az resource, because the az aigateway extension doesn't manage it yet.
Note

The Agent 365 integration is an emerging preview capability. Labels and behavior can change; see the release note↗. AI Gateway itself is free during the preview; Agent 365 is licensed separately.

#How it works

The integration separates governance from enforcement. Microsoft Agent 365 keeps the inventory and the access decisions. Azure API Management enforces them inline on every request to an MCP server, and emits runtime signals for auditing and investigation.

After a tenant administrator consents once, Agent 365 discovers Microsoft.ApiManagement resources across the tenant's subscriptions, including subscriptions you add later, and lists their MCP servers and tools with metadata such as endpoints, access scopes, and service identities. When an administrator blocks a server or a tool, Agent 365 uses API Management control-plane operations to insert a managed policy into that server. Unblocking removes it. Existing agents keep using the same gateway endpoints.

ControlWhere you set itWhat callers get
Block a tool (Agent 365)Admin center › Agents›Tools › server › Tools tabHTTP 200, isError: true, denial code ToolNotAvailable
Block a server (Agent 365)Admin center › Agents›Tools › server › BlockHTTP 403, error code AccessBlockedByGateway
Blocked tools (gateway)AI Gateway portal › MCP server › Tools stepThe tool stays visible, but the gateway blocks its execution
MCP server access (gateway)AI Gateway portal › MCP server › Basic info stepBlocked servers can't be reached by clients

Tool-level blocking needs a static list of allowed tools on the server, so Agent 365 can read the tool list. It isn't available for servers with dynamic allowed tools, such as Allow all tools.

#Publish a static list of allowed tools

Agent 365 can only list and block individual tools when the MCP server publishes a fixed set of tools. You set that in the AI Gateway portal.

1

#Open the Tools step

Open the AI Gateway portal↗ and select your gateway from the gateway switcher. Select MCP servers, then learn, then Edit, and go to the Tools step.

2

#Select exact tools

Under Tool availability, choose Select exact tools, and select the three learn_ tools: learn_microsoft_docs_search, learn_microsoft_code_sample_search, and learn_microsoft_docs_fetch. Leave Blocked tools empty, so the only blocks in this lab come from Agent 365. Select Save.

If your portal doesn't offer Select exact tools yet, Agent 365 can't read this server's tool list. You can still block the whole server from Agent 365, and block single tools under Blocked tools in the AI Gateway portal, as in lab 05.

3

#Check the catalog

List the tools through the gateway. The script runs the MCP handshake with your runtime key and prints the gateway's answer even when a call is blocked.

infra/call-tool.shGitHub
#!/usr/bin/env bash
# Connects to an AI Gateway MCP server with the MCP Streamable HTTP handshake
# (initialize -> notifications/initialized -> tools/list), prints the published tools, and optionally calls one
# tool. Unlike a plain client, it prints the gateway's answer when a server or tool is blocked, so you can see
# how Agent 365 and gateway controls reach the caller.
#
# Usage:
#   export AI_GATEWAY_URL="https://<gateway>.eastus2-01.ai.gateway.azure.com"
#   export AI_GATEWAY_API_KEY="..."      # never commit this value
#   ./call-tool.sh [server-name] [tool-name] [arguments-json]
#
# Examples:
#   ./call-tool.sh learn
#   ./call-tool.sh learn learn_microsoft_docs_search '{"query":"What is Microsoft Agent 365?"}'
#   ./call-tool.sh learn learn_microsoft_docs_fetch '{"url":"https://learn.microsoft.com/azure/api-management/agent-365"}'
#
# Requires curl and jq.
set -euo pipefail

SERVER="${1:-learn}"
TOOL="${2:-}"
ARGS="${3:-}"
if [ -z "$ARGS" ]; then ARGS="{}"; fi
: "${AI_GATEWAY_URL:?Set AI_GATEWAY_URL to https://<gateway>.eastus2-01.ai.gateway.azure.com}"
: "${AI_GATEWAY_API_KEY:?Set AI_GATEWAY_API_KEY to a runtime key from Access > Keys}"
command -v jq >/dev/null || { echo "This script needs jq." >&2; exit 1; }
printf '%s' "$ARGS" | jq -e 'type == "object"' >/dev/null || { echo "arguments-json must be a JSON object." >&2; exit 1; }
ENDPOINT="${AI_GATEWAY_URL%/}/default/toolservers/${SERVER}/mcp"

HEADERS=(-H "api-key: $AI_GATEWAY_API_KEY" -H "Content-Type: application/json"
  -H "Accept: application/json, text/event-stream")
STATUS="" BODY="" SESSION_ID="" CORRELATION_ID=""

# post <json>: sends one JSON-RPC message and sets STATUS, BODY, CORRELATION_ID, and SESSION_ID (when returned).
post() {
  local raw head sid
  raw="$(curl -sS --max-time 60 -D - "$ENDPOINT" "${HEADERS[@]}" --data "$1" | tr -d '\r')"
  if [[ "$raw" == *$'\n\n'* ]]; then head="${raw%%$'\n\n'*}"; BODY="${raw#*$'\n\n'}"; else head="$raw"; BODY=""; fi
  STATUS="$(printf '%s\n' "$head" | awk 'toupper($1) ~ /^HTTP/ {code=$2} END {print code}')"
  CORRELATION_ID="$(printf '%s\n' "$head" | awk -F': ' 'tolower($1)=="x-correlation-id" {print $2}')"
  sid="$(printf '%s\n' "$head" | awk -F': ' 'tolower($1)=="mcp-session-id" {print $2}')"
  if [ -n "$sid" ]; then SESSION_ID="$sid"; fi
}

# response <id>: prints the JSON-RPC response with that id. The body can be JSON or server-sent events.
response() {
  if printf '%s\n' "$BODY" | grep -q '^data:'; then
    printf '%s\n' "$BODY" | sed -n 's/^data:[[:space:]]*//p'
  else
    printf '%s\n' "$BODY"
  fi | jq -c --argjson id "$1" 'select(type == "object" and .id == $id)' 2>/dev/null || true
}

# require_success <step>: prints the gateway's answer and stops when the HTTP status isn't 2xx.
require_success() {
  case "$STATUS" in
    2??) ;;
    *)
      echo "$1: HTTP ${STATUS:-no response}${CORRELATION_ID:+ (x-correlation-id: $CORRELATION_ID)}"
      printf '%s\n' "$BODY" | jq . 2>/dev/null || printf '%s\n' "$BODY"
      exit 1 ;;
  esac
}

echo "MCP endpoint: $ENDPOINT"

post '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-03-26","capabilities":{},"clientInfo":{"name":"aigateway-labs","version":"1.0"}}}'
require_success "initialize"
PROTOCOL="$(response 1 | jq -r '.result.protocolVersion // empty')"
if [ -z "$PROTOCOL" ]; then echo "initialize returned no result:" >&2; printf '%s\n' "$BODY" >&2; exit 1; fi
HEADERS+=(-H "MCP-Protocol-Version: $PROTOCOL")
if [ -n "$SESSION_ID" ]; then HEADERS+=(-H "Mcp-Session-Id: $SESSION_ID"); fi

post '{"jsonrpc":"2.0","method":"notifications/initialized"}'
require_success "notifications/initialized"

post '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}'
require_success "tools/list"
LIST="$(response 2)"
if [ -z "$LIST" ] || [ "$(printf '%s' "$LIST" | jq 'has("error")')" = "true" ]; then
  echo "tools/list returned an error:" >&2; printf '%s\n' "${LIST:-$BODY}" >&2; exit 1
fi
echo "tools/list: HTTP $STATUS"
printf '%s' "$LIST" | jq -r '.result.tools[].name | "  " + .'

if [ -z "$TOOL" ]; then exit 0; fi

echo
echo "tools/call: $TOOL $ARGS"
post "$(jq -cn --arg name "$TOOL" --argjson args "$ARGS" \
  '{jsonrpc:"2.0",id:3,method:"tools/call",params:{name:$name,arguments:$args}}')"
require_success "tools/call"
CALL="$(response 3)"
if [ -z "$CALL" ]; then echo "tools/call returned no JSON-RPC response:" >&2; printf '%s\n' "$BODY" >&2; exit 1; fi

echo "HTTP status: $STATUS"
if [ "$(printf '%s' "$CALL" | jq 'has("error")')" = "true" ]; then
  echo "JSON-RPC error:"; printf '%s' "$CALL" | jq '.error'
elif [ "$(printf '%s' "$CALL" | jq '.result.isError == true')" = "true" ]; then
  echo "isError: true"
  printf '%s' "$CALL" | jq -r '.result._meta["com.microsoft.azure.ai.gateway/denial"] // {} |
    "Denial code: \(.code // "none")\nCorrelation ID: \(.correlationId // "none")"'
  printf '%s' "$CALL" | jq -r '[.result.content[]? | select(.type == "text") | .text] | join("\n")'
else
  echo "isError: false (the result was returned)"
  printf '%s' "$CALL" | jq -r '[.result.content[]? | select(.type == "text") | .text] | join("\n") | .[0:400]'
  echo "..."
fi

Tool 'learn_microsoft_docs_fetch' is blocked by the gateway. Do not retry this tool.

The message text can differ; the denial code is what matters. The call returns HTTP 200 with a JSON-RPC result, not an HTTP error. The isError flag and the "Do not retry" text tell the agent the tool is off on purpose, so a well-behaved agent stops retrying it. The documented response, for a tool named delete_file, is:

JSON
{
  "jsonrpc": "2.0",
  "id": 42,
  "result": {
    "content": [
      { "type": "text", "text": "Tool 'delete_file' is blocked by the gateway. Do not retry this tool." }
    ],
    "isError": true,
    "_meta": {
      "com.microsoft.azure.ai.gateway/denial": {
        "code": "ToolNotAvailable",
        "correlationId": "9f2c1b6e-..."
      }
    }
  }
}

#Call a tool that's still allowed

Bash
./infra/call-tool.sh "$MCP_SERVER" learn_microsoft_docs_search '{"query":"What is Microsoft Agent 365?"}'
PowerShell
./infra/call-tool.ps1 -Server $MCP_SERVER -Tool learn_microsoft_docs_search `

The search returns results with isError: false.

#Turn the tool back on

In the admin center, on the learn server's Tools tab, enable learn_microsoft_docs_fetch again.

Checkpoint

While the tool was off, calls to it returned ToolNotAvailable and the other tools kept working.

#Block the whole server

During an incident, you may need to cut off every tool on a server at once. Blocking the server in Agent 365 inserts a managed return-response policy at the start of the server's inbound policy, so the gateway answers before it reaches any backend.

1

#Block the server in Agent 365

In the admin center, under Agents, select Tools, select the learn server, and select Block.

2

#Try to connect

Bash
./infra/call-tool.sh "$MCP_SERVER"
PowerShell
./infra/call-tool.ps1 -Server $MCP_SERVER
Expected output
MCP endpoint: https://<gateway>.eastus2-01.ai.gateway.azure.com/default/toolservers/learn/mcp
initialize: HTTP 403 (x-correlation-id: <guid>)
{
  "error": {
    "code": "AccessBlockedByGateway",
    "message": "Access to server 'learn' is blocked.",
    "target": "learn",
    "correlationId": "<guid>"
  }
}

The message names your server. Every request to the server, including initialize and tools/list, now returns 403.

3

#Unblock the server

In the admin center, select the learn server again and unblock it. Agent 365 removes the managed policy, and the script lists the tools again.

Checkpoint

While the server was blocked, every request returned 403 AccessBlockedByGateway. After you unblocked it, the handshake and tools/list succeed.

#Verify

1

#Confirm the inventory

In the admin center, under Agents›Tools, the learn server is listed with AI Gateway as its publisher, isn't blocked, and its Tools tab shows all three tools enabled.

2

#Confirm the server works end to end

Bash
./infra/call-tool.sh "$MCP_SERVER" learn_microsoft_docs_search '{"query":"What is Microsoft Agent 365?"}'
PowerShell
./infra/call-tool.ps1 -Server $MCP_SERVER -Tool learn_microsoft_docs_search `

tools/list returns the three tools, and the search returns isError: false.

#Trace a denial

Each denial carries a correlation ID, in the x-correlation-id response header and in the response body. Record it with the agent's logs, so you can match a blocked call with the gateway's runtime signals. If you set up Application Insights in Monitor usage, cost, and traces, Monitoring›Tools shows the server's tool executions and Traces shows each request.

#Go further

  • Close the side door. Agent 365 doesn't route agents through the gateway for you. Each agent must use the gateway's MCP endpoint, and a block only works if agents can't reach the MCP server directly. Restrict the backend so the gateway is its only caller, for example with private networking.
  • Add threat protection. On the AI Gateway tier, add Agent 365 tool threat protection so Microsoft Defender and Microsoft Purview evaluate the calls that you allow.
  • Decide who owns which switch. Agent 365 blocks are tenant-wide governance decisions. The gateway's own Blocked tools and MCP server access settings belong to the platform team. Write down which team uses which control, so a block set in one place isn't undone in the other.
  • Govern every server the same way. Prefer Select exact tools for servers that Agent 365 governs. New tools then stay unpublished until someone reviews and adds them.

#Clean up

1

#Clear Agent 365 blocks

In the admin center, make sure the learn server isn't blocked and all its tools are enabled. The gateway consent is tenant-wide, so leave it on if your organization plans to keep using the integration. Otherwise, ask a tenant administrator to review Azure API Management service and AI Gateway under Agents›Settings›Gateways.

2

#Restore the tool availability

In the AI Gateway portal, open MCP servers › learn › Edit›Tools. Select Allow all tools, then select Save.
