Foundations · Lab 01

Provision your AI Gateway

Create the shared AI Gateway that your apps and agents will call, from the AI Gateway portal, the Azure CLI, or Bicep, then take a guided tour of the portal.

Beginner 15 min PortalCLIBicep Updated Oct 23, 2026
Watch video Notebook Source Edit

What you'll do

  • Create an AI Gateway in East US 2 or Sweden Central from the portal, the Azure CLI, or Bicep
  • Find the gateway's runtime URL and its system-assigned managed identity
  • Confirm that the runtime endpoint answers over HTTPS
  • Navigate the AI Gateway portal and know which area manages what

Before you start

No prerequisite labs. Start here.

Tracks: Portal, Azure CLI, Bicep / azd

Your platform team is about to put every model and tool that the company's apps and agents use behind one governed entry point. Before anyone can publish a model, issue a key, or set a budget, you need the gateway itself. In this lab you create a shared AI Gateway, find its runtime URL and managed identity, and learn your way around the portal so you're ready for the rest of the labs.

#Before you begin

  • An Azure subscription with access to the AI Gateway preview. The AI Gateway tier is free during public preview. Connected services, such as Foundry inference and Application Insights, are billed normally.
  • Permission to create the gateway, for example Contributor on the resource group, or on the subscription if you create a new resource group. Creating a gateway needs write access to both API Management and connector gateways.
  • For the portal track: a browser and your Azure account.
  • For the CLI and IaC tracks and the Verify steps: the Azure CLI↗ 2.75 or later, signed in with az login, the aigateway extension↗, and jq for the Bash snippets.
  • Recommended reading: How AI Gateway works.

Install or upgrade the aigateway extension, then check that the CLI loads it. The installer downloads the published release, verifies it, and needs no Azure sign-in. Every later lab uses the same extension.

curl -fsSL https://aka.ms/aigateway-cli-install | sh
az aigateway version
irm https://aka.ms/aigateway-cli-install-ps | iex
az aigateway version

az aigateway version prints the extension version and the API version it calls, 2025-09-01-preview.

Note

The labs use az aigateway commands wherever the extension covers an operation. A few operations, such as registering a model or setting policies, aren't in the extension yet. For those, the labs call the Azure Resource Manager REST API with az rest and say why.

Set these variables once. Every track and the Verify section reuse them.

az account set --subscription "<subscription-id>"

export RG="<resource-group>"               # for example rg-ai-gateway-labs
export GATEWAY="<gateway>"                 # globally unique, 24 characters or fewer, part of the runtime URL
export LOCATION="<location>"               # eastus2 or swedencentral
export SUBSCRIPTION_ID="$(az account show --query id -o tsv)"
az account set --subscription "<subscription-id>"

$RG              = "<resource-group>"      # for example rg-ai-gateway-labs
$GATEWAY         = "<gateway>"             # globally unique, 24 characters or fewer, part of the runtime URL
$LOCATION        = "<location>"            # eastus2 or swedencentral
$SUBSCRIPTION_ID = az account show --query id -o tsv
Important

During public preview, AI Gateway is available in East US 2 (eastus2) and Sweden Central (swedencentral). Create the resource group in one of these regions so that defaults line up. The gateway name must be 1–24 characters: letters, digits, and hyphens, starting with a letter and not ending with a hyphen.

#How it works

An AI Gateway is an Azure Resource Manager resource of type Microsoft.ApiManagement/aigateways. You manage it in the AI Gateway portal↗, which is separate from the Azure portal, or through Azure Resource Manager with the CLI, REST, or Bicep. Each gateway has a companion connector gateway (Microsoft.Web/connectorGateways) with the same name, which is created first. The service sets the SKU and capacity itself, so the only real decisions are the name, the region, and the resource group.

PropertyValue
Resource typeMicrosoft.ApiManagement/aigateways (API version 2025-09-01-preview), plus Microsoft.Web/connectorGateways with the same name
Regions (preview)East US 2 (eastus2), Sweden Central (swedencentral)
Name1–24 characters: letters, digits, and hyphens. It becomes the first label of the runtime host name
Runtime URLhttps:// + properties.frontend.defaultHostname, for example https://<gateway>.eastus2-01.ai.gateway.azure.com
Runtime routesModels under /default/models/…, MCP servers under /default/toolservers/<server>/mcp
Outbound identityA system-assigned managed identity, used to call Foundry and other Microsoft Entra–protected backends
Provisioning timeA few minutes, often less

Everything you publish later lives in the gateway's default workspace. That's why every runtime route starts with /default/. Applications authenticate inbound with an API key or a Microsoft Entra token. The gateway authenticates outbound to each backend, usually with its managed identity, so apps never hold provider credentials.

#Create the gateway

Pick one track. Each track produces the same result: a gateway named <gateway> in <resource-group>, with a system-assigned managed identity.

Choose your track
1

#Sign in to the AI Gateway portal

Open the AI Gateway portal↗ and sign in with your Azure account. If this is your first gateway, the portal takes you straight into gateway creation. If you already have a gateway, open the gateway switcher in the top bar and start creating a new one from there.

2

#Enter the gateway details

In Create AI gateway, enter a globally unique Name of 24 characters or fewer, or select Generate a new name. Then choose the subscription, a Resource group (New or Existing), and the Region (East US 2 or Sweden Central). Under Advanced, keep Enable system-assigned managed identity selected, Public network access set to Enabled, and Public routing. Private routing connects the gateway to private backends through a virtual network and can only be chosen at creation. Lab 18 covers it.

Note

The subscription picker lists every subscription you can see. Subscriptions where you lack write permission for API Management and connector gateways are disabled, and the portal explains why.

3

#Watch it provision

Select Create gateway. The portal shows provisioning progress in place, and a new gateway is typically ready in a few minutes.

4

#Open the setup guide on Home

When provisioning finishes, Home opens with a setup guide for publishing models, adding MCP servers, and creating runtime access. Leave it for now. You publish your first model in the next lab, and the guide stays on Home until you finish it.

Checkpoint

The gateway switcher in the top bar shows <gateway>, and Home shows the setup guide.

1

#Register the resource providers

The gateway lives in the Microsoft.ApiManagement resource provider and its connector gateway in Microsoft.Web. Registering is a one-time step per subscription, and it returns quickly when a provider is already registered.

Bash
az provider register -n Microsoft.ApiManagement --wait
az provider register -n Microsoft.Web --wait
2

#Create a resource group

Bash
az group create --name "$RG" --location "$LOCATION"
3

#Create the connector gateway

Every AI gateway has a companion Microsoft.Web/connectorGateways resource with the same name. The portal and the Bicep template create it first, so do the same. The aigateway extension creates only the AI gateway, so create the connector gateway through the Azure Resource Manager REST API with az rest.

az rest --method put \
  --url "https://management.azure.com/subscriptions/$SUBSCRIPTION_ID/resourceGroups/$RG/providers/Microsoft.Web/connectorGateways/$GATEWAY?api-version=2026-05-01-preview" \
  --body "$(jq -cn --arg location "$LOCATION" '{location: $location, properties: {}}')"
@{ location = $LOCATION; properties = @{} } | ConvertTo-Json -Compress | Set-Content body.json
az rest --method put `
  --url "https://management.azure.com/subscriptions/$SUBSCRIPTION_ID/resourceGroups/$RG/providers/Microsoft.Web/connectorGateways/${GATEWAY}?api-version=2026-05-01-preview" `
  --body "@body.json"
Remove-Item body.json
4

#Create the AI gateway

az aigateway create only needs the name, the region, and the managed identity. There's no SKU, capacity, or publisher to set: the service picks them, and public network access is enabled. The command waits until provisioning finishes, usually within a few minutes.

az aigateway create -g "$RG" -n "$GATEWAY" --location "$LOCATION" --system-assigned true -o none
az aigateway create -g $RG -n $GATEWAY --location $LOCATION --system-assigned true -o none
Tip

Add --no-wait to return right away, then run az aigateway wait -g "$RG" -n "$GATEWAY" --created when you need the gateway.

5

#Read the runtime URL and identity

az aigateway show -g "$RG" -n "$GATEWAY" \
  --query "{name:name, location:location, state:properties.provisioningState, host:properties.frontend.defaultHostname, principalId:identity.principalId}" \
  -o table
az aigateway show -g $RG -n $GATEWAY `
  --query "{name:name, location:location, state:properties.provisioningState, host:properties.frontend.defaultHostname, principalId:identity.principalId}" `
  -o table
Checkpoint

The table shows Succeeded, a Host like <gateway>.eastus2-01.ai.gateway.azure.com, and a PrincipalId GUID.

1

#Review the template

The template creates what the portal creates: a Microsoft.Web/connectorGateways resource first, then the AI gateway (Microsoft.ApiManagement/aigateways) with the same name, a system-assigned identity, and public network access enabled. There's no SKU, capacity, or publisher to set. Keep both resources together in your own templates.

ParameterDescription
gatewayNameRequired. The gateway name, 24 characters or fewer
locationeastus2 (default) or swedencentral
tagsOptional. Tags applied to both resources
backendSubnetIdOptional. A subnet for outbound virtual network integration, which can only be set at creation. See Lab 18
infra/main.bicepGitHub
// Provisions an Azure AI Gateway (Microsoft.ApiManagement/aigateways) with a system-assigned managed
// identity, plus the companion connector gateway (Microsoft.Web/connectorGateways) with the same name.
// This matches what the AI Gateway portal creates: the connector gateway first, then the AI gateway.
targetScope = 'resourceGroup'

@description('Gateway name. It becomes the first label of the runtime host name, so use letters, numbers, and hyphens (max 24 characters).')
@minLength(1)
@maxLength(24)
param gatewayName string

@description('Region for the gateway. During public preview, Azure AI Gateway is available in East US 2 and Sweden Central.')
@allowed([
  'eastus2'
  'swedencentral'
])
param location string = 'eastus2'

@description('Tags applied to both resources.')
param tags object = {}

@description('Optional subnet resource ID for outbound virtual network integration. It can only be set when the gateway is created.')
param backendSubnetId string = ''

resource connectorGateway 'Microsoft.Web/connectorGateways@2026-05-01-preview' = {
  name: gatewayName
  location: location
  tags: tags
  properties: {}
}

resource aiGateway 'Microsoft.ApiManagement/aigateways@2025-09-01-preview' = {
  name: gatewayName
  location: location
  tags: tags
  identity: {
    type: 'SystemAssigned'
  }
  properties: union(
    {
      publicNetworkAccess: 'Enabled'
    },
    empty(backendSubnetId) ? {} : { backend: { subnet: { id: backendSubnetId } } }
  )
  dependsOn: [
    connectorGateway
  ]
}

output gatewayName string = aiGateway.name
output gatewayUrl string = 'https://${aiGateway.properties.frontend.defaultHostname}'
output gatewayId string = aiGateway.id
output principalId string = aiGateway.identity.principalId
output connectorGatewayId string = connectorGateway.id

On GitHub, open infra/main.bicep↗.

2

#Create a resource group

Bash
az group create --name "$RG" --location "$LOCATION"
3

#Deploy the template

Run the deployment from the lab folder. The template defaults location to eastus2, so pass your region explicitly.

az deployment group create -g "$RG" \
  --template-file infra/main.bicep \
  --parameters gatewayName="$GATEWAY" location="$LOCATION" \
  --query properties.outputs
az deployment group create -g $RG `
  --template-file infra/main.bicep `
  --parameters gatewayName=$GATEWAY location=$LOCATION `
  --query properties.outputs

Expected output (trimmed):

JSON
{
  "connectorGatewayId": { "type": "String", "value": "/subscriptions/<subscription-id>/resourceGroups/<resource-group>/providers/Microsoft.Web/connectorGateways/<gateway>" },
  "gatewayId":   { "type": "String", "value": "/subscriptions/<subscription-id>/resourceGroups/<resource-group>/providers/Microsoft.ApiManagement/aigateways/<gateway>" },
  "gatewayName": { "type": "String", "value": "<gateway>" },
  "gatewayUrl":  { "type": "String", "value": "https://<gateway>.eastus2-01.ai.gateway.azure.com" },
  "principalId": { "type": "String", "value": "00000000-0000-0000-0000-000000000000" }
}
Tip

BCP081 warnings about Microsoft.ApiManagement/aigateways and Microsoft.Web/connectorGateways mean that Bicep has no local type definitions for these preview resources. They don't block the deployment.

Checkpoint

The deployment succeeds and the outputs show gatewayUrl and principalId.

#Verify

1

#Call the runtime URL

Read the host name from the gateway rather than building it yourself, then send a request without a key. Any HTTP status proves that DNS, TLS, and the gateway are up. A new gateway with no models answers 404; after you add a model and a key in the next lab, a call without a key gets 400 or 401.

export AI_GATEWAY_URL="https://$(az aigateway show -g "$RG" -n "$GATEWAY" --query properties.frontend.defaultHostname -o tsv)"
echo "$AI_GATEWAY_URL"

curl -sS -o /dev/null -w "HTTP %{http_code}\n" "${AI_GATEWAY_URL%/}/default/models/openai/v1/chat/completions"
$env:AI_GATEWAY_URL = "https://$(az aigateway show -g $RG -n $GATEWAY --query properties.frontend.defaultHostname -o tsv)"
$env:AI_GATEWAY_URL

(Invoke-WebRequest -Uri "$($env:AI_GATEWAY_URL.TrimEnd('/'))/default/models/openai/v1/chat/completions" `
  -SkipHttpErrorCheck).StatusCode

A Could not resolve host error means the gateway isn't ready yet. Wait a minute and try again.

2

#Find the gateway on Home

Open the AI Gateway portal↗. If you created the gateway with the CLI or Bicep, select it in the gateway switcher in the top bar. Home shows the setup guide for your new gateway.

3

#Check the managed identity

Select Managed identities. On the Configure identities tab, the system-assigned identity is enabled. Its principal ID matches principalId from the CLI or Bicep output. In later labs you grant this identity access to Foundry so that the gateway can call your models without keys.

Checkpoint

The runtime URL answers with an HTTP status, the gateway appears on Home, and Managed identities shows the system-assigned identity enabled.

#Go further

  • One gateway per environment. Repeat the IaC track with a different gatewayName for dev, test, and production, and keep the template in source control next to your app.

  • Tag for ownership and chargeback. The template's tags parameter applies the same tags to the gateway and its connector gateway, so set them when you create each environment's gateway:

    Bash
    az deployment group create -g "$RG" --template-file infra/main.bicep \
  --parameters gatewayName="$GATEWAY" location="$LOCATION" \
               tags='{"workload":"ai-gateway-labs","owner":"platform-team","costCenter":"1234"}'

  • Use a user-assigned identity. When several gateways must share one backend identity, add a user-assigned identity on Managed identities. See Call backends with managed identities.

#Clean up

The gateway is free during preview, and every later lab reuses it. Keep it until you finish the labs you plan to do.

When you're done with all the labs, delete the resource group. That removes the gateway, its connector gateway, and everything else in the group. The command asks for confirmation.

az group delete --name "$RG"
az group delete --name $RG

To keep the resource group, delete the AI gateway first and then its connector gateway. Deleting the gateway also deletes everything you published on it.

az aigateway delete -g "$RG" -n "$GATEWAY" --yes
az resource delete -g "$RG" -n "$GATEWAY" --resource-type Microsoft.Web/connectorGateways --api-version 2026-05-01-preview
az aigateway delete -g $RG -n $GATEWAY --yes
az resource delete -g $RG -n $GATEWAY --resource-type Microsoft.Web/connectorGateways --api-version 2026-05-01-preview

#Troubleshooting

SymptomLikely causeFix
Your subscription is disabled in the portal's subscription pickerYou lack write permission for API Management or connector gateways in that subscriptionAsk for Contributor on the subscription or resource group, or pick another subscription.
The deployment fails because the region isn't supported$LOCATION or the template's location is outside the preview regionsUse eastus2 or swedencentral. The template accepts only these two values and defaults to eastus2.
The name is rejectedGateway names are globally unique and limited to 24 characters: letters, digits, and hyphens, starting with a letterPick another name that follows the rules.
MissingSubscriptionRegistrationA resource provider isn't registered in the subscriptionRun az provider register -n Microsoft.ApiManagement --wait and az provider register -n Microsoft.Web --wait, or ask your subscription administrator.
Could not resolve host when you call the URLProvisioning or DNS isn't finishedRun az aigateway wait -g "$RG" -n "$GATEWAY" --created and retry.
'aigateway' is misspelled or not recognized by the systemThe aigateway extension isn't installedRun the installer from Before you begin, then az aigateway version.
