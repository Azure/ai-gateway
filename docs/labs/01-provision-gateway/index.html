Provision your AI Gateway

Create the shared AI Gateway that your apps and agents will call, from the AI Gateway portal, the Azure CLI, or Bicep, then take a guided tour of the portal.

Beginner 15 min PortalCLIBicep Updated Oct 14, 2026
Source Edit

What you'll do

  • Create an AI Gateway in East US 2 or Sweden Central from the portal, the Azure CLI, or Bicep
  • Find the gateway's runtime URL and its system-assigned managed identity
  • Confirm that the runtime endpoint answers over HTTPS
  • Navigate the AI Gateway portal and know which area manages what

Before you start

No prerequisite labs. Start here.

Tracks: Portal, Azure CLI, Bicep / azd

Your platform team is about to put every model and tool that the company's apps and agents use behind one governed entry point. Before anyone can publish a model, issue a key, or set a budget, you need the gateway itself. In this lab you create a shared AI Gateway, find its runtime URL and managed identity, and learn your way around the portal so you're ready for the rest of the labs.

#Before you begin

  • An Azure subscription with access to the AI Gateway preview. The AI Gateway tier is free during public preview. Connected services, such as Foundry inference and Application Insights, are billed normally.
  • Permission to create the gateway, for example Contributor on the resource group, or on the subscription if you create a new resource group. Creating a gateway needs write access to both API Management and connector gateways.
  • For the portal track: a browser and your Azure account.
  • For the CLI and IaC tracks: the Azure CLI↗ 2.75 or later, signed in with az login. The CLI track and the Verify section also use the aigateway extension (install it↗).
  • Recommended reading: How AI Gateway works.

Set these variables once. Every track and the Verify section reuse them.

az account set --subscription "<subscription-id>"

export RG="<resource-group>"               # for example rg-ai-gateway-labs
export GATEWAY="<gateway>"                 # globally unique, it becomes part of the runtime URL
export LOCATION="<location>"               # eastus2 or swedencentral
az account set --subscription "<subscription-id>"

$RG       = "<resource-group>"             # for example rg-ai-gateway-labs
$GATEWAY  = "<gateway>"                    # globally unique, it becomes part of the runtime URL
$LOCATION = "<location>"                   # eastus2 or swedencentral
Important

During public preview, AI Gateway is available in East US 2 (eastus2) and Sweden Central (swedencentral). Create the resource group in one of these regions so that defaults line up.

#How it works

An AI Gateway is an Azure API Management service that runs the AI Gateway tier (SKU AIGateway). You manage it in the AI Gateway portal↗, which is separate from the Azure portal, or through Azure Resource Manager with the CLI, REST, or Bicep. The capacity is defined by the service, so the only real decisions are the name, the region, and the resource group.

PropertyValue
Resource typeMicrosoft.ApiManagement/service with SKU AIGateway
Regions (preview)East US 2 (eastus2), Sweden Central (swedencentral)
Runtime URLproperties.gatewayUrl, for example https://<gateway>.azure-api.net
Runtime routesModels under /default/models/…, MCP servers under /default/toolservers/<server>/mcp
Outbound identityA system-assigned managed identity, used to call Foundry and other Microsoft Entra–protected backends
Provisioning timeAbout a minute

Everything you publish later lives in the gateway's default workspace. That's why every runtime route starts with /default/. Applications authenticate inbound with an API key or a Microsoft Entra token. The gateway authenticates outbound to each backend, usually with its managed identity, so apps never hold provider credentials.

#Create the gateway

Pick one track. Each track produces the same result: a gateway named <gateway> in <resource-group>, with a system-assigned managed identity.

Choose your track
1

#Sign in to the AI Gateway portal

Open the AI Gateway portal↗ and sign in with your Azure account. If this is your first gateway, the portal takes you straight into gateway creation. If you already have a gateway, open the gateway switcher in the top bar and start creating a new one from there.

2

#Enter the gateway details

Choose the subscription, the resource group, a globally unique gateway name, and the region (East US 2 or Sweden Central).

Note

The subscription picker lists every subscription you can see. Subscriptions where you lack write permission for API Management and connector gateways are disabled, and the portal explains why.

3

#Watch it provision

Create the gateway. The portal shows provisioning progress in place, and a new gateway is typically ready in about a minute.

4

#Open the setup guide on Home

When provisioning finishes, Home opens with a setup guide for publishing models, adding MCP servers, and creating runtime access. Leave it for now. You publish your first model in the next lab, and the guide stays on Home until you finish it.

Checkpoint

The gateway switcher in the top bar shows <gateway>, and Home shows the setup guide.

1

#Create a resource group

Bash
az group create --name "$RG" --location "$LOCATION"
2

#Start creating the gateway

az aigateway create selects the AI Gateway SKU for you. --no-wait returns as soon as Azure accepts the request, which is handy in scripts. Leave it out and the command waits for provisioning instead.

Bash
az aigateway create -g "$RG" -n "$GATEWAY" --location "$LOCATION" \
  --system-assigned true --tags workload=ai-gateway-labs owner=platform-team \
  --no-wait

The managed identity is shown explicitly here. --publisher-email and --publisher-name are optional and default to noreply@aigateway.azure.com and AI Gateway Administrator.

3

#Wait for provisioning

Bash
az aigateway wait -g "$RG" -n "$GATEWAY" --created --interval 15

The command returns when provisioningState reaches Succeeded, usually in about a minute.

4

#Read the runtime URL and identity

Bash
az aigateway show -g "$RG" -n "$GATEWAY" \
  --query "{name:name, location:location, state:properties.provisioningState, url:properties.gatewayUrl, principalId:identity.principalId}" \
  -o table
Checkpoint

The table shows Succeeded, a url that starts with https://, and a principalId GUID.

1

#Review the template

The template mirrors the reference sample↗: an API Management service with SKU AIGateway, capacity 1, and a system-assigned identity, plus a Microsoft.Web/connectorGateways resource with the same name. Keep both resources together in your own templates.

infra/main.bicepGitHub
// Provisions an Azure AI Gateway: an API Management service with the AIGateway SKU and a system-assigned
// managed identity, plus the companion connector gateway resource with the same name.
// Mirrors infra/ai-gateway/main.bicep in the reference sample
// (https://github.com/Azure-Samples/simple-foundry-hosted-agent-python-aigateway).
targetScope = 'resourceGroup'

@description('Globally unique gateway name. It becomes part of the runtime URL, so use letters, numbers, and hyphens.')
@minLength(1)
@maxLength(50)
param gatewayName string

@description('Region for the gateway. During public preview, use eastus2 (East US 2) or swedencentral (Sweden Central).')
param location string = resourceGroup().location

@description('Tags applied to the gateway.')
param tags object = {}

@description('Publisher email required by the underlying API Management service.')
param publisherEmail string = 'noreply@example.com'

@description('Publisher name required by the underlying API Management service.')
param publisherName string = 'AI Gateway'

resource aiGateway 'Microsoft.ApiManagement/service@2025-09-01-preview' = {
  name: gatewayName
  location: location
  tags: tags
  identity: {
    type: 'SystemAssigned'
  }
  sku: {
    name: 'AIGateway'
    capacity: 1
  }
  properties: {
    publisherEmail: publisherEmail
    publisherName: publisherName
  }
}

resource connectorGateway 'Microsoft.Web/connectorGateways@2026-05-01-preview' = {
  name: gatewayName
  location: location
  properties: {}
  dependsOn: [
    aiGateway
  ]
}

output gatewayName string = aiGateway.name
output gatewayUrl string = aiGateway.properties.gatewayUrl
output gatewayId string = aiGateway.id
output principalId string = aiGateway.identity.principalId
output connectorGatewayId string = connectorGateway.id

On GitHub, open infra/main.bicep↗.

2

#Create a resource group

Bash
az group create --name "$RG" --location "$LOCATION"
3

#Deploy the template

Run the deployment from the lab folder. The gateway inherits the resource group's region unless you pass location.

az deployment group create -g "$RG" \
  --template-file infra/main.bicep \
  --parameters gatewayName="$GATEWAY" \
  --query properties.outputs
az deployment group create -g $RG `
  --template-file infra/main.bicep `
  --parameters gatewayName=$GATEWAY `
  --query properties.outputs

Expected output (trimmed):

JSON
{
  "gatewayName": { "type": "String", "value": "<gateway>" },
  "gatewayUrl":  { "type": "String", "value": "https://<gateway>.azure-api.net" },
  "gatewayId":   { "type": "String", "value": "/subscriptions/<subscription-id>/resourceGroups/<resource-group>/providers/Microsoft.ApiManagement/service/<gateway>" },
  "principalId": { "type": "String", "value": "00000000-0000-0000-0000-000000000000" }
}
Tip

BCP081 warnings about Microsoft.Web/connectorGateways mean that Bicep has no local type definitions for this preview resource. They don't block the deployment.

Checkpoint

The deployment succeeds and the outputs show gatewayUrl and principalId.

#Verify

1

#Call the runtime URL

Read the URL from the gateway rather than building it yourself, then send a request without a key. Any HTTP status, typically 401, proves that DNS, TLS, and the gateway are up. You add a model and a key in the next lab.

export AI_GATEWAY_URL="$(az aigateway show -g "$RG" -n "$GATEWAY" --query properties.gatewayUrl -o tsv)"
echo "$AI_GATEWAY_URL"

curl -sS -o /dev/null -w "HTTP %{http_code}\n" "${AI_GATEWAY_URL%/}/default/models/openai/v1/chat/completions"
$env:AI_GATEWAY_URL = az aigateway show -g $RG -n $GATEWAY --query properties.gatewayUrl -o tsv
$env:AI_GATEWAY_URL

(Invoke-WebRequest -Uri "$($env:AI_GATEWAY_URL.TrimEnd('/'))/default/models/openai/v1/chat/completions" `
  -SkipHttpErrorCheck).StatusCode

A Could not resolve host error means the gateway isn't ready yet. Wait a minute and try again.

2

#Find the gateway on Home

Open the AI Gateway portal↗. If you created the gateway with the CLI or Bicep, select it in the gateway switcher in the top bar. Home shows the setup guide for your new gateway.

3

#Check the managed identity

Select Managed identities. On the Configure identities tab, the system-assigned identity is enabled. Its principal ID matches principalId from the CLI or Bicep output. In later labs you grant this identity access to Foundry so that the gateway can call your models without keys.

4

The runtime URL answers with an HTTP status, the gateway appears on Home, and Managed identities shows the system-assigned identity enabled.

#Go further

  • One gateway per environment. Repeat the IaC track with a different gatewayName for dev, test, and production, and keep the template in source control next to your app.

  • Tag for ownership and chargeback. az aigateway update sets tags, and it replaces the whole tag set, so include every tag you want to keep:

    Bash
    az aigateway update -g "$RG" -n "$GATEWAY" --tags workload=ai-gateway-labs owner=platform-team costCenter=1234

  • Use a user-assigned identity. When several gateways must share one backend identity, add a user-assigned identity on Managed identities. See Call backends with managed identities.

#Clean up

The gateway is free during preview, and every later lab reuses it. Keep it until you finish the labs you plan to do.

When you're done with all the labs, delete the resource group. That removes the gateway and everything else in the group. The command asks for confirmation.

az group delete --name "$RG"
az group delete --name $RG

Deleting a gateway keeps an API Management soft-delete record, so the name might not be reusable right away. To reuse the name immediately, purge the record. Purging is permanent.

Bash
az apim deletedservice purge --service-name "$GATEWAY" --location "$LOCATION"

#Troubleshooting

SymptomLikely causeFix
Your subscription is disabled in the portal's subscription pickerYou lack write permission for API Management or connector gateways in that subscriptionAsk for Contributor on the subscription or resource group, or pick another subscription.
The deployment fails because the region isn't supportedThe resource group or --location is outside the preview regionsUse eastus2 or swedencentral. In Bicep, pass location=eastus2 if the resource group is elsewhere.
The name is rejected as unavailableGateway names are globally unique, or a soft-deleted gateway still holds the namePick another name, or purge your own soft-deleted gateway with az apim deletedservice purge.
MissingSubscriptionRegistrationThe resource provider isn't registered in the subscriptionRun az provider register --namespace Microsoft.ApiManagement (and Microsoft.Web for the Bicep track), or ask your subscription administrator.
Could not resolve host when you call the URLProvisioning or DNS isn't finishedRun az aigateway wait -g "$RG" -n "$GATEWAY" --created and retry.
az aigateway: 'create' is misspelled or not recognizedThe CLI extension isn't installedInstall the extension↗ and run az aigateway version.
