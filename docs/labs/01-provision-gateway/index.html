Provision your AI Gateway

Create the shared AI Gateway that your apps and agents will call, from the AI Gateway portal, the Azure CLI, or Bicep and azd, then take a guided tour of the portal.

Beginner 15 min PortalCLIBicep Updated Oct 28, 2026
Watch video Notebook Source Edit

What you'll do

  • Find the regions where AI Gateway is available, and create a gateway in one from the portal, the Azure CLI, or Bicep and azd
  • Find the gateway's runtime URL and its system-assigned managed identity
  • Confirm that the runtime endpoint answers over HTTPS
  • Navigate the AI Gateway portal and know which area manages what

Before you start

No prerequisite labs. Start here.

Tracks: Portal, Azure CLI, Bicep + azd

Your platform team is about to put every model and tool that the company's apps and agents use behind one governed entry point. Before anyone can publish a model, issue a key, or set a budget, you need the gateway itself. In this lab you create a shared AI Gateway, find its runtime URL and managed identity, and learn your way around the portal so you're ready for the rest of the labs.

Important

Create the resource group in the same region as the gateway, so that defaults line up. The gateway name must be 1–24 characters: letters, digits, and hyphens, starting with a letter and not ending with a hyphen.

#How it works

An AI Gateway is an Azure Resource Manager resource of type Microsoft.ApiManagement/aigateways. You manage it in the AI Gateway portal↗, which is separate from the Azure portal, or through Azure Resource Manager with the CLI, REST, or Bicep. Each gateway has a companion connector gateway (Microsoft.Web/connectorGateways) with the same name. There's no capacity to size, so the only real decisions are the name, the region, and the resource group.

PropertyValue
Resource typeMicrosoft.ApiManagement/aigateways (API version 2025-09-01-preview), plus Microsoft.Web/connectorGateways with the same name
RegionsThe list grows over time. List them as in Find the available regions
Name1–24 characters: letters, digits, and hyphens. It becomes the first label of the runtime host name
Runtime URLhttps:// + properties.frontend.defaultHostname, for example https://<gateway>.eastus2-01.ai.gateway.azure.com
Runtime routesModels under /default/models/…, MCP servers under /default/toolservers/<server>/mcp
Outbound identityA system-assigned managed identity, used to call Foundry and other Microsoft Entra–protected backends
SKUConsumption, which az aigateway create and the Bicep templates set. A template that omits sku creates a Premium gateway
Provisioning timeA few minutes, often less

Everything you publish later lives in the gateway's default workspace. That's why every runtime route starts with /default/. Applications authenticate inbound with an API key or a Microsoft Entra token. The gateway authenticates outbound to each backend, usually with its managed identity, so apps never hold provider credentials.

#Create the gateway

Pick one track. Each track produces the same result: a gateway named <gateway> in <resource-group>, with a system-assigned managed identity. The Bicep + azd track picks the names for you: aigw- plus six unique characters, in rg-aigw-lab01.

1

#Sign in to the AI Gateway portal

Open the AI Gateway portal↗ and sign in with your Azure account. If this is your first gateway, the portal takes you straight into gateway creation. If you already have a gateway, open the gateway switcher in the top bar and start creating a new one from there.

2

#Enter the gateway details

In Create AI gateway, enter a globally unique Name of 24 characters or fewer, or select Generate a new name. Then choose the subscription, a Resource group (New or Existing), and the Region. Under Advanced, keep Enable system-assigned managed identity selected, Public network access set to Enabled, and Public routing. Private routing connects the gateway to private backends through a virtual network and can only be chosen at creation. Lab 18 covers it.

Note

The subscription picker lists every subscription you can see. Subscriptions where you lack write permission for API Management and connector gateways are disabled, and the portal explains why.

3

#Watch it provision

Select Create gateway. The portal shows provisioning progress in place, and a new gateway is typically ready in a few minutes.

4

#Open the setup guide on Home

When provisioning finishes, Home opens with a setup guide for publishing models, adding MCP servers, and creating runtime access. Leave it for now. You publish your first model in the next lab, and the guide stays on Home until you finish it.

Checkpoint

The gateway switcher in the top bar shows <gateway>, and Home shows the setup guide.

#Create a resource group

Bash
# Create the resource group that holds the gateway, in the gateway's region
az group create --name "$RG" --location "$LOCATION" --output none &&
  echo "📦 Resource group $RG is ready in $LOCATION"
2

#Create the connector gateway

Every AI gateway has a companion Microsoft.Web/connectorGateways resource with the same name, and either one can be created first. The aigateway extension creates only the AI gateway, so create the connector gateway through the Azure Resource Manager REST API with az rest.

# Create the companion connector gateway through the REST API, because the aigateway extension doesn't create it
az rest --method put --output none \
  --url "https://management.azure.com/subscriptions/$SUBSCRIPTION_ID/resourceGroups/$RG/providers/Microsoft.Web/connectorGateways/$GATEWAY?api-version=2026-05-01-preview" \
  --body "$(jq -cn --arg location "$LOCATION" '{location: $location, properties: {}}')" &&
  echo "🔌 Connector gateway $GATEWAY is ready"
# Write the request body to a file, so that PowerShell passes the JSON to az rest unchanged
@{ location = $LOCATION; properties = @{} } | ConvertTo-Json -Compress | Set-Content body.json

# Create the companion connector gateway through the REST API, because the aigateway extension doesn't create it
az rest --method put --output none `
  --url "https://management.azure.com/subscriptions/$SUBSCRIPTION_ID/resourceGroups/$RG/providers/Microsoft.Web/connectorGateways/${GATEWAY}?api-version=2026-05-01-preview" `
  --body "@body.json"
if ($?) { Write-Host "🔌 Connector gateway $GATEWAY is ready" }
Remove-Item body.json
3

#Create the AI gateway

az aigateway create only needs the name, the region, and the managed identity. It creates the gateway in the Consumption SKU, and there's no capacity or publisher to set. The command waits until provisioning finishes, usually within a few minutes.

# Create the gateway with a system-assigned managed identity, and wait until it's provisioned
az aigateway create -g "$RG" -n "$GATEWAY" --location "$LOCATION" --system-assigned true -o none &&
  echo "🚀 Gateway $GATEWAY is ready in $LOCATION"
# Create the gateway with a system-assigned managed identity, and wait until it's provisioned
az aigateway create -g $RG -n $GATEWAY --location $LOCATION --system-assigned true -o none
if ($?) { Write-Host "🚀 Gateway $GATEWAY is ready in $LOCATION" }
Tip

Add --no-wait to return right away, then run az aigateway wait -g "$RG" -n "$GATEWAY" --created when you need the gateway.

#Review the template

infra/gateway.bicep declares the gateway. It follows the AI Gateway reference sample↗. It creates the AI gateway (Microsoft.ApiManagement/aigateways) in the Consumption SKU with a system-assigned identity, then a Microsoft.Web/connectorGateways resource with the same name. There's no capacity or publisher to set. Keep both resources together in your own templates, and set sku: without it, the gateway is created in the Premium SKU.

ParameterDescription
gatewayNameRequired. The gateway name, 24 characters or fewer
locationeastus2 (default), or another region where AI Gateway is available
tagsOptional. Tags applied to both resources
backendSubnetIdOptional. A subnet for outbound virtual network integration, which can only be set at creation. See Lab 18
infra/gateway.bicepGitHub
// Provisions an Azure AI Gateway (Microsoft.ApiManagement/aigateways) in the Consumption SKU with a
// system-assigned managed identity, then the companion connector gateway (Microsoft.Web/connectorGateways)
// with the same name. This follows the AI Gateway reference sample:
// https://github.com/Azure-Samples/simple-foundry-hosted-agent-python-aigateway/blob/main/infra/ai-gateway/main.bicep
// The lab's main.bicep calls it with azd, and other labs call it as a module. You can also deploy it on its own
// to an existing resource group with "az deployment group create".
targetScope = 'resourceGroup'

@description('Gateway name. It becomes the first label of the runtime host name, so use letters, numbers, and hyphens (max 24 characters).')
@minLength(1)
@maxLength(24)
param gatewayName string

@description('Region for the gateway. Pick one where AI Gateway is available. List them with az provider show --namespace Microsoft.ApiManagement (Setup guide, Find the available regions).')
param location string = 'eastus2'

@description('Tags applied to both resources.')
param tags object = {}

@description('Optional subnet resource ID for outbound virtual network integration. It can only be set when the gateway is created.')
param backendSubnetId string = ''

#disable-next-line BCP081
resource aiGateway 'Microsoft.ApiManagement/aigateways@2025-09-01-preview' = {
  name: gatewayName
  location: location
  tags: tags
  identity: {
    type: 'SystemAssigned'
  }
  sku: {
    name: 'Consumption'
  }
  properties: empty(backendSubnetId) ? {} : { backend: { subnet: { id: backendSubnetId } } }
}

#disable-next-line BCP081
resource connectorGateway 'Microsoft.Web/connectorGateways@2026-05-01-preview' = {
  name: gatewayName
  location: location
  tags: tags
  properties: {}
  dependsOn: [
    aiGateway
  ]
}

output gatewayName string = aiGateway.name
output gatewayUrl string = 'https://${aiGateway.properties.frontend.defaultHostname}'
output gatewayId string = aiGateway.id
output principalId string = aiGateway.identity.principalId
output connectorGatewayId string = connectorGateway.id

infra/main.bicep is the template that azd deploys. It creates the resource group rg-<environment name>, then calls infra/gateway.bicep with the name aigw- plus six characters that are unique to your subscription, environment, and region. Its outputs become azd environment values:

infra/main.bicepGitHub
// Lab 01 with azd: "azd up" creates the resource group rg-<environment name>, then calls gateway.bicep to create
// an AI gateway with a unique name and its connector gateway.
targetScope = 'subscription'

@description('azd environment name. The resource group is rg-<environmentName>.')
@minLength(1)
@maxLength(60)
param environmentName string

@description('Region for every resource. Pick one where AI Gateway is available. List them with az provider show --namespace Microsoft.ApiManagement (Setup guide, Find the available regions).')
@metadata({ azd: { type: 'location' } })
param location string

var suffix = take(uniqueString(subscription().id, environmentName, location), 6)
var tags = { 'azd-env-name': environmentName }

resource rg 'Microsoft.Resources/resourceGroups@2024-03-01' = {
  name: 'rg-${environmentName}'
  location: location
  tags: tags
}

// The lab's template: the gateway in the Consumption SKU with a system-assigned identity, then its connector gateway.
module gateway 'gateway.bicep' = {
  name: 'aigw-gateway'
  scope: rg
  params: {
    gatewayName: 'aigw-${suffix}'
    location: location
    tags: tags
  }
}

output AZURE_RESOURCE_GROUP string = rg.name
output AI_GATEWAY_NAME string = gateway.outputs.gatewayName
output AI_GATEWAY_ID string = gateway.outputs.gatewayId
output AI_GATEWAY_URL string = gateway.outputs.gatewayUrl
output AI_GATEWAY_PRINCIPAL_ID string = gateway.outputs.principalId

Later labs reuse infra/gateway.bicep as a module. You can also deploy it on its own to a resource group you already have, with az deployment group create, as Go further shows.

Tip

Bicep has no type definitions yet for Microsoft.ApiManagement/aigateways and Microsoft.Web/connectorGateways. As in the reference sample, each #disable-next-line BCP081 line silences the warning about it. Without these lines, the build shows BCP081 warnings, which don't block the deployment.

#Verify

1

#Call the runtime URL

Read the host name from the gateway rather than building it yourself, then send a request without a key. Any HTTP status proves that DNS, TLS, and the gateway are up. A new gateway with no models answers 404; after you add a model and a key in the next lab, a call without a key gets 400 or 401.

# Read the runtime host name from the gateway, and build the runtime URL from it
export AI_GATEWAY_URL="https://$(az aigateway show -g "$RG" -n "$GATEWAY" --query properties.frontend.defaultHostname -o tsv)"
echo "🌐 Runtime URL: $AI_GATEWAY_URL"

# Call the Chat Completions route without a key, and print only the HTTP status that the gateway answers with
curl -sS -o /dev/null -w "🌐 The gateway answered: HTTP %{http_code}\n" "${AI_GATEWAY_URL%/}/default/models/openai/v1/chat/completions"
# Read the runtime host name from the gateway, and build the runtime URL from it
$env:AI_GATEWAY_URL = "https://$(az aigateway show -g $RG -n $GATEWAY --query properties.frontend.defaultHostname -o tsv)"
Write-Host "🌐 Runtime URL: $env:AI_GATEWAY_URL"

# Call the Chat Completions route without a key, and print only the HTTP status that the gateway answers with
$status = (Invoke-WebRequest -Uri "$($env:AI_GATEWAY_URL.TrimEnd('/'))/default/models/openai/v1/chat/completions" `
  -SkipHttpErrorCheck).StatusCode
if ($?) { Write-Host "🌐 The gateway answered: HTTP $status" }

A Could not resolve host error means the gateway isn't ready yet. Wait a minute and try again.

#Go further

  • One gateway per environment. Run azd env new <name> and azd up once for each of dev, test, and production: every azd environment gets its own resource group and gateway. Keep the template in source control next to your app.

  • Tag for ownership and chargeback. The template's tags parameter applies the same tags to the gateway and its connector gateway, so set them when you create each environment's gateway. To add them to the gateway you have, deploy infra/gateway.bicep on its own from the lab folder:

    Bash
    # Deploy the gateway's template again with tags, which updates the gateway and its connector gateway in place
az deployment group create -g "$RG" --template-file infra/gateway.bicep --output none \
  --parameters gatewayName="$GATEWAY" location="$LOCATION" \
               tags='{"workload":"ai-gateway-labs","owner":"platform-team","costCenter":"1234"}' &&
  echo "📝 Tags are set on gateway $GATEWAY and its connector gateway"

  • Use a user-assigned identity. When several gateways must share one backend identity, add a user-assigned identity on Managed identities. See Call backends with managed identities.
