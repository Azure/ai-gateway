Build on your gateway with coding agents

Install the AI Gateway plugin in GitHub Copilot CLI, Claude Code, Cursor, or Gemini CLI, then let your coding agent discover the gateway's models and MCP tools and generate working client code.

Beginner 15 min Code Updated Oct 28, 2026
Source Edit

What you'll do

  • Install the AI Gateway plugin in your coding agent
  • Discover a gateway's models and MCP tool servers from its Azure resource ID
  • Generate and run app code that calls the gateway with a runtime key
  • Review generated code for the right endpoint, model name, and secret handling

Before you start

  • 02Publish a Foundry model and make your first call

Tracks: Code

Your platform team publishes models and MCP tools behind AI Gateway, and product developers want to use them without reading gateway settings or passing keys around in chat. The AI Gateway plugin teaches coding agents such as GitHub Copilot CLI, Claude Code, Cursor, and Gemini CLI what your gateway offers. It then generates code that uses the right endpoint, model name, and auth header. The plugin only reads from the gateway, so developers build on top of your governance instead of around it.

#Before you begin

One-time setupThe Setup guide tasks that this lab uses. Mark each one done once, and the labs stop listing it.

  • Choose where to run commandsEvery track except the portal
  • Sign in to AzureOn your own machine. Cloud Shell is already signed in.
  • Install the aigateway extensionThe Azure CLI tracks and the Verify steps

You've done the one-time setup that this lab uses.

  • Complete Publish a Foundry model and make your first call. You need the gateway, a model that answers, and its alias.
  • Optional: complete Federate MCP tools behind one endpoint so the gateway also has MCP tools to discover.
  • One coding agent, installed and signed in: GitHub Copilot CLI, Claude Code, Cursor, or Gemini CLI. Each agent documents its plugin support: GitHub Copilot CLI↗, Claude Code↗, Cursor↗, and Gemini CLI↗.
  • Read access to the gateway: the plugin uses your Azure sign-in to read it.
  • Python 3.10 or later to run the generated app. To scaffold a standalone agent, you also need the GitHub Copilot CLI, because the GitHub Copilot SDK uses it.

Set these variables in the shell that you'll start your coding agent from. Create a key for this app so you can revoke it on its own later.

# Name your gateway and the alias that the generated app calls
export RG="<resource-group>"
export GATEWAY="<gateway>"
export AI_GATEWAY_MODEL="<model-name>"   # the alias from lab 02
echo "📝 Gateway $GATEWAY in $RG, alias $AI_GATEWAY_MODEL"

# Read the gateway's resource ID, which you pass to the plugin, and its runtime URL, which the app calls
export GATEWAY_ID="$(az aigateway show -g "$RG" -n "$GATEWAY" --query id -o tsv)"
export AI_GATEWAY_URL="https://$(az aigateway show -g "$RG" -n "$GATEWAY" --query properties.frontend.defaultHostname -o tsv)"
echo "🌐 Runtime URL: $AI_GATEWAY_URL"

# Create an API key for this app, so that you can revoke it on its own later
az aigateway api-key create -g "$RG" --gateway-name "$GATEWAY" -n app-coding-agent --display-name app-coding-agent -o none &&
  echo "🔑 API key app-coding-agent is ready"

# Read the key into an environment variable, so that it never shows on screen
AI_GATEWAY_API_KEY="$(az aigateway api-key list-secrets -g "$RG" --gateway-name "$GATEWAY" -n app-coding-agent \
  --query primaryKey -o tsv)" && export AI_GATEWAY_API_KEY
echo "🔑 Key: in AI_GATEWAY_API_KEY (${#AI_GATEWAY_API_KEY} characters, not shown)"
# Name your gateway and the alias that the generated app calls
$RG      = "<resource-group>"
$GATEWAY = "<gateway>"

Then print the gateway's Azure resource ID. You pass it to the plugin.

# Print the gateway's resource ID, to copy into the plugin's commands
echo "🆔 Gateway resource ID: $GATEWAY_ID"
# Print the gateway's resource ID, to copy into the plugin's commands
Write-Host "🆔 Gateway resource ID: $GATEWAY_ID"

The ID looks like /subscriptions/<subscription-id>/resourceGroups/<resource-group>/providers/Microsoft.ApiManagement/aigateways/<gateway>.

#How it works

The plugin bundles one skill and two commands. The skill holds the know-how: which endpoints to call, which model name the gateway accepts, and how to send the key. The commands run that skill for a task.

Discovery goes through Azure Resource Manager, which is why the plugin needs the resource ID and your Azure sign-in. Your app then calls the gateway's runtime URL with a runtime key, like any other client. The plugin is read-only against the gateway: it never creates, updates, or deletes gateways, models, tools, or keys. Creating those stays an administrator task in the AI Gateway portal↗.

PieceInvoked asWhat it does
Skill use-ai-gateway/ai-gateway:use-ai-gatewayThe full discover, select, credential, and integrate workflow. The commands use it too.
Command discover/ai-gateway:discover <resource ID>Lists the gateway's models and MCP tool servers and suggests the ones that fit your use case. Stops there.
Command build/ai-gateway:build <resource ID> <description>Discovers, gets a key, integrates the assets into your app, then runs the code once to check it.

What the generated code relies on:

ItemValue
Model base URL (OpenAI-compatible)<gateway URL>/default/models/openai/v1
MCP endpoint<gateway URL>/default/toolservers/<server-name>/mcp
Auth headerapi-key: <runtime key>. The plugin writes it as Api-Key; header names aren't case-sensitive.
Key sourceThe AI_GATEWAY_API_KEY environment variable, loaded from a git-ignored .env file
Model nameThe model's deployment name as the gateway publishes it, for example gpt-6-luna
Agent scaffoldGitHub Copilot SDK, github-copilot-sdk>=1.0.0, Python unless you ask for TypeScript

#Install the plugin

1

#Create a project folder

Start in an empty folder with Git, so you can check later that no secret gets committed.

# Create the project folder, move into it, and start a Git repository quietly
mkdir ticket-summarizer && cd ticket-summarizer && git init -q &&
  echo "📂 Project folder with Git: $(pwd)"

New-Item -ItemType Directory ticket-summarizer | Out-Null; Set-Location ticket-summarizer; git init -q
if ($?) { Write-Host "📂 Project folder with Git: $(Get-Location)" }
2

#Add the plugin to your agent

The plugin lives in the Azure/ai-gateway↗ repository and follows each agent's plugin format. In GitHub Copilot CLI and Claude Code, start a session in the folder (copilot or claude) and run the slash commands. In Gemini CLI, run the command in your shell, then start gemini in the folder. In Cursor, use the dashboard, then open the folder.

gemini extensions install https://github.com/Azure/ai-gateway
echo "🧩 The ai-gateway extension is installed in Gemini CLI"

The marketplace is named azure and the plugin ai-gateway.

3

#Check that the commands are available

In your agent, run the discover command without a resource ID:

Text
/ai-gateway:discover

The plugin asks you for the gateway's resource ID before it makes any call. That's how you know it's loaded. Answer with the ID you printed, or continue with the next step.

Checkpoint

/ai-gateway:discover is recognized and asks for a gateway resource ID.

#Discover what the gateway offers

1

#Run discover with your resource ID

Paste the gateway ID that you printed in Before you begin:

Text
/ai-gateway:discover /subscriptions/<subscription-id>/resourceGroups/<resource-group>/providers/Microsoft.ApiManagement/aigateways/<gateway>

When your agent asks to run az or curl commands, approve the ones that read: getting a token, GET requests to management.azure.com, and MCP calls to your gateway URL. Deny any PUT, PATCH, or DELETE. The plugin never needs them.

2

#Read the summary

The plugin reads the gateway's runtime URL, lists the models with the exact name each one accepts, and lists the MCP tool servers with their endpoints. It checks each tool server with a full MCP handshake and reports how many tools it exposes. Then it highlights the best matches and asks which assets you want. Ask follow-up questions in plain language, for example:

Text
Which model fits short summaries? Do any tool servers search Microsoft Learn?

Discover doesn't retrieve keys or write code. Stop here, or move on to build.

Checkpoint

The summary lists the model you published in lab 02 and, if you did lab 04, the learn tool server.

#Build an app with the gateway

1

#Describe what to build

Run build with the same resource ID and a short description. To use the key you created for this app instead of letting the plugin pick one, say so in the description:

Text
/ai-gateway:build /subscriptions/<subscription-id>/resourceGroups/<resource-group>/providers/Microsoft.ApiManagement/aigateways/<gateway> a Python command-line script that summarizes a support ticket from a text file. Use the <model-name> model and read the key from the AI_GATEWAY_API_KEY environment variable.

Other descriptions to try:

You wantDescribe it as
A model call in an app you already haveadd a /summarize endpoint to my FastAPI app that calls the gateway model
Tools in your own MCP clientconnect my app to the learn MCP tools
A ready-to-run agenta standalone agent that answers Azure questions with the learn tools
2

#Answer the plugin's questions

build runs the discovery again and asks you to confirm the model and tools. Then it gets a key and asks what you're building, if your description didn't say:

  • Call a model: code for the OpenAI-compatible endpoint, in your project's language.
  • Connect MCP tools: configuration for an MCP-capable client or app.
  • Scaffold a standalone agent: a complete GitHub Copilot SDK project with agent code, .env, .env.example, .gitignore, requirements.txt or package.json, and a README.md.

If you didn't name a key, the plugin lists the gateway's keys and reads the secret of an active one. That needs permission to list key secrets on the gateway. When the plugin writes a key to .env, it's a live secret in plain text, kept out of Git by .gitignore.

3

#Review the generated code

Read the code before you run it again or commit it. Check that:

  • The base URL is your gateway URL followed by /default/models/openai/v1, or /default/toolservers/<name>/mcp for tools. Without /default/, calls return 404.
  • The model value is a name your gateway accepts. To retarget models later without a code change, ask the agent to use your alias, as explained in Publish models from any provider behind stable aliases.
  • The key comes from AI_GATEWAY_API_KEY and goes in the api-key header. No key value appears in code, README.md, or config files, and .env.example holds only a placeholder.
  • .gitignore lists .env.
  • The app calls only the gateway's runtime URL, never management.azure.com.
  • For a scaffolded agent: requirements.txt pins github-copilot-sdk>=1.0.0, each MCP server lists the selected tools by name instead of "*", and tool permission requests wait for your approval.
4

#Run the app

build already ran the code once and reported the result. Run it yourself from the shell where you set AI_GATEWAY_API_KEY, using the command in the generated README.md. For a Python project, that's usually:

# Create a virtual environment in .venv and activate it, so that the packages stay out of your global Python
python3 -m venv .venv && source .venv/bin/activate &&
  echo "🧩 Virtual environment .venv is active"

# Install the packages that the generated app lists in requirements.txt
pip install -r requirements.txt &&
  echo "🧩 The packages in requirements.txt are installed"
# Create a virtual environment in .venv and activate it, so that the packages stay out of your global Python
python -m venv .venv; .\.venv\Scripts\Activate.ps1
if ($?) { Write-Host "🧩 Virtual environment .venv is active" }

# Install the packages that the generated app lists in requirements.txt
pip install -r requirements.txt
if ($?) { Write-Host "🧩 The packages in requirements.txt are installed" }

Then start the entry point that the README names, for example python summarize.py ticket.txt.

Checkpoint

The generated app prints a model response that came through your gateway.

#Verify

1

#Confirm the key and model outside the generated code

If the app fails, this call tells you whether the problem is in the gateway setup or in the code.

# Call the model through the gateway with your key and alias, and print only the HTTP status code
echo "🤖 HTTP status of a model call through the gateway:"
curl -sS -o /dev/null -w "HTTP %{http_code}\n" "${AI_GATEWAY_URL%/}/default/models/openai/v1/chat/completions" \
  -H "api-key: $AI_GATEWAY_API_KEY" -H "Content-Type: application/json" \
  -d "{\"model\":\"$AI_GATEWAY_MODEL\",\"messages\":[{\"role\":\"user\",\"content\":\"ping\"}]}"
# Call the model through the gateway with your key and alias, and print only the HTTP status code
Write-Host "🤖 HTTP status of a model call through the gateway:"
$body = @{ model = $env:AI_GATEWAY_MODEL; messages = @(@{ role = "user"; content = "ping" }) } | ConvertTo-Json -Depth 5
(Invoke-WebRequest -Method Post -Uri "$($env:AI_GATEWAY_URL.TrimEnd('/'))/default/models/openai/v1/chat/completions" `
  -Headers @{ "api-key" = $env:AI_GATEWAY_API_KEY } -ContentType "application/json" -Body $body -SkipHttpErrorCheck).StatusCode

Expect HTTP 200 (200 in PowerShell).

2

#Check that no secret can be committed

Run this in the project folder. It checks that Git ignores .env and that your key appears in no other file.

# Check that Git ignores .env, the file that holds your key
git check-ignore -q .env && echo "✅ .env is ignored" || echo "⚠️ .env is not ignored"

# Search every other file for your key, skipping .git, .venv, and node_modules, and list any file that holds it
if grep -rIlF --exclude=.env --exclude-dir=.git --exclude-dir=.venv --exclude-dir=node_modules -- "$AI_GATEWAY_API_KEY" .; then
  echo "⚠️ The key appears in the files above"
else
  echo "✅ No key in project files"
fi
# Check that Git ignores .env, the file that holds your key
git check-ignore -q .env; if ($LASTEXITCODE -eq 0) { Write-Host "✅ .env is ignored" } else { Write-Host "⚠️ .env is not ignored" }

# Search every other file for your key, skipping .git, .venv, and node_modules, and list any file that holds it
$hits = Get-ChildItem -Recurse -File -Force |
  Where-Object { $_.Name -ne ".env" -and $_.FullName -notmatch '[\\/](\.git|\.venv|node_modules)[\\/]' } |
  Select-String -SimpleMatch -Pattern $env:AI_GATEWAY_API_KEY -List
if ($hits) { Write-Host "⚠️ The key appears in:"; $hits.Path } else { Write-Host "✅ No key in project files" }

Expect ✅ .env is ignored and ✅ No key in project files. If the plugin wrote a different key to .env, run the check again with that key in AI_GATEWAY_API_KEY.

Checkpoint

The direct call returns 200, the app works, and no key can reach Git.

#Go further

#Use the gateway's tools in VS Code agent mode

VS Code reads MCP servers from .vscode/mcp.json. To give agent mode the tools that you federated in Federate MCP tools behind one endpoint, save this file as .vscode/mcp.json in your project. Replace https://<gateway>.eastus2-01.ai.gateway.azure.com with your gateway URL (echo $AI_GATEWAY_URL) and learn with any tool server name that discover listed. To copy a tool server's exact MCP URL, run az aigateway mcp show -g "$RG" --gateway-name "$GATEWAY" -n learn --query "properties.gatewayEndpoints[0].url" -o tsv.

infra/mcp.jsonGitHub
{
  "inputs": [
    {
      "type": "promptString",
      "id": "aigw-key",
      "description": "AI Gateway runtime key (Access > Keys)",
      "password": true
    }
  ],
  "servers": {
    "ai-gateway-learn": {
      "type": "http",
      "url": "https://<gateway>.eastus2-01.ai.gateway.azure.com/default/toolservers/learn/mcp",
      "headers": {
        "api-key": "${input:aigw-key}"
      }
    }
  }
}

On GitHub, open infra/mcp.json↗.

Start the server from the mcp.json editor and paste your runtime key when VS Code prompts for it. The inputs entry keeps the key out of the file.

#Go keyless

The plugin generates code that uses a runtime key. For production apps, switch to Microsoft Entra ID tokens with the audience https://azure-api.net/aigateway, as shown in Go keyless with Microsoft Entra ID and RBAC.

#Clean up

Keep the gateway, model, and alias. Other labs use them.

Delete the key you created for this lab. Then delete the ticket-summarizer folder when you're done, because its .env file can hold a live key.

# Delete the API key that you created for this lab, so that it stops working everywhere
az aigateway api-key delete -g "$RG" --gateway-name "$GATEWAY" -n app-coding-agent --yes &&
  echo "🧹 API key app-coding-agent is deleted"
# Delete the API key that you created for this lab, so that it stops working everywhere
az aigateway api-key delete -g $RG --gateway-name $GATEWAY -n app-coding-agent --yes
if ($?) { Write-Host "🧹 API key app-coding-agent is deleted" }

If the plugin wrote another gateway key to .env and that file was shared or committed, regenerate that key as shown in Issue and rotate runtime API keys. Remove the ai-gateway-learn entry from .vscode/mcp.json if you added it.

Optionally, remove the plugin. In Cursor, remove it where you installed it.

/plugin uninstall ai-gateway
/plugin marketplace remove azure
/plugin uninstall ai-gateway@azure
/plugin marketplace remove azure
# Remove the ai-gateway extension from Gemini CLI
gemini extensions uninstall ai-gateway
echo "🧹 The ai-gateway extension is removed from Gemini CLI"
