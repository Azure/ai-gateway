Security & identity · Lab 11

Go keyless with Microsoft Entra ID and RBAC

Replace shared gateway API keys with Microsoft Entra ID tokens. Grant users, groups, apps, and managed identities an AI Gateway data-plane role at the gateway, a model alias, or an MCP server, then call models from the playground, curl, Python, TypeScript, and C# with no secret in code.

Intermediate 35 min PortalCLIBicepCode Updated Oct 22, 2026
Notebook Source Edit

What you'll do

  • Choose between AI Gateway User, AI Gateway Models User, and AI Gateway Tools User, and pick the narrowest scope
  • Assign a data-plane role in the portal or with az role assignment create
  • Acquire a token for the https://azure-api.net/aigateway audience and send it as a bearer token
  • Call a model from Python, TypeScript, and C# with DefaultAzureCredential and no API key
  • Tell a 401 from a 403 and fix each one

Before you start

  • 02Publish a Foundry model and make your first call

Tracks: Portal, Azure CLI, Bicep / azd, Code

A security review of your AI platform found runtime API keys in .env files, CI logs, and a shared notebook. Every key grants every model and tool on the gateway, nobody can say which person is behind a key, and rotation means chasing every team. The platform team wants callers to use their own Microsoft Entra identity instead: access granted by Azure RBAC, scoped to one model alias or MCP server when needed, and removed automatically when someone leaves a group. In this lab you grant a data-plane role, call a model with an Entra token from the playground, the command line, and code, and see what the gateway answers when the role is missing.

#Before you begin

  • Complete Publish a Foundry model and make your first call. You need a gateway with at least one model alias.
  • The Azure CLI↗ 2.75 or later, signed in with az login to the tenant that holds the gateway. The commands call the Azure Resource Manager REST API with az rest, because the az aigateway extension doesn't manage the new aigateways resource type yet.
  • For the CLI track in Bash: jq↗, which decodes the token and reads the reply.
  • Permission to create role assignments on the gateway: Owner, User Access Administrator, or Role Based Access Control Administrator. Contributor can manage the gateway but can't grant roles. If you don't have one of these, ask an administrator to run the role assignment step for you.
  • For the Code track, one of: Python 3.9 or later, Node.js 22.18 or later, or the .NET 8 SDK or later.

#How it works

Access to AI Gateway crosses two trust boundaries. Inbound, your app authenticates to the gateway endpoint. Outbound, the gateway authenticates to each model or tool with its own credential, which you set up in Call backends with managed identities.

For inbound Entra access, the caller gets an access token for the audience https://azure-api.net/aigateway and sends it in the Authorization: Bearer <token> header. The gateway validates the token at its edge, then checks the caller's Azure RBAC role assignments for the model alias or MCP server in the request. Without a matching role, it answers 403 before any policy or backend runs. These roles grant runtime access only, not gateway administration.

infra/assign-roles.shGitHub
#!/usr/bin/env bash
# Grants an AI Gateway data-plane role to a Microsoft Entra identity at the gateway, a model alias, or an MCP server.
#
# Usage: ./assign-roles.sh <role> [scope] [principal-object-id] [principal-type]
#   role                 user | models | tools
#                          user   = AI Gateway User        (models and tools)
#                          models = AI Gateway Models User (models only)
#                          tools  = AI Gateway Tools User  (tools only)
#   scope                gateway (default) | alias:<alias-name> | mcp:<mcp-server-name>
#   principal-object-id  defaults to the signed-in user
#   principal-type       User (default) | Group | ServicePrincipal
#
# Requires RG and GATEWAY, and permission to create role assignments (Owner, User Access Administrator,
# or Role Based Access Control Administrator). Contributor isn't enough.
set -euo pipefail

: "${RG:?Set RG to the resource group of the gateway}"
: "${GATEWAY:?Set GATEWAY to the gateway name}"

ROLE="${1:?Usage: ./assign-roles.sh <user|models|tools> [gateway|alias:<name>|mcp:<name>] [principal-object-id] [principal-type]}"
TARGET="${2:-gateway}"
PRINCIPAL_ID="${3:-}"
PRINCIPAL_TYPE="${4:-User}"

case "$ROLE" in
  user)   ROLE_ID="caad7a21-134e-43f4-a550-c5ffc17e051c"; ROLE_NAME="AI Gateway User" ;;
  models) ROLE_ID="a6b68e3d-a1f0-4c60-8678-237c050cf4ea"; ROLE_NAME="AI Gateway Models User" ;;
  tools)  ROLE_ID="dce03f8d-857f-4e40-a90d-67770fa6ecd2"; ROLE_NAME="AI Gateway Tools User" ;;
  *) echo "Unknown role '$ROLE'. Use user, models, or tools." >&2; exit 2 ;;
esac

GATEWAY_ID="$(az resource show -g "$RG" -n "$GATEWAY" --resource-type Microsoft.ApiManagement/aigateways --query id -o tsv)"

case "$TARGET" in
  gateway) SCOPE="$GATEWAY_ID" ;;
  alias:?*)
    [[ "$ROLE" != "tools" ]] || { echo "AI Gateway Tools User can't be assigned on a model alias." >&2; exit 2; }
    SCOPE="$GATEWAY_ID/workspaces/default/aliases/${TARGET#alias:}" ;;
  mcp:?*)
    [[ "$ROLE" != "models" ]] || { echo "AI Gateway Models User can't be assigned on an MCP server." >&2; exit 2; }
    SCOPE="$GATEWAY_ID/workspaces/default/toolServers/${TARGET#mcp:}" ;;
  *) echo "Unknown scope '$TARGET'. Use gateway, alias:<name>, or mcp:<name>." >&2; exit 2 ;;
esac

if [[ -z "$PRINCIPAL_ID" ]]; then
  PRINCIPAL_ID="$(az ad signed-in-user show --query id -o tsv)"
  PRINCIPAL_TYPE="User"
fi

echo "Role:      $ROLE_NAME ($ROLE_ID)"
echo "Principal: $PRINCIPAL_ID ($PRINCIPAL_TYPE)"
echo "Scope:     $SCOPE"

az role assignment create \
  --assignee-object-id "$PRINCIPAL_ID" \
  --assignee-principal-type "$PRINCIPAL_TYPE" \
  --role "$ROLE_ID" \
  --scope "$SCOPE" \
  --output none

az role assignment list --scope "$SCOPE" \
  --query "[?principalId=='$PRINCIPAL_ID'].{Role:roleDefinitionName, PrincipalType:principalType, Scope:scope}" \
  --output table

echo "Role assignments can take several minutes to apply. Until then, calls return 403."

On GitHub, open assign-roles.sh↗ or assign-roles.ps1↗.

For a managed identity, pass its principal (object) ID with the type ServicePrincipal, for example from az identity show -g <resource-group> -n <identity-name> --query principalId -o tsv.

#Review the template

The template grants one AI Gateway role to one principal at the gateway, a model alias, or an MCP server. It names the assignment with guid() of the scope, principal, and role, so redeploying it changes nothing.

infra/role-assignment.bicepGitHub
// Grants an AI Gateway data-plane role to a Microsoft Entra identity at the gateway, a model alias, or an MCP server.
// Data-plane roles let callers invoke models and call tools. They don't grant gateway administration.
// The assignment name is derived from the scope, principal, and role, so redeploying the template is safe.

@description('Name of the existing AI Gateway (Microsoft.ApiManagement/aigateways).')
param gatewayName string

@description('Object ID of the user, group, service principal, or managed identity to grant.')
param principalId string

@description('Type of the principal. Use ServicePrincipal for apps and managed identities.')
@allowed([ 'User', 'Group', 'ServicePrincipal' ])
param principalType string = 'User'

@description('Role to grant: user (AI Gateway User, models and tools), models (AI Gateway Models User), or tools (AI Gateway Tools User).')
@allowed([ 'user', 'models', 'tools' ])
param role string = 'models'

@description('Where to grant it: the whole gateway, one model alias, or one MCP server.')
@allowed([ 'gateway', 'alias', 'mcp' ])
param scope string = 'gateway'

@description('Alias name when scope is alias, or MCP server name when scope is mcp.')
param scopeName string = ''

var roleIds = {
  user: 'caad7a21-134e-43f4-a550-c5ffc17e051c'
  models: 'a6b68e3d-a1f0-4c60-8678-237c050cf4ea'
  tools: 'dce03f8d-857f-4e40-a90d-67770fa6ecd2'
}
var roleDefinitionId = subscriptionResourceId('Microsoft.Authorization/roleDefinitions', roleIds[role])
var childName = empty(scopeName) ? 'unused' : scopeName

resource gateway 'Microsoft.ApiManagement/aigateways@2025-09-01-preview' existing = {
  name: gatewayName
}

resource workspace 'Microsoft.ApiManagement/aigateways/workspaces@2025-09-01-preview' existing = {
  parent: gateway
  name: 'default'
}

resource alias 'Microsoft.ApiManagement/aigateways/workspaces/aliases@2025-09-01-preview' existing = {
  parent: workspace
  name: childName
}

resource toolServer 'Microsoft.ApiManagement/aigateways/workspaces/toolServers@2025-09-01-preview' existing = {
  parent: workspace
  name: childName
}

resource onGateway 'Microsoft.Authorization/roleAssignments@2022-04-01' = if (scope == 'gateway') {
  scope: gateway
  name: guid(gateway.id, principalId, roleDefinitionId)
  properties: {
    principalId: principalId
    principalType: principalType
    roleDefinitionId: roleDefinitionId
  }
}

resource onAlias 'Microsoft.Authorization/roleAssignments@2022-04-01' = if (scope == 'alias') {
  scope: alias
  name: guid(alias.id, principalId, roleDefinitionId)
  properties: {
    principalId: principalId
    principalType: principalType
    roleDefinitionId: roleDefinitionId
  }
}

resource onToolServer 'Microsoft.Authorization/roleAssignments@2022-04-01' = if (scope == 'mcp') {
  scope: toolServer
  name: guid(toolServer.id, principalId, roleDefinitionId)
  properties: {
    principalId: principalId
    principalType: principalType
    roleDefinitionId: roleDefinitionId
  }
}

output roleAssignmentId string = scope == 'gateway' ? onGateway.id : (scope == 'alias' ? onAlias.id : onToolServer.id)
output scopeId string = scope == 'gateway' ? gateway.id : (scope == 'alias' ? alias.id : toolServer.id)

#Get a token

The Azure CLI can issue a token for the AI Gateway audience with your sign-in:

export AI_GATEWAY_TOKEN="$(az account get-access-token \
  --resource https://azure-api.net/aigateway --query accessToken -o tsv)"
$env:AI_GATEWAY_TOKEN = az account get-access-token `
  --resource https://azure-api.net/aigateway --query accessToken -o tsv

Access tokens are short-lived, typically about an hour. Run the command again when you get a 401.

2

#Look inside the token

Decode the token's payload (the middle segment) to see what the gateway checks:

jq -R 'split(".")[1] | gsub("-";"+") | gsub("_";"/") | @base64d | fromjson
  | {aud, tid, oid, scp, appid}' <<< "$AI_GATEWAY_TOKEN"
$payload = ($env:AI_GATEWAY_TOKEN -split '\.')[1].Replace('-', '+').Replace('_', '/')
$payload = $payload.PadRight($payload.Length + (4 - $payload.Length % 4) % 4, '=')
[Text.Encoding]::UTF8.GetString([Convert]::FromBase64String($payload)) |
  ConvertFrom-Json | Select-Object aud, tid, oid, scp, appid

aud is https://azure-api.net/aigateway, scp includes Data.All because the CLI gets a delegated token for you, and tid plus oid identify you to per-caller policies.

#Call the model with the bearer token

curl -sS "${AI_GATEWAY_URL%/}/default/models/openai/v1/chat/completions" \
  -H "Authorization: Bearer $AI_GATEWAY_TOKEN" \
  -H "Content-Type: application/json" \
  -d "{\"model\":\"$AI_GATEWAY_MODEL\",\"messages\":[{\"role\":\"user\",\"content\":\"Say hello in five words.\"}]}" \
  | jq -r '.choices[0].message.content'
$body = @{
  model    = $env:AI_GATEWAY_MODEL
  messages = @(@{ role = "user"; content = "Say hello in five words." })
} | ConvertTo-Json -Depth 5
$response = Invoke-RestMethod -Method Post `
  -Uri "$($env:AI_GATEWAY_URL.TrimEnd('/'))/default/models/openai/v1/chat/completions" `
  -Headers @{ Authorization = "Bearer $env:AI_GATEWAY_TOKEN" } `
  -ContentType "application/json" -Body $body
$response.choices[0].message.content
Warning

Send a token or a key, never both. A request with an Authorization header and an api-key header gets 400.

The OpenAI SDKs for Python (1.106 or later) and TypeScript (5.18 or later) accept a function as the API key. They call it before each request and send the result as Authorization: Bearer <token>, and the Azure Identity token provider refreshes the token before it expires. The C# sample calls the REST endpoint with HttpClient and asks the credential for a token before each call, which also returns a cached token until it's close to expiry. Don't use an AzureOpenAI client here: the gateway exposes the OpenAI v1 API at /default/models/openai/v1.

The complete samples add input checks and print the reply and token usage:

infra/call_with_entra.pyGitHub
"""Calls a model through AI Gateway with a Microsoft Entra ID access token instead of an API key.

DefaultAzureCredential picks up your Azure CLI or Visual Studio Code sign-in on a laptop, and a managed
identity or workload identity when the code runs in Azure. The token provider returns a cached token and
refreshes it before it expires. The OpenAI SDK (1.106 or later) calls the provider before every request and
sends the result as `Authorization: Bearer <token>`.

Usage:
  pip install -r requirements.txt
  az login
  export AI_GATEWAY_URL="https://<gateway>.eastus2-01.ai.gateway.azure.com"
  export AI_GATEWAY_MODEL="<model-alias>"
  python call_with_entra.py
"""

import os

from azure.identity import DefaultAzureCredential, get_bearer_token_provider
from openai import OpenAI

# App-only and managed identity callers must use /.default. It also works for an Azure CLI sign-in.
AI_GATEWAY_SCOPE = "https://azure-api.net/aigateway/.default"

gateway_url = os.environ["AI_GATEWAY_URL"].rstrip("/")
model = os.environ["AI_GATEWAY_MODEL"]

token_provider = get_bearer_token_provider(DefaultAzureCredential(), AI_GATEWAY_SCOPE)

client = OpenAI(
    base_url=f"{gateway_url}/default/models/openai/v1",
    api_key=token_provider,
)

completion = client.chat.completions.create(
    model=model,
    messages=[{"role": "user", "content": "In one sentence, why use Microsoft Entra ID instead of API keys?"}],
)
print(f"Model reply: {completion.choices[0].message.content}")
print(f"Tokens used: {completion.usage.total_tokens if completion.usage else 'n/a'}")

// Calls a model through AI Gateway with a Microsoft Entra ID access token instead of an API key.
//
// DefaultAzureCredential picks up your Azure CLI or Visual Studio Code sign-in on a laptop, and a managed
// identity or workload identity when the code runs in Azure. getBearerTokenProvider returns a cached token
// and refreshes it before it expires. The OpenAI package (5.18 or later) calls the provider before every
// request and sends the result as `Authorization: Bearer <token>`.
//
// Usage (Node.js 22.18 or later runs TypeScript directly; on older versions use `npx tsx call-with-entra.ts`):
//   npm install
//   az login
//   export AI_GATEWAY_URL="https://<gateway>.eastus2-01.ai.gateway.azure.com"
//   export AI_GATEWAY_MODEL="<model-alias>"
//   node call-with-entra.ts
import { DefaultAzureCredential, getBearerTokenProvider } from "@azure/identity";

// Calls a model through AI Gateway with a Microsoft Entra ID access token instead of an API key.
//
// DefaultAzureCredential picks up your Azure CLI or Visual Studio sign-in on a laptop, and a managed identity
// or workload identity when the code runs in Azure. Request a new token for each call: the credential caches
// tokens and refreshes them before they expire.
//
// Usage:
//   az login
//   export AI_GATEWAY_URL="https://<gateway>.eastus2-01.ai.gateway.azure.com"
//   export AI_GATEWAY_MODEL="<model-alias>"
//   dotnet run
using System.Net.Http.Headers;
using System.Net.Http.Json;
using System.Text.Json;
using Azure.Core;
using Azure.Identity;

// App-only and managed identity callers must use /.default. It also works for an Azure CLI sign-in.
const string AiGatewayScope = "https://azure-api.net/aigateway/.default";

static string Required(string name) =>
    Environment.GetEnvironmentVariable(name) is { Length: > 0 } value
        ? value
        : throw new InvalidOperationException($"Set {name} before running this sample.");

var gatewayUrl = Required("AI_GATEWAY_URL").TrimEnd('/');
var model = Required("AI_GATEWAY_MODEL");

var credential = new DefaultAzureCredential();
AccessToken token = await credential.GetTokenAsync(new TokenRequestContext(new[] { AiGatewayScope }));

using var http = new HttpClient();
using var request = new HttpRequestMessage(HttpMethod.Post, $"{gatewayUrl}/default/models/openai/v1/chat/completions")
{
    Content = JsonContent.Create(new
    {
        model,
        messages = new[] { new { role = "user", content = "In one sentence, why use Microsoft Entra ID instead of API keys?" } },
    }),
};
request.Headers.Authorization = new AuthenticationHeaderValue("Bearer", token.Token);

using var response = await http.SendAsync(request);
var body = await response.Content.ReadAsStringAsync();
if (!response.IsSuccessStatusCode)
{
    Console.Error.WriteLine($"{(int)response.StatusCode} {response.ReasonPhrase}: {body}");
    return 1;
}

using var json = JsonDocument.Parse(body);
var reply = json.RootElement.GetProperty("choices")[0].GetProperty("message").GetProperty("content").GetString();
Console.WriteLine($"Model reply: {reply}");
var tokensUsed = json.RootElement.TryGetProperty("usage", out var usage) ? usage.GetProperty("total_tokens").ToString() : "n/a";
Console.WriteLine($"Tokens used: {tokensUsed}");
return 0;

#Verify

1

#Confirm the keyless call succeeds

Run the curl call or a code sample from the previous section. It returns 200 with a reply.

2

#Send a token for the wrong audience

A token for Azure Resource Manager is valid, but not for AI Gateway:

Bash
curl -sS -o /dev/null -w "%{http_code}\n" "${AI_GATEWAY_URL%/}/default/models/openai/v1/chat/completions" \
  -H "Authorization: Bearer $(az account get-access-token --query accessToken -o tsv)" \
  -H "Content-Type: application/json" \
  -d "{\"model\":\"$AI_GATEWAY_MODEL\",\"messages\":[{\"role\":\"user\",\"content\":\"ping\"}]}"

The gateway answers 401: authentication failed, so the role was never checked.

3

#Remove the role and try again

Remove your assignment, wait a few minutes, get a fresh token, and repeat the curl call:

Bash
az role assignment delete --assignee "$MY_OBJECT_ID" \
  --role "a6b68e3d-a1f0-4c60-8678-237c050cf4ea" --scope "$GATEWAY_ID"

The gateway now answers 403: you're authenticated, but no role allows you to invoke the model. In the playground, the same error offers Review access, which opens the role assignments, and Copy access request, which copies your identity, the suggested role, and the scope for an administrator.

4

#Restore access

Assign the role again (portal, az role assignment create, or ./infra/assign-roles.sh models), wait for it to apply, and confirm the call returns 200.

Checkpoint

You called a model with no API key, got 401 for a token with the wrong audience, and 403 while your identity had no role.

#Go further

  • Narrow the scope. Replace the gateway-wide assignment with AI Gateway Models User on a single alias (./infra/assign-roles.sh models "alias:<alias>"). Calls to other aliases now return 403.
  • Grant tools only. Give an agent AI Gateway Tools User on one MCP server from Federate MCP tools, so it can list and call those tools but not invoke models.
  • Run without a user. Deploy the Python sample to an Azure service with a managed identity, assign the role to that identity's principal ID, and the same code runs with app-only tokens for the .default scope. Agent identities work the same way.
  • Budget per person. Add a cost limit with Caller identity as the counter dimension and an override for one Entra identity in Enforce cost budgets. Each tid and oid pair gets its own budget.
  • See who called. In Monitoring›Settings, Token claim attributes exports claims such as tid, oid, appid, and azp as azure.ai_gateway.identity.claims.<claim> attributes on logs, traces, and metrics. See Monitor usage, cost, and traces.

#Troubleshooting

SymptomLikely causeFix
401 on every Entra callThe token is expired, or it was issued for another audience, such as Azure Resource ManagerRequest a new token for https://azure-api.net/aigateway (.default for app-only callers). Check aud in the decoded token.
403 right after you assigned the roleRole assignments take several minutes to applyWait and retry with a fresh token. In the playground, use Back to playground after reviewing access.
403 for one model or MCP server onlyThe role is scoped to a different alias or MCP server, or the role doesn't cover it (Models User on an MCP server, Tools User on a model)Assign a compatible role at the gateway or at that alias or MCP server.
403 even though the role is correctA gateway policy (for example a cost limit), the request proxy, or the backend rejected the callRead the error code in the response body before changing permissions. LlmCostQuotaExceeded comes from a cost limit.
AuthorizationFailed when you create the assignmentYou have Contributor, which can't write role assignmentsAsk an Owner, User Access Administrator, or Role Based Access Control Administrator to assign the role.
DefaultAzureCredential failed to retrieve a tokenNo sign-in is available to the credential chainRun az login, or sign in to the Azure extension in your IDE, then rerun the sample.
