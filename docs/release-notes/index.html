#Labs changes

  • October 27. The Azure CLI tracks need aigateway extension 1.0.0b14 or later, which lab 01 installs. They now register models with az aigateway model create, set and remove token limits and content safety with az aigateway model policy (lab 06, lab 08, lab 09, lab 24), and rotate the secondary key value with az aigateway api-key regenerate --key-type secondary (lab 10). Lab 02 also shows the one-step az aigateway model create --foundry-resource-id. The labs keep az rest for gateway policies, cost limits, telemetry exporters, MCP versions, API key state, and the connector gateway.
  • October 27. The quick start's Bicep + azd track now gets its template by cloning the repo and moving into labs/quickstart, instead of downloading each file. The clone also gets the other labs, and the track no longer lists the template's files.
  • October 26. The Bicep templates now follow the AI Gateway reference sample↗: they create the gateway in the Consumption SKU, the same one that az aigateway create uses, and then its connector gateway. A template that omits sku creates a Premium gateway, so set it in your own templates too. Every template now silences the BCP081 warnings for the preview resource types, so az bicep build runs clean, and the quick start template's model and alias set displayName, modelVersion, and aliasName, as the sample does. Lab 01 explains the template, and its troubleshooting now covers InvalidSkuName and the limit of five gateways per subscription in each region.
  • October 23. The Azure CLI tracks, the Verify and Clean up steps, and the lab scripts now use the aigateway CLI extension for gateways, model providers, aliases, API keys, and MCP servers. Lab 01 shows how to install it. The labs keep az rest only for what the extension can't do yet, such as registering models and setting policies, and say why each time.
  • October 23. Lab 18 now delegates the integration subnet to Microsoft.App/environments, which the service requires. A subnet delegated to Microsoft.Web/serverFarms fails with AIGatewaySubnetNotDelegated. The portal's subnet check still expects Microsoft.Web/serverFarms and shows a warning, which you can ignore.
  • October 23. Lab 24 now publishes the Microsoft Learn MCP server on the gateway, with portal, Azure CLI, and Bicep tracks, and adds its tools to GitHub Copilot in VS Code, the Copilot CLI, the Copilot SDK, and the GitHub Copilot app with the same runtime key. It shows the token cost of tool results and how one suspended key cuts off both models and tools.
  • October 22. New lab 24 · Use your gateway's models and tools in GitHub Copilot: publish gpt-6-astra with a per-caller token limit and a key for Copilot, then connect GitHub Copilot in VS Code, the Copilot CLI, the Copilot SDK (Python and TypeScript), and the GitHub Copilot app with bring your own key (BYOK). It includes portal, Azure CLI, and Bicep tracks, and shows how one suspended key cuts off every Copilot surface.
  • October 22. New 5-minute quick start: learn the five building blocks, create a gateway with a Foundry gpt-6-luna model, an alias, and a runtime key, and make your first call. Follow it in the AI Gateway portal, with a screenshot for every step; paste its Azure CLI commands (Bash or PowerShell) into Cloud Shell; or download its Bicep template and deploy it with one azd up. There's nothing to clone. The home page now starts with it, and the former 30-minute quickstart path is now 30-minute essentials.
  • October 22. New lab 23 · Stream responses and count every token, which covers usage for streamed Chat Completions responses from the September 24 release. It streams with curl, PowerShell, Python, and TypeScript, shows each chunk and where usage arrives, proves that a token limit counts streams with or without include_usage, and has a notebook and an interactive streaming usage simulator on the site.
  • October 22. New lab 22 · Route an alias across models by priority and weight, with portal, Azure CLI, and Bicep tracks, a script that counts which model served each request, and an interactive priority and weight simulator on the site.
  • October 22. Lab 04 adds Supported MCP versions: the version list, the legacy defaults, the rule that every backend must support every listed version, and a supportedVersions Bicep parameter. Lab 03 follows the new alias wizard and links to lab 22.
  • October 22. The labs use the latest models: gpt-6-luna and gpt-6.1-sol from Microsoft Foundry, and claude-haiku-5-5 and claude-sonnet-5-5 from Anthropic. Portal steps say Catalog where the portal used to say Discover.
  • October 22. Lab 00 has a narrated three-minute video tour of the portal.
  • October 19. Every lab creates the dedicated Microsoft.ApiManagement/aigateways resource type.
  • October 19. Each lab's README.md is the source of truth for both the site and GitHub, with navigation that works on GitHub. Jupyter notebooks run five labs end to end by deploying the labs' own Bicep files through a shared utils.py↗.
  • October 19. Lab 01 has a narrated video, and the azure-ai-gateway-labs↗ agent skill teaches coding agents how to use the labs.

#How these notes work

Each section matches one entry in the product release notes↗, with the same date and title, and maps every product change to the lab where you can practice it. Changes to the labs that don't come from a product release are listed under Labs changes in the release they followed.

This file, labs/RELEASE-NOTES.md, is the source of truth: the labs site renders it at /release-notes/. To check for product releases that the notes don't cover yet, run npm run releases in labs/. See Authoring↗.
