#Labs changes

  • October 28. A new Setup guide collects the tasks that every lab shares: checking your subscription and permissions, choosing between Cloud Shell and a local shell, signing in, installing the aigateway extension, registering the resource providers, finding the available regions, cloning the labs repo, and deploying and deleting a lab with azd. Each lab page links to it from the right rail, between Your values and Open the portal, and the labs link to its sections instead of repeating the steps, so they're shorter. Labs that run scripts or samples from infra/ now say to clone the repo first.
  • October 28. On the site, the Setup guide now opens in a panel next to the lab, like Your values, from the right rail, the lab's header, or any link to one of its tasks. Mark a task Done in the panel or on the guide's page, and the labs stop listing it. Each lab's Before you begin starts with a One-time setup card that lists only the tasks it needs and that you haven't done yet, so the labs no longer repeat tool lists, sign-in, or a Clone the lab step: the Bicep + azd tracks start by moving into the lab's folder. The quick start uses the card too, so its tracks no longer install the extension, register the providers, or clone the repo, and every later lab reuses that setup.
  • October 28. A new Troubleshooting page collects the errors from every lab, with their likely causes and fixes, in one section per lab, plus Setup and deployment. On the site, you can filter it by an error code or a word from the message, and site search finds each lab's section. Each lab's right rail links to its section on the page.
  • October 28. On the site, Troubleshooting now opens in a panel next to the lab, like the Setup guide, from the right rail or any other link to it. The lab's own errors come first, open, as cards that label the likely cause and the fix, and the filter works in the panel too. Open as a page keeps the filter.
  • October 28. Each error on the Troubleshooting page now names the steps where it shows up, and the labs no longer have a Troubleshooting section. On the site, those steps get a Troubleshoot button next to Done, with the number of known errors. It opens the panel with only that step's errors, for the track you're on, and Show all errors shows the rest of the lab. On GitHub, each lab's footer links to its section.
  • October 28. Every Azure CLI, azd, and REST command in the labs, the quick start, and the Setup guide now has a comment that explains what it does, in both Bash and PowerShell. After it runs, it prints a short status line with an emoji, such as 🚀 Gateway aigw-1a2b3c is ready or 🤖 <the model's reply>. Status lines print only when the command succeeds, and keys and tokens are never printed: only their length is. Authoring↗ lists the conventions.
  • October 28. The quick start's Azure CLI track no longer creates a connector gateway (Microsoft.Web/connectorGateways) with az rest, or registers Microsoft.Web. Only connector-based MCP tools use the connector gateway, and the portal creates it when you first add a connector backend. A live run of the track without it published the model and got a reply.
  • October 28. The quick start now names Azure RBAC as the keyless alternative to the runtime API key, in every track and in How it works, and links to Go keyless with Microsoft Entra ID and RBAC from its next steps.
  • October 28. The quick start's Azure CLI track now publishes the model with one import: az aigateway model-provider create --foundry-resource-id grants the gateway's managed identity the Foundry User role on the Foundry account, adds a model provider that signs in with that identity, and adds a model for each deployment. It replaces the role assignment, the provider JSON, and az aigateway model create. The track still adds the alias, because the import doesn't. Labs 02 and 18 now pass the provider's Foundry settings in the Azure CLI shorthand instead of building JSON with jq or a file.
  • October 28. The Bash snippets now paste cleanly into zsh on macOS. Their status lines use only emoji that zsh draws, such as 🔐 instead of 🛡️ and 🔖 instead of 🏷️, and JSON values that contain a URL stay on one line, so oh-my-zsh's URL quoting can't escape them. The Setup guide turns on interactive_comments, so zsh accepts the pasted comments, and Troubleshooting lists the paste errors. npm run check flags other emoji, and URL lines that zsh could change. Authoring↗ lists the emoji.
  • October 28. The labs no longer describe AI Gateway as a preview service or say that the gateway is free during the preview. Lab 00 and the Setup guide point to the AI Gateway documentation↗ for pricing, and the lab 01 video narrates the region step without the preview. Labs 19 and 20 still mark Agent 365 as an emerging capability.
  • October 28. AI Gateway now runs in more regions, and the list keeps growing, so the labs no longer name fixed regions. The Setup guide shows how to list the current ones with the Azure CLI, and how to check that a Foundry model is available in a region. The Bicep templates accept any region, the other labs link to that list, and the notebooks check AIGW_LOCATION against it. The portal can offer fewer regions than the Azure CLI and Bicep + azd tracks.
  • October 28. On the site, Safari no longer offers saved credit cards or contacts in Your values, such as on Subscription ID. The panel now focuses its close button when it opens instead of the first field, and password managers skip its fields too. Your saved values carry over.
  • October 28. The Azure CLI tracks need aigateway extension 1.0.0b15 or later, which the Setup guide installs. They publish aliases with az aigateway model-alias set, which creates the alias or updates it, so you can run the step again (the quick start, labs 02, 03, 18, 22, 23, and 24). Lab 01 passes --sku Consumption and shows the SKU, lab 06 shows that --token-counter-key takes Identity, IPAddress, or both, like the portal's Counter dimensions, and lab 12 changes only the provider's identity with a partial az aigateway model-provider update --foundry, without reading and rewriting the whole provider.
  • October 27. Every Bicep + azd track is now a self-contained azd template, like the quick start's: clone the repo, run azd up in the lab's folder to create a new gateway with everything the lab needs, change its settings with azd env set and azd provision, and remove it all with azd down --purge --force (lab 06 shows the pattern). Labs 01, 02, 04, 06, 11, 12, 13, 18, 22, 23, and 24 move to it, and labs 03, 05, 07, 08, 10, 14, and 19 gain a Bicep + azd track. The reusable modules have descriptive names, such as lab 01's gateway.bicep, lab 02's publish-model.bicep, lab 04's tool-server.bicep, and lab 06's limited-alias.bicep, so other labs can compose them. Lab 05 now shows that a blocked MCP server answers 200 with the JSON-RPC error AccessBlockedByGateway.
  • October 27. The Azure CLI tracks need aigateway extension 1.0.0b14 or later, which the Setup guide installs. They now register models with az aigateway model create, set and remove token limits and content safety with az aigateway model policy (lab 06, lab 08, lab 09, lab 24), and rotate the secondary key value with az aigateway api-key regenerate --key-type secondary (lab 10). Lab 02 also shows the one-step az aigateway model create --foundry-resource-id. The labs keep az rest for gateway policies, cost limits, telemetry exporters, MCP versions, API key state, and the connector gateway.
  • October 27. The quick start's Bicep + azd track now gets its template by cloning the repo and moving into labs/quickstart, instead of downloading each file. The clone also gets the other labs, and the track no longer lists the template's files.
  • October 26. The Bicep templates now follow the AI Gateway reference sample↗: they create the gateway in the Consumption SKU, the same one that az aigateway create uses, and then its connector gateway. A template that omits sku creates a Premium gateway, so set it in your own templates too. Every template now silences the BCP081 warnings for the preview resource types, so az bicep build runs clean, and the quick start template's model and alias set displayName, modelVersion, and aliasName, as the sample does. Lab 01 explains the template, and its troubleshooting now covers InvalidSkuName and the limit of five gateways per subscription in each region.
  • October 23. The Azure CLI tracks, the Verify and Clean up steps, and the lab scripts now use the aigateway CLI extension for gateways, model providers, aliases, API keys, and MCP servers. The Setup guide shows how to install it. The labs keep az rest only for what the extension can't do yet, such as registering models and setting policies, and say why each time.
  • October 23. Lab 18 now delegates the integration subnet to Microsoft.App/environments, which the service requires. A subnet delegated to Microsoft.Web/serverFarms fails with AIGatewaySubnetNotDelegated. The portal's subnet check still expects Microsoft.Web/serverFarms and shows a warning, which you can ignore.
  • October 23. Lab 24 now publishes the Microsoft Learn MCP server on the gateway, with portal, Azure CLI, and Bicep tracks, and adds its tools to GitHub Copilot in VS Code, the Copilot CLI, the Copilot SDK, and the GitHub Copilot app with the same runtime key. It shows the token cost of tool results and how one suspended key cuts off both models and tools.
  • October 22. New lab 24 · Use your gateway's models and tools in GitHub Copilot: publish gpt-6-astra with a per-caller token limit and a key for Copilot, then connect GitHub Copilot in VS Code, the Copilot CLI, the Copilot SDK (Python and TypeScript), and the GitHub Copilot app with bring your own key (BYOK). It includes portal, Azure CLI, and Bicep tracks, and shows how one suspended key cuts off every Copilot surface.
  • October 22. New 5-minute quick start: learn the building blocks, create a gateway with a Foundry gpt-6-luna model, an alias, and a runtime key, and make your first call. Follow it in the AI Gateway portal, with a screenshot for every step; paste its Azure CLI commands (Bash or PowerShell) into Cloud Shell; or download its Bicep template and deploy it with one azd up. There's nothing to clone. The home page now starts with it, and the former 30-minute quickstart path is now 30-minute essentials.
  • October 22. New lab 23 · Stream responses and count every token, which covers usage for streamed Chat Completions responses from the September 24 release. It streams with curl, PowerShell, Python, and TypeScript, shows each chunk and where usage arrives, proves that a token limit counts streams with or without include_usage, and has a notebook and an interactive streaming usage simulator on the site.
  • October 22. New lab 22 · Route an alias across models by priority and weight, with portal, Azure CLI, and Bicep tracks, a script that counts which model served each request, and an interactive priority and weight simulator on the site.
  • October 22. Lab 04 adds Supported MCP versions: the version list, the legacy defaults, the rule that every backend must support every listed version, and a supportedVersions Bicep parameter. Lab 03 follows the new alias wizard and links to lab 22.
  • October 22. The labs use the latest models: gpt-6-luna and gpt-6.1-sol from Microsoft Foundry, and claude-haiku-5-5 and claude-sonnet-5-5 from Anthropic. Portal steps say Catalog where the portal used to say Discover.
  • October 22. Lab 00 has a narrated three-minute video tour of the portal.
  • October 19. Every lab creates the dedicated Microsoft.ApiManagement/aigateways resource type.
  • October 19. Each lab's README.md is the source of truth for both the site and GitHub, with navigation that works on GitHub. Jupyter notebooks run five labs end to end by deploying the labs' own Bicep files through a shared utils.py↗.
  • October 19. Lab 01 has a narrated video, and the azure-ai-gateway-labs↗ agent skill teaches coding agents how to use the labs.

#How these notes work

Each section matches one entry in the product release notes↗, with the same date and title, and maps every product change to the lab where you can practice it. Changes to the labs that don't come from a product release are listed under Labs changes in the release they followed.

This file, labs/RELEASE-NOTES.md, is the source of truth: the labs site renders it at /release-notes/. To check for product releases that the notes don't cover yet, run npm run releases in labs/. See Authoring↗.
