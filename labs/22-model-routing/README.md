switch. In this lab you put the current model and the new one behind the same alias, send a fifth of the traffic

## How it works

An alias holds a list of backend models. Each one has a priority and a weight:

| Setting | Values | Default | What it does |
|---|---|---|---|
| **Priority** | Whole number from 0 to 100 | `0` | Lower numbers are preferred. Requests go to the backend models with the lowest priority number. |
| **Weight** | Whole number from 1 to 100 | `1` | Splits traffic among the backend models that share a priority, in proportion to their weights. |

A backend model's **Share within priority** is its weight divided by the sum of the weights at its priority.
Weights `80` and `20` give 80% and 20%; weights `3` and `1` give 75% and 25%. With one backend model, the alias
behaves like the single-target aliases of labs 02 and 03.

Pick the values from the job you need to do:

| Scenario | Priority | Weight |
|---|---|---|
| **Canary a new model version** | Same for both | Small share for the new version, for example `95` and `5`, then raise it |
| **A/B test two models** | Same for both | Equal, for example `50` and `50` |
| **Balance deployments** across regions or providers | Same for all | In proportion to each deployment's capacity, for example `3` and `1` |
| **Prefer purchased capacity** | Provisioned deployment `0`, pay-as-you-go `1` | Any |

A few rules keep every request answerable:

- Each backend model can appear only once in an alias.
- All backend models must support at least one interface in common, for example **OpenAI Chat Completions**.
  Mixing an Anthropic Messages model with an OpenAI model in one alias fails.
- The response tells you which backend served the request: the `model` field holds the backend's model name and
  version, for example `gpt-6.1-sol-2026-09-29`, and Foundry models also return an `x-ms-served-model` header.

> [!IMPORTANT]
> Priority sets a preference, not a guaranteed failover. In our preview tests, when the preferred backend
> returned an error such as `429` or `404`, the gateway passed that error to the client instead of retrying a
> lower-priority backend. Test how your gateway behaves under throttling before you rely on priority for
> availability, and keep retries in your clients.

### Create the chat alias

Each entry in `backendModels` has a `resourceId`, a `priority`, and a `weight`.

<details open><summary>Bash</summary> <!-- gh -->

```bash title="Bash"
export MODELS="$GATEWAY_ID/workspaces/default/modelProviders/$PROVIDER/models"
az rest --method put --url "$WS/aliases/$ALIAS?$API" \
  --body "$(jq -cn --arg p "$MODELS/$PRIMARY" --arg c "$MODELS/$CANDIDATE" '{properties: {
      description: "Canary: 80/20 between the current and the new model",
      backendModels: [
        {resourceId: $p, priority: 0, weight: 80},
        {resourceId: $c, priority: 0, weight: 20}]}}')" \
  --query properties.backendModels -o json |
  jq -r '.[] | "\(.resourceId | split("/") | last)  priority \(.priority)  weight \(.weight)"'
```
</details> <!-- gh -->

<details><summary>PowerShell</summary> <!-- gh -->

```powershell title="PowerShell"
$MODELS = "$GATEWAY_ID/workspaces/default/modelProviders/$PROVIDER/models"
@{ properties = @{
    description   = "Canary: 80/20 between the current and the new model"

      @{ resourceId = "$MODELS/$PRIMARY";   priority = 0; weight = 80 }

Remove-Item body.json
```

```bicep
// Routes one callable alias across two Foundry backend models.
// Registers a candidate deployment under the existing Foundry provider from lab 02, then publishes an alias that
// either splits traffic between the primary and the candidate by weight, or prefers the primary by priority.
// The primary backend model is only referenced, so its policies from lab 02 stay untouched.
targetScope = 'resourceGroup'

@description('Name of the existing AI Gateway (Microsoft.ApiManagement/aigateways) in this resource group.')
param gatewayName string

@description('Name of the existing Foundry model provider in the gateway, for example foundry-models from lab 02.')
param providerName string = 'foundry-models'

@description('Name of the existing backend model that takes most of the traffic, for example gpt-6-luna.')
param primaryModelName string = 'gpt-6-luna'

@description('Resource ID of the Foundry account that hosts the candidate deployment.')
param foundryAccountId string

@description('Name of the candidate deployment in that account, for example gpt-6.1-sol.')
param candidateDeploymentName string = 'gpt-6.1-sol'

@description('Version of the candidate model, for example 2026-09-29. Optional.')
param candidateModelVersion string = ''

@description('Callable alias that clients send in the request "model" field.')
param aliasName string = 'chat'

@description('weighted: both backends share priority 0 and split traffic by weight. priority: the primary is preferred, and the candidate gets priority 1.')
@allowed([
  'weighted'
  'priority'
])
param strategy string = 'weighted'

@description('Weighted strategy only: the candidate weight. The primary gets 100 minus this value.')
@minValue(1)
@maxValue(99)
param candidateWeight int = 20

type route = {
  @description('Resource ID of the backend model.')
  resourceId: string

  @description('Lower numbers are preferred. 0 to 100.')
  @minValue(0)
  @maxValue(100)
  priority: int

  @description('Share of traffic among backends with the same priority. 1 to 100.')
  @minValue(1)
  @maxValue(100)
  weight: int
}

resource aiGateway 'Microsoft.ApiManagement/aigateways@2025-09-01-preview' existing = {
  name: gatewayName
}

resource defaultWorkspace 'Microsoft.ApiManagement/aigateways/workspaces@2025-09-01-preview' existing = {
  parent: aiGateway
  name: 'default'
}

resource provider 'Microsoft.ApiManagement/aigateways/workspaces/modelProviders@2025-09-01-preview' existing = {
  parent: defaultWorkspace
  name: providerName
}

resource primary 'Microsoft.ApiManagement/aigateways/workspaces/modelProviders/models@2025-09-01-preview' existing = {
  parent: provider
  name: primaryModelName
}

resource candidate 'Microsoft.ApiManagement/aigateways/workspaces/modelProviders/models@2025-09-01-preview' = {
  parent: provider
  name: candidateDeploymentName
  properties: {
    displayName: candidateDeploymentName
    description: 'Candidate deployment that the ${aliasName} alias routes to.'
    apiFormat: 'OpenAIChatCompletions'
    supportedEndpoints: [
      '/openai/v1/chat/completions'
      '/openai/v1/responses'
    ]
    deployment: {
      resourceId: '${foundryAccountId}/deployments/${candidateDeploymentName}'
      modelName: candidateDeploymentName
      modelVersion: empty(candidateModelVersion) ? null : candidateModelVersion
    }
  }
}

var routes route[] = strategy == 'weighted'
  ? [
      { resourceId: primary.id, priority: 0, weight: 100 - candidateWeight }
      { resourceId: candidate.id, priority: 0, weight: candidateWeight }
    ]
  : [
      { resourceId: primary.id, priority: 0, weight: 1 }
      { resourceId: candidate.id, priority: 1, weight: 1 }
    ]

resource alias 'Microsoft.ApiManagement/aigateways/workspaces/aliases@2025-09-01-preview' = {
  parent: defaultWorkspace
  name: aliasName
  properties: {
    description: strategy == 'weighted'
      ? 'Splits traffic ${100 - candidateWeight}/${candidateWeight} between ${primaryModelName} and ${candidateDeploymentName}.'
      : 'Prefers ${primaryModelName}. ${candidateDeploymentName} has a lower preference.'
    backendModels: [
      for r in routes: {
        resourceId: r.resourceId
        priority: r.priority
        weight: r.weight
      }
    ]
  }
}

output aliasName string = alias.name
output candidateModelName string = candidate.name
output routes array = [
  for r in routes: {
    model: last(split(r.resourceId, '/'))
    priority: r.priority
    weight: r.weight
  }
]
output chatCompletionsUrl string = 'https://${aiGateway.properties.frontend.defaultHostname}/default/models/openai/v1/chat/completions'
```

## Prefer one model by priority

The canary looks good, but finance wants `gpt-6-luna` to handle the traffic until the new model is approved.
Give `gpt-6.1-sol` priority `1`. It stays in the alias, ready to promote, but requests go to `gpt-6-luna`.

## Go further

- **Canary in steps.** Move the weights from `95`/`5` to `80`/`20` to `50`/`50` while you watch errors, latency,
  and cost per model in [Monitor usage, cost, and traces](../13-monitoring/README.md). Weights must be at least
  `1`, so to stop sending traffic to a model, give it a higher priority number or remove it from the alias.
- **Prefer provisioned throughput.** Put a provisioned deployment at priority `0` and a pay-as-you-go
  deployment of the same model at priority `1`, so purchased capacity is used first. Test what happens when the
  provisioned deployment is saturated before you depend on it.
- **Balance regions or providers.** Register the same model from two Foundry accounts, or from Foundry and a
  custom provider, and give them weights in proportion to their quota.
- **Limit each model and the alias.** A token limit on a backend model, as in
  [Throttle tokens per caller with token limits](../06-token-limits/README.md), applies to that model. A limit
  on the alias applies to every request that calls `chat`.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| "Select models with at least one common API format." | The selected backend models don't share an interface, for example an Anthropic Messages model and an OpenAI Chat Completions model | Put models that share an interface in the same alias. |
| "Weight must be a whole number from 1 to 100." or `weight must be between 1 and 100.` | A weight is `0`, negative, or above `100` | To stop traffic to a model, raise its priority number or remove it. |
| "Priority must be a whole number from 0 to 100." or `priority must be between 0 and 100.` | A priority is outside `0` to `100` | Use `0` for the preferred tier and higher numbers for the others. |
| "Each backend model can appear only once." or `backendModels must not contain duplicate model identities.` | The same backend model is listed twice | Combine the entries and adjust the weight. |
| All requests go to one model | The models have different priorities, so only the lowest number receives traffic | Give the models the same priority to split by weight. |
| `404` with `DeploymentNotFound` | The candidate backend model points to a Foundry deployment that doesn't exist | Create the deployment, or fix `deployment.resourceId` on the backend model. |
| `429` from the preferred model | The preferred deployment is out of capacity, and the gateway returns the error | Retry in the client, add capacity, or spread traffic with weights at the same priority. |
