## How it works

One subscription-scope template, `infra/main.bicep`, creates two resource groups and composes small modules.
Each module owns one concern, so the people who own that concern can review and change it on their own, and no
module outputs a secret. Parameter files hold everything that differs between environments.

Gateway-wide policies aren't in Bicep. They live on the gateway's `default` workspace, and declaring that
workspace in a template would replace it. Instead, a script merges them in after each deployment, as in
[Set gateway-wide policy baselines](../09-gateway-baselines/README.md).

| File | Resource group | Deploys |
|---|---|---|
| `modules/monitoring.bicep` | `…-gateway` | Log Analytics workspace and a workspace-based Application Insights component, `<gateway>-insights` |
| `modules/foundry.bicep` | `…-foundrymodels` | Foundry account with key authentication turned off, and the `gpt-5.4-mini` deployment |
| `modules/gateway.bicep` | `…-gateway` | The AI Gateway (`Microsoft.ApiManagement/aigateways`, system-assigned identity), its connector gateway, and **Foundry User** for the identity on the Foundry account |
| `modules/models.bicep` | `…-gateway` | A Foundry model provider that authenticates with the managed identity, the backend model with a token limit and content safety, the alias `chat`, and **AI Gateway Models User** on the alias |
| `modules/tools.bicep` | `…-gateway` | The Microsoft Learn MCP server `learn`, and **AI Gateway Tools User** on it |
| `modules/keys.bicep` | `…-gateway` | One runtime API key per app: `web-chat` and `batch-jobs` |
| `modules/telemetry.bicep` | `…-gateway` | The legacy Application Insights telemetry exporter, off by default |
| `scripts/apply-baselines.sh` | Not applicable | Gateway scope **Request rate limit** and **Cost limit** from `baselines.json` |

## Make the architecture decisions

Each decision below is already built into the templates. In your own environment, change the parameters first,
and change the shape only when your organization needs something different.

### Identity: no secrets between services or in the pipeline

Each trust boundary uses its own mechanism, and none of them needs a stored secret:

| Boundary | Mechanism | Where |
|---|---|---|
| Gateway to Foundry | The gateway's system-assigned identity has **Foundry User** on the account. The account sets `disableLocalAuth: true`, so Foundry keys don't work at all. | `gateway.bicep`, `foundry.bicep` |
| Apps to gateway | One runtime API key per app, so every app gets its own policy counters, its own row in **Monitoring**, and its own rotation. Or keyless Microsoft Entra calls through **AI Gateway Models User** on the alias and **AI Gateway Tools User** on the MCP server, granted to groups. | `keys.bicep`, `models.bicep`, `tools.bicep` |
| Pipeline to Azure | An OpenID Connect federated credential. GitHub exchanges a short-lived token for an Azure token, so there's no client secret to rotate or leak. | `deploy-workflow.yml` |

Roles are granted at the narrowest scope that works: the alias instead of the whole gateway, and one MCP server
instead of every tool. Templates output key **names** only, never key values. The smoke test reads a key with
the `listSecrets` action when it needs one.

### Policies: a gateway floor plus model limits

| Layer | Declared in | Policies | Counted per |
|---|---|---|---|
| Gateway | `baselines.json`, applied by `scripts/apply-baselines.sh` | **Request rate limit**: 120 calls per 60 seconds, on models and MCP servers. **Cost limit**: $20 per day, one budget across all models. | Caller identity |
| Model | `models.bicep` | **Token rate limit**: 20,000 tokens per minute in dev. **Content safety**: **Balanced** (`Medium`) for all four categories. | Caller identity |

The gateway evaluates every applicable policy before it forwards a request, and any one of them can block it.
The platform team owns the gateway floor, and app teams tune the model layer through parameters. Blocked calls
get `429` from a rate limit, `403` with `LlmCostQuotaExceeded` from the cost limit, and `400` from content
safety.

The baseline script reads the workspace's `policies` array, updates policies of the same type in place, appends
missing ones, and writes the array back with `PATCH`. Updating in place keeps a cost limit's `id`, its
portal-only overrides, and the spend it has already counted.

> [!NOTE]
> The portal writes `"scope": "workspace"` on Gateway scope rate and cost limits, so `baselines.json` does too.
> If the API rejects a field, create the policy once in the portal at **Gateway** scope, read the workspace with
> `az rest`, and copy that shape into `baselines.json`.

### Observability: the destination in Bicep, the connection in the portal

`monitoring.bicep` creates the Log Analytics workspace and the Application Insights component, with retention
set per environment. The sample also declares a telemetry exporter of kind `applicationInsights`, but the
current portal treats that kind as **legacy**: it no longer activates the OTLP signals the **Monitoring**
dashboard needs. The OpenTelemetry exporter that replaces it isn't documented for automation yet. So you
connect the component once in the portal after the first deployment. No module declares an exporter, so later
deployments leave that connection alone. The sample's exporter is still available as `telemetry.bicep`, behind
`enableLegacyAppInsightsExporter`.

### Naming, tags, and resource groups

- **Deterministic names.** A resource token, the first eight characters of
  `uniqueString(subscription, environmentName, location)`, goes into every name. Deploying again updates the
  same resources instead of creating new ones.
- **Two resource groups.** `rg-<env>-<token>-gateway` holds the gateway and its monitoring, and
  `rg-<env>-<token>-foundrymodels` holds model capacity. You can secure, scale, and delete them separately, and
  only the gateway's identity needs access to Foundry.
- **A unique gateway name.** The gateway is `aigw-<token>`, which becomes
  `https://aigw-<token>.<region>-01.ai.gateway.azure.com`. Set `aiGatewayName` to choose your own: up to 24
  letters, digits, and hyphens, starting with a letter.
- **Tags.** Resource groups and top-level resources get `environment` and `workload: ai-gateway`, plus the
  `tags` from the parameter file, such as `costCenter`.
- **Preview regions.** `aiGatewayLocation` only allows `eastus2` and `swedencentral`, where the AI Gateway tier
  is in public preview. The other resources follow the deployment's `--location`.

### Environments: one template, two parameter files

| Setting | `main.bicepparam` (dev) | `prod.bicepparam` (prod) |
|---|---|---|
| `environmentName` | `aigw-dev` | `aigw-prod` |
| Developer access (`principalId`) | You, from `AZURE_PRINCIPAL_ID` | None |
| Model capacity (`modelCapacity`) | 50 | 200 |
| Tokens per minute per caller (`tokensPerMinutePerCaller`) | 20,000 | 50,000 |
| Microsoft Entra access (`modelUsers`, `toolUsers`) | Your user only | Groups you add |
| Log retention (`logRetentionInDays`) | 30 days | 90 days |
| `costCenter` tag | `dev` | `platform` |

> [!TIP]
> Put prod in its own subscription so quotas, role assignments, and Azure Policy stay isolated from dev. The
> template is subscription-scoped, so it works unchanged. Use a separate deployment identity for each
> subscription.

### Delivery: GitHub Actions with OpenID Connect

The workflow previews every change with `what-if`, deploys, applies the baseline, and runs the smoke test. A
`prod` GitHub environment with required reviewers gates production, and a concurrency group per environment
stops two runs from deploying to the same environment at once. The deployment identity needs **Contributor**
and **Role Based Access Control Administrator** on the subscription, because the template creates role
assignments. To narrow that, you can add a condition that only lets it assign the roles the template needs, as
described in
[Delegate Azure access management to others](https://learn.microsoft.com/azure/role-based-access-control/delegate-role-assignments-overview).

// Enterprise reference deployment for Azure AI Gateway. One subscription-scope template creates two resource groups
// and composes small modules:
//
//   rg-<env>-<token>-foundrymodels   foundry.bicep         Foundry account (keyless) + model deployment
//   rg-<env>-<token>-gateway         monitoring.bicep      Log Analytics + Application Insights
//                                    gateway.bicep         aigateways resource + connector gateway + Foundry User role for the gateway identity
//                                    models.bicep          Foundry provider + backend model (tokenLimit, contentSafety) + alias
//                                    tools.bicep           Microsoft Learn MCP server
//                                    keys.bicep            one runtime API key per app
//                                    telemetry.bicep       optional legacy exporter (off by default)
//
// Gateway-wide baseline policies are applied after deployment by scripts/apply-baselines.sh (or .ps1).
targetScope = 'subscription'

import { principal } from './modules/types.bicep'

@minLength(1)
@maxLength(64)
@description('Environment name, for example aigw-dev or aigw-prod. Used in resource group names, tags, and the deterministic resource token.')
param environmentName string

@description('Region for the resource groups, the Foundry account, and the monitoring resources. The model and SKU must be available here.')
param location string = deployment().location

@allowed([
  'eastus2'
  'swedencentral'
])
@description('Region for the gateway. The AI Gateway tier preview is available in East US 2 and Sweden Central.')
param aiGatewayLocation string = 'eastus2'

@description('Optional Microsoft Entra object ID of a developer. When set, the developer gets data-plane roles on the Foundry account, the alias, and the MCP server. Leave empty in production.')
param principalId string = ''

@description('Extra tags merged into the default tags on every resource group and resource.')
param tags object = {}

@description('Gateway name, max 24 characters. Defaults to aigw-<token>. It becomes https://<name>.<region>-01.ai.gateway.azure.com.')
param aiGatewayName string = ''

@description('Foundry model name to deploy.')
param modelName string = 'gpt-5.4-mini'

@description('Foundry model version to deploy.')
param modelVersion string = '2026-03-17'

@description('ARM-safe name of the Foundry deployment. It is also the backend model name in the gateway.')
param modelDeploymentName string = 'gpt-mini-latest'

@description('Model format for the Foundry deployment.')
param modelFormat string = 'OpenAI'

@description('Model deployment SKU name.')
param modelSkuName string = 'GlobalStandard'

@description('Deployment capacity, in thousands of tokens per minute for Global Standard.')
@minValue(1)
param modelCapacity int = 50

@description('Tokens per minute that each caller identity (API key or Microsoft Entra principal) can use on the backend model.')
@minValue(1)
param tokensPerMinutePerCaller int = 20000

@allowed([
  'None'
  'Low'
  'Medium'
  'High'
])
@description('Content safety threshold for every category on the backend model. The threshold is the lowest severity that is blocked: Low is strictest, None turns the category off.')
param contentSafetySeverity string = 'Medium'

@description('Client-facing alias that apps send in the request "model" field.')
param aliasName string = 'chat'

@description('Apps that get their own runtime API key. Each key is named after the app.')
param appNames string[] = [
  'web-chat'
  'batch-jobs'
]

@description('Microsoft Entra principals (usually groups) that get the AI Gateway Models User role on the alias.')
param modelUsers principal[] = []

@description('Microsoft Entra principals (usually groups) that get the AI Gateway Tools User role on the Microsoft Learn MCP server.')
param toolUsers principal[] = []

@description('Days to keep gateway telemetry in Log Analytics.')
@minValue(30)
@maxValue(730)
param logRetentionInDays int = 30

@description('Also deploy the reference sample\'s telemetry exporter (kind applicationInsights). The portal labels this kind as legacy because it no longer activates OTLP signals. Leave false and connect telemetry in the portal.')
param enableLegacyAppInsightsExporter bool = false

var resourceToken = take(toLower(uniqueString(subscription().id, environmentName, location)), 8)
var environmentLabel = toLower(environmentName)
var allTags = union({
  environment: environmentName
  workload: 'ai-gateway'
}, tags)
var gatewayResourceGroupName = 'rg-${environmentLabel}-${resourceToken}-gateway'
var foundryModelsResourceGroupName = 'rg-${environmentLabel}-${resourceToken}-foundrymodels'
var effectiveAiGatewayName = !empty(aiGatewayName) ? aiGatewayName : 'aigw-${resourceToken}'
var modelServicesName = 'aimodels-${resourceToken}'
var appInsightsName = take('${effectiveAiGatewayName}-insights', 64)
var logAnalyticsWorkspaceName = take('${effectiveAiGatewayName}-logs', 63)
var developer = empty(principalId) ? [] : [
  {
    principalId: principalId
    principalType: 'User'
  }
]
var gatewayModelDeployments = [
  {
    deploymentName: modelDeploymentName
    modelName: modelName
    modelFormat: modelFormat
    modelVersion: modelVersion
    skuName: modelSkuName
    capacity: modelCapacity
    description: 'Default chat model for every app behind the gateway.'
  }
]

resource gatewayRg 'Microsoft.Resources/resourceGroups@2021-04-01' = {
  name: gatewayResourceGroupName
  location: location
  tags: allTags
}

resource foundryModelsRg 'Microsoft.Resources/resourceGroups@2021-04-01' = {
  name: foundryModelsResourceGroupName
  location: location
  tags: allTags
}

module monitoring './modules/monitoring.bicep' = {
  name: 'monitoring-${resourceToken}'
  scope: gatewayRg
  params: {
    location: location
    tags: allTags
    logAnalyticsWorkspaceName: logAnalyticsWorkspaceName
    appInsightsName: appInsightsName
    retentionInDays: logRetentionInDays
  }
}

module foundry './modules/foundry.bicep' = {
  name: 'foundry-models-${resourceToken}'
  scope: foundryModelsRg
  params: {
    location: location
    tags: allTags
    aiServicesName: modelServicesName
    principalId: principalId
    modelDeployments: gatewayModelDeployments
  }
}

module gateway './modules/gateway.bicep' = {
  name: 'ai-gateway-${resourceToken}'
  scope: gatewayRg
  params: {
    location: aiGatewayLocation
    gatewayName: effectiveAiGatewayName
    tags: allTags
    foundryResourceIds: [
      foundry.outputs.aiServicesId
    ]
  }
}

// Every module below takes gateway.outputs.gatewayName, so it starts only after the gateway, its connector gateway,
// and the Foundry User role assignment exist.
module models './modules/models.bicep' = {
  name: 'ai-gateway-models-${resourceToken}'
  scope: gatewayRg
  params: {
    gatewayName: gateway.outputs.gatewayName
    providerName: 'foundry'
    providerDisplayName: 'Foundry'
    providerDescription: 'Managed-identity Foundry provider for the ${environmentName} environment.'
    foundryEndpoint: foundry.outputs.aiServicesEndpoint
    foundryResourceIds: [
      foundry.outputs.aiServicesId
    ]
    foundryModels: [for (deployment, i) in gatewayModelDeployments: {
      armName: deployment.deploymentName
      description: deployment.description
      resourceId: foundry.outputs.modelDeploymentIds[i]
      modelName: deployment.modelName
      modelVersion: deployment.modelVersion
      tokenLimit: tokensPerMinutePerCaller
      apiFormat: 'OpenAIChatCompletions'
      supportedEndpoints: [
        '/openai/v1/chat/completions'
        '/openai/v1/responses'
      ]
    }]
    contentSafetySeverity: contentSafetySeverity
    aliasName: aliasName
    aliasUsers: concat(developer, modelUsers)
  }
}

module tools './modules/tools.bicep' = {
  name: 'ai-gateway-tools-${resourceToken}'
  scope: gatewayRg
  params: {
    gatewayName: gateway.outputs.gatewayName
    toolUsers: concat(developer, toolUsers)
  }
}

module keys './modules/keys.bicep' = {
  name: 'ai-gateway-keys-${resourceToken}'
  scope: gatewayRg
  params: {
    gatewayName: gateway.outputs.gatewayName
    appNames: appNames
  }
}

module telemetry './modules/telemetry.bicep' = if (enableLegacyAppInsightsExporter) {
  name: 'ai-gateway-telemetry-${resourceToken}'
  scope: gatewayRg
  params: {
    gatewayName: gateway.outputs.gatewayName
    appInsightsName: monitoring.outputs.appInsightsName
  }
}

output AZURE_LOCATION string = location
output AZURE_TENANT_ID string = tenant().tenantId

output AI_GATEWAY_RESOURCE_ID string = gateway.outputs.gatewayId
output AI_GATEWAY_URL string = gateway.outputs.gatewayUrl
output AI_GATEWAY_PRINCIPAL_ID string = gateway.outputs.gatewayPrincipalId
output AI_GATEWAY_MODEL string = models.outputs.aliasName
output MCP_ENDPOINT string = tools.outputs.mcpEndpoint
output API_KEY_NAMES array = keys.outputs.apiKeyNames

// the companion connector gateway (created first, as the AI Gateway portal does), and the Foundry User role for the
// gateway identity on every Foundry account it calls.
targetScope = 'resourceGroup'

@description('Location of the gateway. The AI Gateway tier preview is available in East US 2 and Sweden Central.')
@allowed([
  'eastus2'
  'swedencentral'
])
param location string

@description('Gateway name, max 24 characters. It becomes the first label of the runtime host name, https://<name>.<region>-01.ai.gateway.azure.com.')
@maxLength(24)
param gatewayName string

@description('Tags applied to the gateway.')
param tags object = {}

@description('Optional subnet resource ID for outbound virtual network integration. It can only be set when the gateway is created.')
param backendSubnetId string = ''

@description('Resource IDs of the Foundry accounts the gateway calls with its managed identity.')
param foundryResourceIds array = []

resource connectorNamespace 'Microsoft.Web/connectorGateways@2026-05-01-preview' = {
  name: gatewayName
  location: location
  tags: tags
  properties: {}
}

resource aiGateway 'Microsoft.ApiManagement/aigateways@2025-09-01-preview' = {
  name: gatewayName
  location: location
  tags: tags
  identity: {
    type: 'SystemAssigned'
  }
  properties: union(
    {
      publicNetworkAccess: 'Enabled'
    },
    empty(backendSubnetId) ? {} : { backend: { subnet: { id: backendSubnetId } } }
  )
  dependsOn: [
    connectorNamespace
  ]
}

  scope: resourceGroup(split(foundryResourceId, '/')[2], split(foundryResourceId, '/')[4])
  params: {
    foundryAccountName: last(split(foundryResourceId, '/'))
    gatewayPrincipalId: aiGateway.identity.principalId
    gatewayResourceId: aiGateway.id
  }
}]

output gatewayName string = aiGateway.name
output gatewayId string = aiGateway.id
output gatewayUrl string = 'https://${aiGateway.properties.frontend.defaultHostname}'
output runtimeHostname string = aiGateway.properties.frontend.defaultHostname

```sh
#!/usr/bin/env bash
# Applies the gateway-wide baseline policies in infra/baselines.json to an AI Gateway.
#
# Gateway-scope policies live in the policies array of the gateway's default workspace. A PATCH replaces the whole
# array, so the script reads the current array, merges the baselines into it, and writes it back:
#   - A baseline whose type already exists updates that policy in place and keeps its id, overrides, and any other
#     fields you set in the portal. Updating a costLimit this way keeps its accumulated spend.
#   - A baseline whose type doesn't exist is appended. A new costLimit gets a fresh, stable id.
#   - Policies of other types (for example ones you added in the portal) are left untouched.
# Running it twice gives the same result.
#
# Usage:
#   export RG="<gateway-resource-group>" GATEWAY="<gateway-name>"
#   ./apply-baselines.sh [baselines.json]
#   DRY_RUN=1 ./apply-baselines.sh          # print the merged array without changing anything
#
# Requires Azure CLI and jq.
set -euo pipefail

SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
BASELINES="${1:-$SCRIPT_DIR/../baselines.json}"
API_VERSION="2025-09-01-preview"
: "${RG:?Set RG to the gateway resource group}"
: "${GATEWAY:?Set GATEWAY to the gateway name}"
command -v jq >/dev/null || { echo "This script needs jq." >&2; exit 1; }
jq -e 'type == "array" and all(.[]; has("type"))' "$BASELINES" >/dev/null \
  || { echo "$BASELINES must be a JSON array of policy objects." >&2; exit 1; }

SUB="$(az account show --query id -o tsv)"
URL="https://management.azure.com/subscriptions/$SUB/resourceGroups/$RG/providers/Microsoft.ApiManagement/aigateways/$GATEWAY/workspaces/default?api-version=$API_VERSION"
NEW_ID="$( (uuidgen 2>/dev/null || cat /proc/sys/kernel/random/uuid) | tr 'A-Z' 'a-z')"

CURRENT="$(az rest --method get --url "$URL")"
POLICIES="$(printf '%s' "$CURRENT" | jq -c --slurpfile base "$BASELINES" --arg id "$NEW_ID" '
  reduce $base[0][] as $b (.properties.policies // [];
    if any(.[]; .type == $b.type)
    then map(if .type == $b.type then . + $b else . end)
    else . + [if $b.type == "costLimit" and ($b.id // "") == "" then $b + {id: $id} else $b end]
    end)')"

echo "Gateway-scope policies after merge:"
printf '%s' "$POLICIES" | jq .

if [ "${DRY_RUN:-0}" = "1" ]; then
  echo "DRY_RUN=1: nothing was changed."
  exit 0
fi

az rest --method patch --url "$URL" --body "{\"properties\":{\"policies\":$POLICIES}}" --output none
echo "Applied. Current gateway-scope policy types:"
az rest --method get --url "$URL" --query "properties.policies[].type" -o tsv
```

## Go further

- **Add a content safety floor.** Add a `contentSafety` entry to `baselines.json` with the shape from
  [Set gateway-wide policy baselines](../09-gateway-baselines/README.md), so MCP servers and future models get
  it too.
- **Go keyless everywhere.** Remove entries from `appNames`, move apps to Entra groups in `modelUsers` and
  `toolUsers`, and follow [Go keyless with Microsoft Entra ID and RBAC](../11-entra-rbac/README.md).
- **Keep backend traffic private.** Create the gateway with outbound virtual network integration, and give the
  Foundry account a private endpoint, as in
  [Lock down backend traffic with private networking](../18-private-networking/README.md). Pass the integration
  subnet to `gateway.bicep` as `backendSubnetId` on the first deployment. Inbound private endpoints and turning
  off the gateway's public endpoint aren't available for AI Gateway yet.
- **Protect and govern tools.** Add [Agent 365 tool threat protection](../19-tool-threat-protection/README.md)
  to sensitive MCP servers in the portal, and [govern MCP servers with Agent 365](../20-agent-365-governance/README.md).
- **Charge back by team.** Attribute tokens and cost to callers with
  [Attribute tokens and cost with OpenTelemetry](../14-otel-chargeback/README.md).

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| The deployment fails with `InsufficientQuota`, or the model or version isn't available | The region has no `GlobalStandard` quota for `gpt-5.4-mini`, or doesn't offer that version | Lower `modelCapacity`, request quota, or change `modelName`, `modelVersion`, or `--location` in your parameter file and command. |
| The gateway's `provisioningState` ends in `Failed` | Azure hit an activation or managed identity conflict, often after a gateway with the same name was deleted moments before | Delete the failed gateway and its connector gateway, wait about three minutes for the identity to be cleaned up, and deploy again. |
| The smoke test prints `Waiting for the model route` until it fails with `401`, `403`, or `404` | The new Foundry User role assignment or the model route hasn't propagated yet | Wait a few minutes and run the smoke test again. If it still fails, run the backend identity checks in [Verify](#verify). |
| **Settings** in **Monitoring** shows "This legacy exporter no longer activates OTLP signals" | You deployed with `enableLegacyAppInsightsExporter` set to `true` | Select **Settings** › **General** › **Disable monitoring**, then **Configure telemetry** again with the same Application Insights resource. |
| `apply-baselines` fails with a validation error from the `PATCH` | A field in `baselines.json` doesn't match the current API contract, for example `counterKey` as a string instead of an array such as `["identity"]` | Create the policy once in the portal at **Gateway** scope, read the workspace with `az rest`, and copy that shape into `baselines.json`. |
| `azure/login` fails with `AADSTS70021: No matching federated identity record found` | The token subject doesn't match a federated credential | Check that the subject is exactly `repo:<github-org>/<github-repo>:environment:<name>` and that the GitHub environment name matches the job's `environment:`. |
